# SP01 网络样本汇总器

本地纯函数 `summarizeSamples` 与 `collectSequentialSamples` 已接到隔离小程序的独立 `pages/network/index` 页面；它们只有一份实现，Node 入口从小程序工具模块复用。加载页面不会调用云端，只有手动按“开始 30 次只读采样”才顺序调用。代码提交本身不产生测速数据。它保留失败次数和失败率；成功请求的 P50/P95 使用最近秩；相邻成功请求耗时差的均值仅是应用层波动描述，**不是网络层抖动或丢包测量**。全部失败时耗时为 `null`，不会以零伪装。

`collectSequentialSamples` 最多90次顺序调用，调用函数与时钟由外部注入；小程序页面当前使用 `Date.now`，若墙上时钟在采样中回拨，结果拒绝计入有效样本。它只返回成功标志及耗时，不保存身份函数返回体或错误内容。现有 `sp01IdentityProbe` 仅计算身份摘要、无数据库或存储写入，可作为候选只读端点；这只是源码核对，当前未进行网络调用或云端状态复核。应用层往返时间包括客户端、网关和函数处理，不直接等于链路 RTT；上/下行及真实丢包仍需独立测法。

用户同意先设计目标 cloud1 的临时只读探针，再于 SP08 用正式接口复测。正式取样前仍需取得这轮调用的具体授权、核对端点实际状态，并确定上/下行测法、正常和弱网参数、设备与环境、样本输入以及清理边界。当前没有本轮真实样本，因此 R04 和 SP01 均保持待完成。

复用核对：项目原有隔离小程序固定目标 AppID/环境，现有身份函数按[CloudBase 小程序调用说明](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)通过 `wx.cloud.callFunction` 触发；其本地源码只读上下文、不写数据库或存储。改造仅增加独立页面与验证返回形状的适配器，不增加云函数或第三方库。复用原有许可证/依赖边界，无外部开源代码引入。Node 专项测试覆盖延迟统计、失败保留、错误脱敏、手动触发和 30 次调用；微信真机采样、上/下行与丢包尚未验证。

## Pre-enter credentials and await one source run

`start-local-operator.ps1 -ConfigPath <absolute-public-plan> -NodePath <absolute-Node-v20.19.3> -AwaitSource` checks a public watch plan offline without prompting. Add `-RunOnce` only for a separately authorized live attempt. This mode reuses the existing hidden credential prompts, one stdin envelope, bounded process output, public config preparer and `runOperatorEntry`; it adds no credential discovery, storage, library or cloud permission. It does not write GitHub variables or dispatch the source caller. The operator's existing certificate return dispatch and TAT/security-group operations remain live effects requiring authorization.

The plan has exactly `operatorInput`, `watchDurationMs` and `resourceCleanupAtMs`. `operatorInput` has exactly the earlier operator preparer's fields except `sourceRunId`, `notBeforeMs` and `notAfterMs`; these three are discovered/generated in memory, not copied through screenshots or written to a config file. `watchDurationMs` is an explicit positive integer capped at 60000. The effective discovery deadline is computed once after stdin credential collection completes, so time spent on hidden prompts does not consume that duration. The obsolete `watchUntilMs` plan field is rejected. Both the pre-prompt check and the post-input check require the confirmed resource cleanup time, runner authorization, JWKS expiry and supplied STS expiry (STS checked only after input) to leave at least 360 seconds after the resulting watch deadline (300 seconds plus a 60-second scheduling/cleanup margin). These absolute expiry values are never moved by input delay. This is a conservative precondition, not a guarantee of cloud completion. Generate fresh public policies/plan shortly before the local prompt; expired preparation is rejected without extending any authorization or resource deadline.

After local input validation and one successful baseline GET, the child emits a fixed readiness marker. PowerShell reads exactly those bounded bytes with a 15-second wait before printing `{"state":"waiting-for-source","readyToDispatch":false}`. Process creation alone never prints readiness. This message confirms only that this watch process passed its local checks and baseline query; source dispatch still requires the separately reviewed live authorization. If it does not appear, do not dispatch a caller or automatically retry.

Following that message, the authorized operator dispatches the fixed caller once. The watcher makes at most 12 subsequent list polls, separated by at most 5 seconds, with at most one artifact-list GET per poll. It excludes the baseline run IDs, checks the current second-resolution creation window plus repository ID/name, actor ID/login, branch, SHA, path, event and attempt, pins one queued/active run, and refuses ambiguity, completion or replacement. There is no arbitrary run-ID input. A public artifact's presence is only a readiness signal: the existing entry independently re-reads and verifies the run, artifact digest/archive, CSR and egress before TAT or return dispatch. Polling never downloads artifacts itself.

Every discovery request is a fixed-origin GET with redirects disabled, no pagination, a 64 KiB streamed JSON limit and a 10-second response/body timeout capped by the watch deadline. API errors/timeouts do not retry; successful empty results may poll within the fixed budget. The original source/CSR/operator deadlines remain enforced by the existing entry. Only start one watch process for a reviewed attempt; this mode is not a cross-process lock. Variable removal, resource destruction and role/session closure remain explicit independent cleanup steps.

Reuse review: [GitHub workflow-run listing](https://docs.github.com/en/rest/actions/workflow-runs#list-workflow-runs-for-a-workflow) and [run artifact listing](https://docs.github.com/en/rest/actions/artifacts#list-workflow-run-artifacts) provide discovery through the same Actions read access already used by the operator. The existing `selectSourceRun` selects completed successful runs, so it cannot discover the active caller awaiting a certificate; a small active-run observer bridges that gap and hands all trust decisions back to the existing verifier. No third-party package or license change is introduced. Tests reuse the existing synthetic public-certificate fixture and Windows bridge, including delayed/ambiguous/stale source responses, body stalls, deadline rejection, no source POST, one operator call and no secret output. These offline fixtures do not establish GitHub queue latency, artifact visibility during this particular live job, cloud permissions, backend readiness or a successful live TLS round.

Before the caller window, `node prepare-run-policies.cjs <absolute-public-input.json> <absolute-new-output.json>` prepares the two public GitHub variable values without writing GitHub or dispatching. Both paths must be absolute and the output must not exist. The input has exactly `repository`, `repositoryId`, `actorId`, `actorLogin`, `branch`, `trustedHeadSha`, `targetIPv4`, `caCertificate`, `serverCertificate`, and `authorizedUntil` (Unix milliseconds). Identity IDs are strings; certificates are public PEM only. Supply the explicitly reviewed published SHA, actual CLB public IPv4 and actual bootstrap public certificates; there is no default SHA or automatic trust discovery. Authorization must expire within 15 minutes of preparation. Do not prepare these time-limited values days in advance.

This replaces the old temp `prepare-github-vars.ps1` path, which hard-coded `713df290` and immediately wrote GitHub variables. The new preparer reuses the existing handoff schema and target certificate checks, preserves the fixed proof request, and computes its code digest over UTF-8/LF `a-segment-local.cjs` so Windows checkout line endings do not change it. It verifies certificate SAN/serverAuth/CA signature and pin, but does not independently verify the supplied account IDs, remote SHA, cloud target or resource readiness. Its output remains `readyToDispatch:false`. Actual source-run ID, operator config, JWKS handoff, temporary permissions and explicit variable-write/dispatch authorization remain runtime preparation steps; the generated public variables alone do not complete them. No new dependency or permission is introduced.

The request `env_id` must equal the caller's fixed GitHub environment, `SP08-A3-03-OIDC-smoke`, as required by `runner-entry.cjs`. The old temporary script's `sp08-a3-03-isolated-test` value failed that existing runtime contract. The preparer now derives both from the same value; regression coverage includes `runner-entry.validateConfig`, not only `buildApprovedConfig`.

After an actual caller run ID is known, `node prepare-operator-config.cjs <absolute-public-input.json> <absolute-new-config.json>` creates the exact public JSON accepted by `start-local-operator.ps1`. The input has exactly `preparedPolicies` (the complete previous preparer output), `sourceRunId`, `notBeforeMs`, `notAfterMs`, `region`, `instanceId`, `securityGroupId`, `commandIds` (`sign`, `start`, `stop`), `privateIPv4`, `interfaceName`, `jwksFetchedAt`, `jwksExpiresAt`, `journalPath`, and `pwshPath`. Supply actual values, not fixture IDs; the accepted run-creation interval must contain the current time and span at most 300 seconds. Read JWKS timestamps from the fresh public handoff installed on the server; these numbers do not independently establish its provenance. Both paths must be absolute; existing output is never overwritten.

The operator preparer reuses the existing runner, command, lifecycle and operator validators. It binds public claims/request to the supplied run ID, keeps all target objects on one instance/group, and checks the same SHA and original authorization window. It does not fetch a run, read credentials, create SDK clients, modify GitHub/cloud state, or mark a source artifact trusted. It deliberately leaves `sourceBinding` absent: `runOperatorEntry` must still verify the actual GitHub source artifact and bind its real CSR digest before invoking TAT. Runtime JSON contains only public certificate/policy data; private key fields are rejected. The original resource cleanup deadline and all runtime verification remain unchanged.

The watch plan also rejects a server authorization later than its confirmed resource cleanup deadline. The actual operator entry always forwards that short authorization as an explicit resource deadline cap when verifying source materials. This caps the source state's legacy recovery ceiling for signing failure cleanup and ingress rule removal as well as normal lifecycle cleanup; it does not extend CSR, JWKS, credential or resource windows or control the provider's actual destruction/billing behavior.

`operator-entry.cjs` exports `checkOnly(config)` and `runOperatorEntry(config, secrets, options)`.

The public JSON config contains only explicit reviewed values: repository and numeric identity bindings, trusted workflow path/ref/SHA, source run ID and accepted creation interval, CA fingerprint, fixed signing/start/stop targets, serialized server input, public expected target, absolute journal path, and absolute `pwsh` path. `checkOnly` validates the static shape and server target agreement without network access, secret access, or SDK construction; it does not establish trust readiness.

For a future operator-run Windows 11 session with PowerShell 7, use `pwsh -NoProfile -File .\start-local-operator.ps1 -ConfigPath <absolute-public-config> -NodePath <absolute-Node-v20.19.3-path> [-RunOnce]`. Without `-RunOnce`, it validates the Node executable/version and public config and returns check-only without prompting. With the explicit switch, it uses hidden `Read-Host -AsSecureString` prompts for the STS SecretId, SecretKey, STS token and GitHub token, plus a visible ISO 8601 expiration. It passes the values once through child-process stdin; no secret file, environment variable, command-line secret argument, clipboard read, or credential discovery is used. The Node launcher enforces a 32 KiB input cap and 30-second input deadline, exact fields, and a non-expired STS credential; the STS token and GitHub token remain separate. It calls existing `runOperatorEntry` once, suppresses exception details, and never retries. A fixed-size .NET async reader drains stdout/stderr in 1 KiB chunks, terminates the child once either stream exceeds 4 KiB, accepts only the expected public result shape, and has a 15-minute overall process bound. A local PowerShell test exercises a fake child emitting oversized no-newline stdout and stderr and verifies termination without sentinel output. Runtime memory beyond explicitly cleared buffers/BSTR cannot be guaranteed erased.

The Windows bridge fixture (`local-operator-bridge.test.cjs`) copies the production PowerShell entry into a temporary test directory and supplies only fake config/Node files plus a test-only `Read-Host` function. It verifies default and invalid-config no-prompt behavior, the separate STS and GitHub sentinel mapping through real child stdin, fixed-output success, child failure redaction, and cancellation before child launch. The fixture cleans each named temporary file individually. It does not use real credentials or network access.

Execution requires `options.enableExternalDispatch === true` and a separate `secrets` object with explicit `{ token, credential: { secretId, secretKey } }`. The CLI intentionally supports only `--check-only <public-config.json>` and never loads secrets. There is no credential discovery or secret-file format.

Execution verifies the source run and artifact through `verifySourceMaterials`, then passes its WeakMap-branded material into the existing `runOperatorFlow`. Return-run selection uses `waitForReturnRun`; TLS completion uses `awaitVerifiedCallerRun` against the source caller run. The offline integration fixture exercises this exact route through certificate verification, SDK-shaped requests, ingress lease, return POST, run binding, caller completion, stop, and lease removal. It does not call GitHub or Tencent Cloud.

The return selection and caller completion are bounded by the source, egress, caller-job, and original five-minute source window. A timeout during a return poll is treated as unknown and is not retried as a dispatch. A3-03 remains HOLD; real credentials, reviewed command IDs and target values, cloud permissions, and live behavior remain outside this offline entry.

## Verification plan and reuse

Before implementation, compared `server-entry.cjs`, `prepare-a-runner.cjs`, `jwks-handoff.cjs`, `return-bundle.cjs`, `verify-return.cjs`, the TAT/VPC adapter and its fixtures with the operator scripts dated 2026-11-24. The existing adapter already binds a source artifact to an in-progress run, verifies run/attempt/workflow SHA/CSR and egress, provides bounded TAT task polling, and leases/removes only its marked ingress rule. `server-entry.cjs` validates the 15-minute authorization and JWKS snapshot; `return-bundle.cjs` builds the already-defined return artifact. This change reuses those boundaries and adds no package or CAM action.

Validation: `node --test *.test.cjs`; offline transport observes start Invoke → exact task/readiness result → return submission → bounded GitHub run polling bound to the same repository/run/attempt/workflow path/ref/SHA and actor as the verified source. The TLS caller and reusable source job are the same run; the return workflow is a separate run that supplies the uniquely named artifact. A built return artifact or a different successful run cannot trigger stop. The adapter accepts only source materials minted by the existing verified-artifact selector. Existing VPC lease cleanup remains owned by `withIngressRule` and runs in its `finally` path, including when stop fails.

Start invocation, each SDK HTTP request, task polling and return construction are bounded by their original absolute deadlines; SDK HTTP `reqTimeout` is set from remaining time (TAT `Timeout` limits only remote command execution). Caller polling is at most 120 requests, five seconds apart, within the source job deadline; a response arriving at/after deadline is rejected. Stop is bounded by the original authorization/resource cleanup deadline and its own remaining TAT timeout. HTTP timeout is an unknown side effect: no retry occurs, one stop is attempted, then the SG lease cleanup runs.

## Operator command templates

`tat-sign-csr.template.sh`, `tat-server-start.template.sh`, and `tat-server-stop.template.sh` are review templates only. `tencentyun-a303-command-draft.cjs` builds non-submittable CreateCommand request candidates with exact template bytes, SHA-256, timeout and declared parameter names; `buildPolicy` creates a three-command/one-instance/one-SG CAM candidate after explicit reviewed inputs. The helper performs no submit or grant operation. The signing template accepts the validated CSR base64 plus `source_run_id`, binds the owner marker before signing, and writes the resulting public leaf certificate at `pki/client.pem`, the path consumed by the existing start template. The lifecycle adapter passes the same owner ID to start/stop; if signing or its task result fails, it makes one stop attempt before propagating the original error. No command creation, CAM grant, or cloud call is part of this change.

The start command accepts only `server_input_b64`, base64-decodes to the fixed public input path with mode 0600, composes local private TLS material, then calls the existing `jwks-handoff.cjs assemble-local` and `server-entry.cjs --check-only` before starting its approved listener. It records a run owner marker before producing secret-bearing config. Readiness requires the recorded PID alive, matching expected server argv, and owning the exact configured private IPv4:8443 socket. Stop requires the matching owner marker, attempts process stop when PID is known, then removes each named file with a separate `rm -f` command, including both private-key-bearing JSON configs; it verifies every path absent and emits the exact success marker only when stop and cleanup are confirmed. Missing/invalid PID still triggers owned-file cleanup but reports unknown. API polling checks invocation/command/instance binding, success status, exit code, output completeness and exact stdout. Arbitrary stdout is never proof.

The adapter accepts the existing PowerShell prep script's public JSON shape and adds `sourceBinding` directly from its verified source-material object before encoding. It validates matching run/attempt/workflow SHA and CSR digest, matching run/attempt/repository fields in the OIDC/request policy, private CVM IPv4/interface, fixed port 8443, CLB IPv4, and an unexpired GitHub JWKS snapshot no older than its 15-minute limit. The full input is strict UTF-8 JSON encoded as canonical base64 before TAT parameter substitution; the shell template rejects non-base64 characters before decoding. CA/server private keys remain on the CVM; runner keys remain job-local.

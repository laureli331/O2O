## 2. 信息架构与角色

### 2.1 全局导航

底部五项为“首页 / 服务 / 发布 / 消息 / 我的”。导航组织方式沿用已确认六页方案，不新增业务。

| 导航 | 承载内容 | 权限与跳转边界 |
| --- | --- | --- |
| 首页 | V01公开分类、搜索、推广与最新需求；进入V02/V03 | 访客可浏览；村/社区手选；不强制GPS |
| 服务 | 维修/跑腿免费服务目录及公开资料；关联V10、V19 | 服务项目、真实区域、时段/忙碌、限定核验说明；联系按授权，不新增独立业务 |
| 发布 | V04维修、二手、跑腿表单及草稿/模板 | 正式提交校验资格；首次发布不要求完整住址，任务必要取送地址独立填写 |
| 消息 | V14站内通知，链接到V08/V07/V11/V12/V17/V18等相关记录 | 本人通知与业务操作，不扩展自由聊天 |
| 我的 | 资料与资格、四项业务入口、私人工具、服务与推广、举报申诉 | 本人管理；运营角色进入V15/V16/V20，实际入口承载形式待明确 |

### 2.2 角色与可见性

角色属于同一账号的能力，同一用户可发单和接单，不拆成互斥骑手账号。两位运营者权限相同，各自操作须可追溯。

| 访问者 | 可以读取或操作 | 不能由当前身份推导的权限 |
| --- | --- | --- |
| 访客、未获准联系者 | 有效公开信息、粗略位置、打码联系、合法公开双向评价 | 登录/收藏/分享不会解码；看不到私密地址、证件、候选详情或原稿 |
| 信息发布者、资料所有者 | 本人内容管理、逐人批准或撤销普通联系；跑腿候选及选人 | 不可编辑他人内容；联系批准不代表成交；草选不代表正式承接 |
| 普通获准联系者 | 仅被批准的具体信息完整联系；本来源实际经历操作 | 授权不跨信息，不继承到再发布，不开放私人地址簿或其他候选 |
| 正式跑腿双方 | 本订单相互联系、必要取送快照/领取码、履约及争议记录 | 履约/争议中不能一般单方撤回联系；不开放其他人的订单 |
| 推广客户 | 本人审核、占位、付款、权益、退款及汇总报表 | 看不到访客身份；付费不提高评分权重或赋予删除差评权益 |
| 必要运营 | 按处理目的看必要证据、审核/核查/协助/处置并留理由 | 无日常完整证件查看页，不作无目的敏感信息浏览，不公开举报者 |

发布和接单须具备有效姓名/身份证二要素与满16岁资格；登录、手机号验证和资格状态分别显示。未满16岁只浏览，16—17岁适用条件须E02确认。供应商失败或未知不显示成功，当前有效结果在发单/接单间复用，不刷脸。

身份变更转人工处理，暂停新的发布/接单；旧身份的订单、推广、标识和评分不直接转交给新身份。公开核验结果只解释姓名与证件信息一致，不证明操作人为证件本人或与微信实名一致；出生日期判断也不能虚构核验接口返回字段。

三色限制仅针对 UI，色阶由透明度与三色混合产生；示例照片允许自然彩色，不冒充真实经营记录。失败、警示、成功等状态用文字、图标与层级区分，不擅自增加第四种UI源色。

### 3.2 层次与布局

正文内容纵向滚动；底部导航/主要操作托盘保持可访问，滚动内容不能被底栏永久遮挡。图片自然彩色，毛玻璃只用于底栏、分类面板、维修照片信息叠层和维修/跑腿操作托盘等少量位置。高斯模糊作用于背景，不作用于文字。

主操作按钮呈斜向绿色渐变，避免将效果说明替代实际效果。照片信息叠层应透出模糊背景；无可见背景时不宣称已实现毛玻璃。常规卡片尽量避免层层套框；保留已采用布局，不将所有功能压进首屏。

## 4. 六页已采用画面的结构

### 4.1 首页（UI01，对应V01）

顺序：绿色柔和背景/叶片装饰 → 标题与微信胶囊 → 手选村/社区 → 搜索 → 三类玻璃入口 → 独立维修推广卡 → 最新需求标题与四分类筛选 → 需求列表 → 五项玻璃导航。

推广卡显示“维修推广”“广告”“查看资料”，普通需求显示任务标题、粗略区域、服务费预算与发布时间。画面只示例一个推广卡，不把它解释为容量1位；维修、跑腿各3位规则不变。首页不虚构真实地区、用户数量、热门度或质量保证。

### 4.2 维修详情（UI02，对应V02）

顺序：详情导航/收藏/分享 → 自然彩色公开照片 → 照片底部玻璃分类与粗略区域 → 标题 → 公开说明 → 发布信息区 → 联系方式卡 → 设计示例/举报 → 玻璃操作托盘。

保留发布信息区，不采用第二次候选删除它的调整。底部主操作为“申请联系”；公开电话示例为“138****0000”，提示“同意联系后可查看完整号码”。本人视角另有编辑、撤回、结束操作；二手对应“已售”，这些操作按PRD补充，不声称已出图。

### 4.3 跑腿报价选人（UI03，对应V03，发布者视角）

顺序：选择承接者标题 → 发布者视角提示 → 公开任务摘要/服务费预算 → 待承接、履约中、待确认进度示意 → 候选标题 → 两张候选卡 → 费用与垫付提示 → 玻璃确认托盘。

示例A报价¥12、不垫付；示例B报价¥15、愿垫付且上限¥50，均为设计数据。卡片边框/勾选仅草选，点击“确认费用并选此人”并成功返回正式承接结果后才转履约中。必须明确最终服务费和垫付条件；并发只能选1人，其他有效申请结束并通知。进度线是当前画面简化展示，不能替代完整状态表。

候选视角展示公开任务、打码联系与本人报价/修改/撤回入口，不能读取其他候选私密资料或取送地址。正式承接后双方才进入V07读取必要快照；同时承接不限量，忙碌不增加接单上限。

### 4.4 二手列表（UI04，对应V01/V02）

顺序：二手标题 → 搜索 → 分类/村社区/最新发布 → 两列商品卡 → 下一排预览 → 玻璃五项导航。保留两张完整自然彩色商品卡和下排部分图片，不采用第二次候选删除下排的调整。

商品卡为公开图片、标题、粗略区域、明确价格或面议；示例自行车¥180、书架面议不作为真实商品。点击进入V02，按普通联系授权。没有二手付费推广、购物车或平台结算，价格不表示交易已经完成。

### 4.5 三维评分（UI05，对应V18）

顺序：评价标题 → 被评对象资料卡/业务角色/实际完成已确认 → 态度、效率、沟通三行各5颗空星 → 三项必选提示 → 选填文字与0/300计数 → 最多3图入口 → 审核提示 → 提交按钮。

保留资料卡，不采用未选候选中删除它的调整。三项未选完不能有效提交；文字和图片均选填，不能强迫为了评分填评价正文。资料卡只是本人评分界面，不向公众额外暴露头像/私密经历，公开评价遵循打码昵称规则。评分资格、截止时间和修改机会在对应状态区/记录页说明，不能因首屏未展开而省略。

### 4.6 我的（UI06，对应V05—V14及V18入口）

顺序：标题/设置 → 资料与登录/资格两种独立状态 → 2×2业务入口“我的发布、我的跑腿、联系申请、我的评价” → 个人工具箱“收藏、草稿、私人地址簿” → 服务管理与帮助 → 五项导航。

保留个人工具箱包围结构、服务管理与帮助入口及资格说明，不采用第二次候选删除或移出这些内容的调整。帮助/服务管理进入免费资料、时段/忙碌、推广、报表、举报申诉等本人功能，未在六页中展开的内容按下一节组织。

### 7.5 实际经历确认（FL05：V08/V06/V10/V07→V17）

争议处理中不开新评分；结案后仍需按实际完成依据核查，关闭争议不自动形成资格。待确认有争议、遭拒确认、无回应或撤回等需核查时，保留原记录与核查记录，无法明确认定实际完成则不开资格。

### 7.8 运营处理（FL08：V14→V15/V16/V20）

举报/申诉/争议或审核请求 → 记录提交时间 → 两运营者同权队列 → 必要证据/理由 → 实际首次回应 → 处理记录/结论 → 对应通知。首次回应24小时目标不等于24小时解决，自动受理不冒充实际运营回应。

限制期限为1/3/7/30天或永久，动作与理由/操作者/时间/前后状态留痕。限制新发布/接单不取消旧订单，不阻止必要履约、取消协商、费用/完成异议和申诉。处置不能当线下款项已结清或司法裁决；举报者身份不向被举报人公开。

推广审核与评价图文/回应各自24小时内给结果；核查/举报/申诉仅24小时首次回应。合法低分、同IP/住址、商家付费或不满意本身不作为造假/删除依据，虚假资格与非法内容分开处理。

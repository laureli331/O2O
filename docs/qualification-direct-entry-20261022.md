# 资格完善直达当前步骤

日期：2026-10-22。用户指出V10接单资料 → V05-B资格总览 → V05-C身份核验连续跳转冗余，要求参考成熟产品后适配。

## 参考依据

[GOV.UK任务列表规范](https://design-system.service.gov.uk/components/task-list/)建议先简化步骤；任务列表适合较长、需要多次完成或自行选择顺序的流程，简单流程不一定需要总览。此处借鉴其减少中间层的原则，不声称已体验其他平台最新版应用。

## 本项目适配

- 原路径：接单资料 → 资格总览 → 身份核验 → 资格总览 → 返回接单资料。
- 新路径：接单资料 → 身份核验 → 完成状态 → 返回接单资料。已登录、已验证电话时省去两次总览跳转。
- 未登录才显示微信登录；登录后仅在缺少电话验证时进入手机号步骤；单独授权后直达身份核验，不再让用户找下一步。
- 已有效资格直接显示状态，不重复核验。未知结果只查询，年龄受限和身份变更仍走既有约束；资料完善不是新的资格门槛。
- 完成后的主按钮直接返回固定来源；取消/顶部返回也回来源。申请的原需求与输入保留，回到申请页后由本人明确提交。
- 从业务入口进入时只展示当前办理画板，窄屏不用先翻过“我的”。
- V05普通入口仍提供资格总览，便于主动查看状态；不增加新的页面、授权合并或业务规则。

## 验证方案与结果

为步骤选择增加状态矩阵测试；浏览器验证V10直达、有效资格复用、游客登录及手机号的独立同意、未知/年龄受限不放行、取消保留原申请、完成后不自动提交。检查320/375/414px无横向溢出、底部操作不遮挡内容，以及V05原有管理入口和V03申请行为。

预览仍使用只读合成姓名与证件；没有接入真实微信授权或身份核验。30分钟临时资格和一次性申请恢复仅供本地演示，不能代替服务端权限校验。

## 浏览器旧缓存修复

用户实际标签页出现空白，日志确认 `V10Flow.qualificationStep is not a function`：新版HTML依赖新增方法，而浏览器沿用未带版本号的旧脚本。此前全新浏览器测试未覆盖这种更新组合。

V03、V05、V10统一使用与脚本内容SHA-256摘要对应的资源版本；脚本变更后必须同步版本。新增浏览器回归测试，在旧地址提供缺少新方法的旧模块，先复现同一报错，再验证新HTML绕过旧缓存、显示核验表单并正常返回。内容摘要契约测试防止后续脚本更新漏改版本号。本次不变更资格规则与页面设计。

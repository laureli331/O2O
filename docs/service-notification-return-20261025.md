# 通知详情返回原来源

2026-10-25。沿用统一服务订单页与次级通知入口，修复通知到需求/订单之间的返回连续性。

## 实际问题与修复

- 已复现：从“我承接的”筛选进入通知、打开维修需求，再返回会跳到服务列表，通知点击还强行改成“我发布的”。现在保留原服务筛选，从通知进入的需求详情返回原通知列表。
- 记录通知标签、阅读位置及触发项。全部标签下返回原通知；未读标签中原条目已读后不再显示，定位同位置下一条，末项退到上一条，空列表定位当前通知标签。不会为了恢复位置把已读通知改回未读。
- 进入进行中/历史订单仍复用V07完整详情与原授权校验，只在原返回地址携带通知来源和一次性返程凭据。通知状态在本标签页临时存储，返回消费后删除；重建合成通知列表并恢复已读标记、筛选、焦点及位置，不把通知改成服务订单。
- 返程只接受匹配的凭据、既有演示状态、全部/未读选项、固定通知ID序列、布尔已读值和有界阅读位置，不从返程信息导入订单、标题、联系方式或业务处置。旧凭据重放不能复用旧状态；存储不可用或数据不合条件时按原通知页兜底。
- 返回服务页继续原来的本人角色、业务、状态筛选；“全部已读”后定位当前通知标签，不把焦点留在已被重绘的按钮上。
- 草稿编辑/管理离开保护、通知计数、固定通知工具栏、右下浮动入口和V07交易规则不变。仅保存通知界面返程状态，不持久化服务记录或编辑结果；普通新进入/刷新仍按原演示规则重置，不接真实消息或交易后台。

## 参考与适配

[GOV.UK返回链接规范](https://design-system.service.gov.uk/components/back-link/)要求回到上一个页面及离开时的状态；[W3C焦点顺序说明](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)强调合理可操作的焦点。本项目适配为区分通知来源与订单列表来源、未读移除后的邻项定位，复用原导航和详情，不新增中转页或业务功能。

# SP01 R06：CloudBase 数据库恢复能力更新

日期：2026-11-01。结构化证据见[JSON](sp01-recovery-capability-20261101.json)。本次只核对腾讯云官方公开资料，并沿用此前用户只读查看的控制台结果；没有登录、查询、修改或写入云环境。

## 已查明的公开套餐能力

腾讯云当前[资源点与套餐能力表](https://cloud.tencent.com/document/product/876/127357)将数据库回档列为：免费体验版和个人版不支持，标准版及以上支持14天；JSON/CSV数据导入导出列为各套餐支持。腾讯云[文档型数据库说明](https://cloud.tencent.com/document/product/876/46897)还写明默认每日备份保留7天、个人版不支持回档，并把升级后的实时备份与14天保留单独描述。这里的备份保留与套餐能否使用回档是不同问题，不能把公开的备份机制当成目标环境有可用恢复点。

CloudBase 官方[导入/导出说明](https://docs.cloudbase.net/database/manage)提供集合 JSON/CSV 导入导出步骤；JSON可保留嵌套结构，适合完整导出。项目没有实际导出或恢复，不能据此声称目标环境的恢复流程已演练通过。

## 目标环境证据边界

此前用户只读反馈：cloud1 数据库设置有相关入口，区域显示「暂无数据」，没有付费或不可用提示。此前套餐截图报告标签为「微信体验版」、40,000点/月及¥19.9/月；这些字段不能与当前公开套餐表无歧义地对应，也不证明已付款或具体恢复权益。没有重新查询目标环境或账单。

因此，公开套餐层面的能力已经查明，目标 cloud1 的当前套餐映射、回档权益、恢复点、实际保留期和费用仍未核实；R06、E06及SP01继续保持未通过。当前没有用户操作需要：不创建回档、不导入导出、不更改环境设置。正式业务数据建立前，再用只读套餐信息确定当前权益，并落实可执行的备份/恢复替代方案。

## 复用核查

复用腾讯云现有文档型数据库套餐能力与官方 JSON 导入/导出流程；本轮没有新增依赖、代码或自制恢复机制。来源均为腾讯云官方产品文档。最小验证是逐项对照套餐表和数据库操作文档，并与既有只读控制台报告分开记录；没有执行云端恢复验证。

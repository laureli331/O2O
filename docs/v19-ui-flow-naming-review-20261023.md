# V19「公开评价」UI、流程与命名复核稿

日期：2026-10-23  
性质：审阅建议已于2026-10-24获用户全部确认并实施；下文保留原审阅依据。

## 1. 结论先行

V19 已经做到按业务和被评角色分别统计，不生成默认 0 分，也没有把私密订单信息带入公开详情；空态、访客浏览、举报和本人回应入口均可成立。

当前主要问题是“数字的含义需要用户猜”：汇总区直接显示 `3.5`，没有紧邻的“综合评分”和 `/ 5`；点击态度、效率、沟通后，下面的星级桶图没有动态标题，用户不容易确认正在看哪个维度；“按首次提交时间排序”也没有说明从新到旧还是从旧到新。

建议不改变统计公式，只把统计对象、量纲、当前维度和排序方向说完整。本人查看收到的评价时，再把“回应评价”提升为主要任务，把“举报”保持为次级操作。

## 2. 已核对范围与验证方式

实际检查包括：

- 默认对象下的维修业务、维修服务方角色、综合分和三维均分；
- 态度/效率/沟通三个维度切换及 1—5 星数量分布；
- 公开评价列表、图文、对方回应、详情和举报链接；
- 25 条评价场景及“再看 20 条”的分页加载；
- 图文修改待审、图文修改未通过、空态和访客浏览；
- “我收到的公开评价”及可回应记录；
- 详情页只展示合法公开字段，不出现订单私密资料；
- 375px 视口下的滚动、底部操作和横向溢出；现有测试覆盖 320px、375px、414px。

已确认且不在本稿中改变的边界：四类业务、各自角色分组独立；评分使用有效公开记录；无记录时不显示默认分；图文审核与数值评分分开；排序依据是首次提交时间；举报携带准确评价编号；回应仍进入 V18。

## 4. 问题与修改建议

### P1-01：裸数字 `3.5` 缺少名称和量纲

**现状**

汇总区把 `3.5` 作为最大视觉元素，下方才显示“2条有效评价”。用户需要从上下文推断它是综合评分而不是某个维度、满分 5 分而不是 10 分。

**建议**

固定显示：

```text
综合评分
3.5 / 5
基于 2 条有效评价
```

“有效”可保留，用来说明被撤销或资格失效的记录不计入；空态继续不显示 `0.0`。

### P1-02：评分分布缺少当前维度标题

**现状**

“态度 4.5 / 效率 3.5 / 沟通 2.5”既像指标卡又是切换控件。切换后，下方直接出现 5—1 星分布，没有再次标明当前维度。

**建议**

- 给切换区域增加可见标题“查看分项分布”；
- 当前项使用选中态，不只依靠颜色；
- 桶图上方动态显示“态度评分分布 / 效率评分分布 / 沟通评分分布”；
- 读屏名称包含维度、均分和选中状态。

### P1-03：排序说明缺少方向

将“按首次提交时间排序”改为“按首次提交时间从新到旧”。这与现有稳定排序规则一致，不新增排序能力。

### P1-04：本人收到评价时，举报与回应的任务层级相同

**现状**

本人查看可回应的评价时，“举报”和“回应评价”并列为相同层级的小链接。

**建议**

- 列表卡片保留弱操作 `举报`；
- 详情底部在允许回应时显示主按钮 `回应评价`；
- 已提交回应时改为状态 `回应审核中 / 回应已公开 / 回应未通过`，不要继续显示同样的“回应评价”；
- 举报仍进入 V14 并携带当前评价编号，不改变既有流程。

### P2-01：姓名旁“公开评价”标签信息量低

页面标题已经说明“邻友的评价”或“我收到的公开评价”，姓名旁再次显示“公开评价”没有帮助用户确认当前筛选组。

建议二选一：

1. **推荐**：标签改为当前分组，例如“维修 · 维修服务方”；
2. 删除标签，只保留姓名和筛选器。

不要在此处显示未经确认的认证、等级或信用标签。

### P2-02：演示场景名称与实际生效范围不完全一致

与 V18 保持同一套演示命名：

| 当前 | 建议 |
|---|---|
| 修改图文待审 | 修改已提交，图文待审 |
| 修改图文未通过 | 评分已生效，图文未通过 |

这能避免评审时误判为“整个修改都未生效”。

### P2-03：“最近评价”与固定排序说明可以合并

当前标题“最近评价”与副标题“按首次提交时间排序”表达重复但又不够精确。建议改为：

- 主标题：`评价记录`；
- 辅助说明：`按首次提交时间从新到旧`。

这样也能覆盖将来记录较旧但仍有效的情况。

## 6. 建议流程

```text
公开评价总览
  ├─ 选择业务 → 角色自动切换到该业务合法角色
  ├─ 查看综合评分、有效条数和三维均分
  ├─ 选择维度 → 查看该维度 1—5 星分布
  └─ 查看评价记录
       ├─ 详情 → 举报 → V14（携带评价编号）
       └─ 本人且允许回应 → 详情底部“回应评价” → V18
```

切换业务或角色时，综合分、三维均分、分布和列表必须来自同一筛选组，不能出现局部未刷新。

## 7. 已确认的关键决策（2026-10-24）

1. **D19-1（推荐）**：汇总固定使用“综合评分 {分数} / 5 + 基于 {数量} 条有效评价”。
2. **D19-2（推荐）**：分布图增加动态维度标题，并把固定排序写完整为“按首次提交时间从新到旧”。
3. **D19-3（推荐）**：姓名旁标签改为当前“业务 · 角色”，不再重复“公开评价”。
4. **D19-4（推荐）**：本人收到的评价在详情底部突出“回应评价”，举报保持次级操作。

以上推荐项已确认并实施；既有业务规则、评分算法及真实能力启用边界不变。

## 8. 实施后的验收清单

- 综合分始终带“综合评分”和 `/ 5`，有效评价条数紧邻显示；
- 空组不显示 `0.0`、空分布或伪造样本量；
- 切换业务、角色、维度时，总览、分布和列表属于同一分组；
- 当前分布标题随态度/效率/沟通切换；
- 排序文案与实际“首次提交时间从新到旧”一致，修改评价不改变原排序位置；
- 20 条分页追加不重复、不漏项，加载后焦点和滚动位置合理；
- 公开详情不出现手机号、私密证据、草稿或未审核回应；
- 举报携带当前评价编号；回应只对本人合法记录开放；
- 320px、375px、414px 下无横向滚动，长评价和回应可完整换行；
- 按钮与筛选项具备清晰选中态、键盘焦点和轻微按压反馈；
- 原有统计、模型、页面和全量回归测试全部通过。

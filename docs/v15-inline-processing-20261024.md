## 页面变化

保留网页主侧栏、队列和详情三栏，宽屏详情内部采用“材料＋处理区”并排；较窄屏幕在同一页上下排列。原文、举报说明、原结论和独立材料持续可查，选择处理方式后只展开相应期限、能力或金额字段。

取消独立填写页、上下文中转页及整页核对。账号动作在处理下拉中的“更多处理·账号”分组，账号限制历史默认折叠。原文中的被举报句子高亮，不再重复输出“你需要判断什么”卡片；仅重述原句的材料不再单独成卡，原合成数据仍保留。

固定操作区保留返回、保存草稿和当前具体动作。成功更新原事项，失败保留填写，未知结果只提供本次查询。未知/失败时不把此前的成功回执当成本次结果展示。

## 操作与确认

| 方式 | 动作 |
| --- | --- |
| 填写后直接记录 | 首次回应、请求补充、无需处置/维持结论、明确重新开启。 |
| 一次确认弹窗 | 整改、下架、账号限制/封禁/解除、费用核验与通知、实收分配、核对多收与发起退款、故障保护与恢复验收。 |
| 查询已有请求 | 原操作结果查询及退款状态查询；不发起另一笔操作，不增加重复确认。 |

重要操作仍复用现有模型预演，展示该动作的对象、精确前后变化及理由。账号核对包含所属账号、所选能力/限制条目与期限；费用包含原标准、核准额、差额和原截止；实收包含逐笔分配、暂缓项和多收；恢复包含验收引用与逐交易保护截止。默认焦点为“返回修改”，取消或Escape关闭后保留填写及原材料位置。

业务事件保持独立：记录回应不结案、不视为通知送达；最终结论不自动补首次回应；请求材料不重置原回应目标。各条限制独立、终态明确重开、模型权限/版本/幂等、资金与故障算法均未改。

## 理由短句

每种操作显示3个相关短句或具体依据的填写起句，由用户手动点选，打开事项不预填。插入保留已有文字和选中文字，不自动改变动作。重复点击不叠加，插入后可编辑；撤销只移除仍可安全定位的最近插入段，保留其它文字，插入段已被改写时提示手动调整。

沿用1—1000字限制；超出空间不截断原内容。涉及处罚、金额或验收时，只有“所依据的材料是：”等起句不能提交，需补充本事项具体依据。短句不调用AI、不自动生成已核实事实，也不执行处置。

## 状态与恢复

- 切换动作保留输入、刷新短句与相应字段；不重复选过的动作。
- 切换事项或离开时，沿用明确保存与未保存离开确认。仅选择动作而没有改变实际填写，不增加离开拦截。
- 失败留在同页，输入不丢失；未知结果在本事项处理区显示，刷新后仍恢复原请求，其他事项不能提交新操作。
- 事项或所属账号版本变化时保留理由，重新读取当前状态、清空动作/能力范围/期限，要求重新选择并核对；不覆盖新状态。
- “无故障核实依据”场景的头部、申报说明及材料均显示待核实，不再出现“影响范围已核实”或假称已有日志。故障保护与恢复操作仍由原模型限制。

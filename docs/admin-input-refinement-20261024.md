# 配置编辑退出与评价处理说明

2026-10-24。承接用户继续优化前序HTML的要求，本轮处理V16、V20。沿用已确认的网页管理台、配置发布核对和V20一个队列/两个工作台，不修改真实业务模型或管理权限。

## V16：有改动才提醒

原编辑态无论是否修改都会提示放弃，核对页反而没有同样保护。本轮比较进入编辑时的快照：未修改、改回原值、重新打开已保存草稿且没有新增修改时直接离开；编辑页或核对页存在未保存改动时仍确认。保存草稿不发布，发布不等于实际生效；未知结果沿用原请求查询。既有校验错误焦点、当前/拟发布对照、旧交易锁定快照与版本日志保留。

## V20：常用提示只辅助填写

- 原因框旁提供三个与当前动作相符的提示及撤销入口。回复用户提供接收/继续核对提示，请求补充提供沟通记录、服务经过及相关凭据提示；审核/结论只提供依据、范围、材料来源的填写开头，不代替运营下结论。
- 手动点选后插入，可继续编辑；不预填、不覆盖选择的原文字、不选择公开/拒绝结论、不勾选材料、不自动提交。重复点选不重复插入，超长保持原文；撤销仅移除上次插入段，若该段已被修改则提示手工调整。
- 原因只有提示开头时，页面要求补充具体材料或原因后再核对；所有操作仍进入原确认层，权限、证据引用、范围、版本冲突及未知查询校验不删。
- 版本冲突或存在待确认请求时，提示与撤销随原填写区停用；成功、失败与结果未知不混用。
- 复用既有V15Flow的纯文本insert/undo/incomplete方法，未修改V15文件、业务操作确认分类或独立改版基线；V20自己定义提示菜单。撤销位置仅当前页面内存，不新增真实服务或跨页面输入存储。

## 参考与适配

[GOV.UK提交前核对](https://design-system.service.gov.uk/patterns/check-answers/)建议提交前让用户检查所填内容；本轮保留配置和评价处置的影响核对，不为减少步骤删除必要确认。[NN/g识别与回忆](https://www.nngroup.com/articles/recognition-and-recall/)说明可见选项有助减少从头回忆。本项目将其用于可编辑理由提示，沿用V15已认可的方式；不引入自动判断或与当前案件无关的成文结论。参考为公开规范和文章，不声称体验最新版应用。

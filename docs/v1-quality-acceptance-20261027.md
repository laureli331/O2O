## 1. 验证方案与证据等级

本轮先核对来源、覆盖、依赖和已有测试，再完善合同；交付前检查文档与JSON一致、全部本地链接、编号与映射、工作区差异，并执行现有计划测试和全量Node回归。不编写产品、HTML、脚本或测试代码，不删除历史或修改他人改动。

产品开发按四层取证，任何一层不能代替后一层：

| 层次 | 可以证明什么 | 不能证明什么 |
| --- | --- | --- |
| L0 文档/模型检查 | 计划结构、规则样例和引用一致 | 页面真实可用、服务端鉴权、真机性能 |
| L1 HTML浏览器 | 指定原型的可达、布局和合成交互 | 微信键盘/胶囊、真实账号/资金/云端结果 |
| L2 正式工程受控集成 | 实际服务端权限、事务、时钟、状态、故障和合成业务闭环 | 未开通供应商、生产数据处理资格或正式收款 |
| L3 实际能力与真机 | 指定版本/设备/环境下的真实集成、性能、隐私、安全和恢复 | 永久无故障或未测试设备均可用 |

本轮仅交付L0合同。历史33页423组布局/状态、23组主要交互及1353项Node是UI交付快照，不改写为本次或未来正式产品结果。实际产品结果当前均为“未执行”，不预填成功或伪造证据。

1. 已确认首版功能、有效页面/适用状态、82项原验收及新增经营合同100%有责任任务与证据。条件性未启用、取消和延后范围分别列出，不用省功能换通过率。

3. 视觉逐页人工审阅并取得用户认可，按钮/返回/输入/滚动等实际操作也须逐页确认。相同组件可复用测试方法，但每个页面保留实际执行证据，不以一个代表页替代全页。
4. 冷/热启动、切页、反馈和滚动按第5节分组达标；不能用快设备、缓存命中、平均耗时或混合网络数据掩盖失败组。
5. E01—E06、QG01、AG01、DG01按计划首版实际启用范围有证据；未满足的首发能力不得伪称通过，不擅自从首发移除。任何缩小范围需用户确认并更新基线。
6. 资金/权限/数据版本/计时/恢复的正常、异常、边界与竞态均有L2/L3证据。备份文件存在不等于恢复通过，截图不等于收款事实，正常结束不等于客户已付款。
7. 最终版本、配置、设备、全部结果、缺陷复验和回退点一致且可定位，有用户独立上线授权才可提审/发布。完整真实验收后才启动既定连续14天稳定观察；严重/阻断问题按PRD修复验收重新计时。

“不适用”只用于该页面确无对应动作或经最新确认明确取消的范围，必须附来源、理由和责任任务。接口未实现、无设备、没权限、没时间、失败和未执行均不属于不适用，也不计通过。100%通过率的分母是全部适用必验实例，不能把失败从分母删除。

## 5. 性能、设备与重复测量合同

### 5.1 已确认的项目门槛

2026-10-27用户已确认采用以下严格门槛、三类真机覆盖及3轮/每轮至少30次的分组测量。这些是项目选择，不冒称微信统一规定。SP01登记实际设备型号、OS、微信及基础库/渲染引擎、云运行时、构建方式、网络和数据清单；没有实物或精确版本不能写成已验。

| 指标 | 起止与测量范围 | 每个必验组的通过条件 |
| --- | --- | --- |
| QP01 冷启动首屏可操作 | 用户触发打开到首屏必要真实数据或真实空态完成，首个合法操作可响应；单列有包缓存/无包首次访问及云函数冷实例 | 正常网络P95≤3000ms；骨架、首帧、onReady或后端响应单项不能代替整体终点 |
| QP02 热启动首屏可操作 | 证实原进程/资源保留，用户重新进入到当前首屏状态恢复可操作；测量前登记缓存/前后台条件 | 正常网络P95≤1000ms；进程被回收后归冷启动，不混样本 |
| QP03 常用页面切换 | 已启动环境中，从点击导航/详情/返回到目标必要内容及合法操作可用 | 正常网络P95≤800ms；覆盖首页↔详情、服务↔订单、发布、我的、发现↔主帖及本人账单；后台同类导航单独分组 |
| QP04 按钮可见反馈 | 输入事件到可见按压/选中/处理中反馈，使用同一时基的视频或事件/渲染轨迹；不包含等待业务最终结果 | 每个有效样本≤100ms；不借动效拖延实际状态更新或用提前成功冒充反馈 |
| QP05 滚动与交互动效 | 60Hz设备在持续用户操作窗口记录真实帧及输入/渲染轨迹；冻结窗口长度，排除无操作空闲段 | 每段连续滚动平均≥55FPS，且无超过100ms的应用可归因卡顿；无视觉跳变/错触；不得只测空列表或隐藏帧 |

最低设备为一台入门Android、一台主流Android、一台iPhone，型号在SP01核实；网页后台另记实际Windows浏览器版本与支持范围。高刷设备记录实际刷新率，不将120Hz结果冒充60Hz组。真机硬件、微信/系统最大文字档、屏幕阅读能力、键盘和安全区按实际能力记录；实际不支持的测量项不虚构读数，须选择可用等价取证方法并确认。

### 5.2 环境、数据和测量规程

1. 一个组＝设备/OS/微信/基础库或浏览器＋构建/渲染模式＋网络＋数据集＋路径＋缓存/云实例条件。每个耗时组独立3轮，每轮至少30次，分别报告P50、P95、最大值及失败/超时数量。P95采用排序后最近秩ceil(0.95×n)，不能先对三轮均值再求P95；三轮分别过线才通过。
2. SP01在正式工程开始前冻结测量配置。正常网络必须登记实际上下行、RTT、抖动、丢包、接入方式及其稳定范围；弱网另冻结限速/高延迟/丢包/中断/恢复配置及可复现设置步骤。不得仅用“Wi-Fi/4G/弱网”作环境定义，也不把人为配置当当地用户网络事实。
3. 测试数据固定种子/版本：空、1条、单页20条、至少连续加载10页（200条），以及各字段允许的最大文字/图片数量和边界值。实际图片字节、尺寸、格式和资源缓存状态要登记。若业务无列表或字段不适用，引用页面合同解释，不能用不相干数据集替代。
4. 冷启动3轮各30次，热启动和每条常用切页路径同样分组。QP04对适用的主操作/表单/弹层按钮各组3轮，每轮至少30次；QP05每组3轮，各轮至少30段持续操作片段，片段长度在SP05固定并保持一致；保存帧轨迹而非只报平均FPS。
5. 同一组不能混调试版和体验/候选版、不同采样工具、设备温度状态或网络。记录采样开销；不得在测试中更换参数追求通过。系统弹窗/来电等无关干扰可标无效，保留原因与原证据并补采；有效慢样本、超时或失败不得剔除。
6. 每轮逐实例对齐UI和服务端轨迹，避免不同设备时钟相减。等待第三方支付/核验/AI时，界面必须按QP04及时反馈，最终耗时单独记录，不能混入普通页面切换或伪造成功；状态终点和计费事实各自独立。

## 6. 视觉美观、交互与无障碍的人工验收

对每个有效HTML及其正式承载，执行本文件逐页矩阵中的业务状态和适用G状态。页面不合并免验，归档文件不重新设计。原型尺寸单位为CSS px；小程序适配记录实际逻辑尺寸，不把截图物理像素当rpx或机械缩放。

- 视觉基准检查：按组件角色核对当前变量，保留图文封面贴边、胶囊/头像/圆形按钮、金额/品牌独立层级和后台表格容器滚动等已确认例外。每个差异注明是否为已批准例外，不能靠“肉眼差不多”替代测量，也不追求跨系统字体逐像素相同。
- 审美审阅：对同版本、同视口、同数据的整页和关键区域截图，逐项评阅信息主次、留白节奏、对齐、可读性、图片裁切、颜色克制、图标一致、状态辨认及视觉稳定；每项分别“通过/需修改”，任何一项需修改即记录缺陷。先由执行者逐页自审，再由用户审阅全部页面证据；不得只用总分或自动截图相似度放行。
- 移动窄屏320/375/414 CSS px和后台1280/1440 CSS px沿既有基线；后台窄屏按已确认响应式方案另验。长内容到字段上限、200%文本缩放和系统大字，逐项检查信息不丢失、重要动作可达、滚动到底不被固定栏遮挡，表格横向滚动仅限表格容器。实际小程序缩放能力不同须明确等价用例。

## 7. 安全、资金、计时和恢复的强制方法

1. 权限至少以访客、未具资格者、当前当事人、另一候选/无关账号、商家本人/他店、管理/非管理账号直接读写同一对象验证；检查完整响应、原图/缩略图/元数据、旧URL、搜索、分享、通知、缓存。只藏按钮不是通过，不能为了测试收集真实原证件。
2. 并发必须制造真实重叠竞争，并保留请求开始/结束、不同请求ID和事务/状态证据；顺序连点不是并发。优先测最后一名额/库存/有效评分修改/公开回应/退款余额、选人和核销；一组多请求只能形成合法数量的最终事实。
3. 金额校验使用分/精确定点，按各业务本来的舍入和封顶规则判定，不统一改为另一种舍入。区分付款、实际抵付、欠费、暂缓、抵扣、多收退回、佣金更正；不同实收不能当同回调重放，未知先查，不能用退款改写付款事实。
4. 所有期限以服务端事实为起点，分别测截止前、截止瞬间、严格超过及与相反动作的竞态；按当前业务“截止及时/严格超过”的规则判定，不套原24小时手动完成。模拟时钟在受控环境使用，另验证实际调度和恢复重放。
5. 故障注入点覆盖状态已落库但通知失败、事务前/后断网、回调迟到/重复、图片检测失败、任务停止/重启、配置/审核旧版本迟到。记录唯一业务事实、版本、消息和可恢复路径，不能为演示修复直接篡改结果。
6. 备份/恢复选择完整对象关系和失败中的请求，恢复到隔离目标后对账授权、订单、佣金、付款/退款、广告区间、券库存/核销、评价版本和通知。实际外部资金事实只核对/补偿，不回滚成未发生；付费/隐私/数据丢失等阻断缺陷修复前停止受影响的新操作，保留旧履约与申诉。

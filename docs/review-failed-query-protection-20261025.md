# 评价查询失败后继续保护未提交内容

2026-10-25。沿用已确认的V18提交、查询和未提交离开规则，修复状态恢复缺口。

## 实际问题与修复

- 已复现新评价提交结果未知，查询确认失败后，评分与文字虽恢复，编辑基线却被设为这份尚未提交的表单；返回不会再提示，可以直接丢掉填写。
- 将新评价、修改评价、回应的原始表单构造合并为同一函数，开始编辑及查询失败时共用原始基线。查询失败恢复当前评分/文字/图片元信息，仍和原记录比较，确有未提交改动才触发原离开保护。
- 待确认请求经刷新恢复后也从原记录计算基线，不依赖查询前页面内的临时变量。已存在的未通过回应原文或未修改的原评价仍是比较起点，未产生新修改时不额外打扰。
- 复用原确认层，保留按钮明确写“继续填写”；取消返回、取消切换演示状态仍保留内容，明确放弃才回列表。浏览器离开提醒继续使用现有实际改动判断，不增加新的保存机制。
- 失败不新增评价、不消耗一次修改机会、不创建回应；重新明确提交成功后才按原模型更新记录。资格、评分生效、图文审核、修改次数、公开回应及幂等查询规则不变。
- 失败提示区分评价与回应，仅在确有图片时说明图片占位，不向纯文字回应展示不存在的评分或图片提示。
- 原图仍不上传或跨页保存，未知后的失败恢复仍按原说明显示图片占位；不声称新增原图恢复能力。V19与共享模型/弹层组件未修改。

## 参考与适配

[GOV.UK错误恢复规范](https://design-system.service.gov.uk/patterns/validation/)强调保留原填写，便于修改并避免重复输入；本项目将同一恢复原则用于原有合成查询失败分支，不将系统失败当作字段校验失败，也不改变既有错误提示结构。[MDN离开事件](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)说明原生提醒用于保护未保存内容，同时移动端不保证所有关闭路径触发。此处只是修正现有判断，不把提醒等同保存。

## 验证方案

先复现“失败恢复后未提交标记变为干净”。专项覆盖新建/修改/回应三种操作和320/375/414/1280px，检查未知后查询失败、刷新后查询、评分文字保留、继续填写、取消演示状态切换和明确放弃。核对失败时无新增/无修改次数消耗/无回应；375px重新提交成功后各对应记录仅更新一次。检查截图、横溢和浏览器错误，回归评价全流程、次级交互和关联订单上下文，更新V18资源版本。同步ASCII/PRD后运行全量Node、14项文档、资源交接和差异检查并提交Git。

## 验证结果

专项先复现失败恢复后的未提交标记错误；修复后三种操作在320/375/414/1280px全部通过，包含刷新待确认请求后查询失败、评分/文字保留、返回继续填写、切换取消及明确放弃。核对失败没有新增评价、没有使用修改次数、没有生成回应；375px重新明确提交成功后仅更新对应记录一次，成功后不再标记未提交。已复核375px截图，纯文字提示不再带无关图片/评分。评价全流程、次级交互和订单上下文回归通过；全部1225项Node测试、14项文档验证、57项资源/26项图标交接及差异检查通过。

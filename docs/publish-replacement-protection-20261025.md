# 发布内容替换前保护当前修改

2026-10-25。检查V04发布表单连续性，按实际会丢失内容的路径收窄本轮范围。

## 问题与调整

- 切换发布类型、返回发布入口、打开草稿列表原本保留各类表单，本轮不为这些操作增加确认，也不改变原填写逻辑。
- 实际复现：保存草稿后修改标题、地址和图片，再恢复旧草稿，会直接覆盖当前修改。本轮在恢复草稿、复用本人常用需求、使用文字模板和再次发布之前检查目标类别表单。
- 目标表单确有未保留修改时，提示“替换未保存的内容？”，正文明确是维修、跑腿、闲置还是其它表单；优先聚焦“保留原内容”，明确选择“确认替换”后才执行原操作。跨类别复制只检查真正被替换的目标，不误清另一类填写。
- 保留、Esc和遮罩取消不改变标题、私密地址、图片、草稿或AI已采用内容，焦点回到原触发按钮。背景暂不可操作，Tab在两个按钮内循环。替换完成后聚焦表单标题，继续核对内容。
- 未修改的初始表单，或者当前内容已有完全一致的本页草稿副本时，不重复打断。保存草稿只认现存副本；删除唯一副本后，再替换当前未保留修改会重新提醒。原成功发布及导入/复用起点更新对应比较基线。
- 检查完整表单数据，包含图片用途与本地预览引用、私密地址、AI采用后的值。这里只防止覆盖，不新增草稿持久化、真实发布或自动保存。本轮不调整浏览器刷新/离开行为，本页草稿和图片仍按原说明仅保留在当前演示页面。
- 结果未知保护保持优先：不能借恢复或复制清除原查询。原复制不继承私密信息/申请/授权规则不变，替换后仍需重新核对并明确发布。

## 参考与适配

[W3C模态弹窗规范](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)规定背景不可操作、焦点保持在弹窗内、Esc取消和关闭后恢复合理焦点；不可逆操作宜优先聚焦较安全选项。本项目采用既有绿色按钮、纸色背景和底部弹层，明确覆盖的类别，不照搬其它产品视觉，也不增加原本不会丢内容的步骤。

# 订单列表返回连续性

2026-10-25。沿用已确认的原入口返回原则，补齐服务列表到需求/订单详情的往返。

## 问题与方案

浏览器先复现：点击订单操作按钮进入需求详情，返回后焦点没有回到原卡片；跨V07仅带内部列表偏移，未带原按钮及外层阅读位置。现在记录原卡片、主卡片/底部按钮入口、内外滚动位置；同页返回恢复原入口，跨V07沿既有返回地址带回这些界面参数。连续两次往返仍保留已恢复位置。

筛选继续复用原角色、业务和状态，改变筛选或重置后清除旧入口。目标必须存在于当前筛选后的已渲染列表，不存在则定位当前角色标签；查找采用逐项ID比较，不把传入值拼接成选择器。滚动参数仅接受0至100000的有限数字，异常值归零。不会从返程参数导入订单、标题、联系方式或操作结果，不新增存储或页面。

[GOV.UK返回链接规范](https://design-system.service.gov.uk/components/back-link/)要求回到上一个页面及离开时的状态。本项目沿用该原则，适配小程序预览的内部滚动容器与外部页面；沿用现有视觉、入口、未保存保护和通知来源返回逻辑，不新增业务或确认步骤。

## 验证方案

先复现原按钮焦点丢失。320/375/414/1280px覆盖发布者维修、申请者跑腿的同页往返，以及已成交闲置、已结束其它订单跨V07往返；各连续两次，检查原入口、角色、内外阅读位置。另测主卡片入口、业务/状态筛选、不可见目标、无穷/负偏移的兜底及横向溢出、浏览器错误。回归通知往返、编辑离开保护、服务完整流程；运行全量Node、14项文档、交接与Git差异检查。

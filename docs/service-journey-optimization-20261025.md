# 服务任务链路与优化记录收口

本轮范围已由用户确认：按顺序完成服务页申请/选人衔接、详情子流程返回、重复入口整理、任务链路验收、审查记录收口，全部完成后统一交付。

## 方案与边界

1. 申请/选人携带原需求类别、公开标题、金额、约定时间与原服务详情返回地址。服务来源只呈现对应角色，独立V03仍保留双角色演示。返回地址限定同源服务页，来源不能当作真实权限或评价资格。
2. 编辑、关闭/重开、历史子流程记录原详情入口与内外阅读位置；取消/保存后回原详情，入口消失则定位合理的当前入口。未保存保护及通知来源返回保持。
3. 历史统一留在详情内已有入口，从更多菜单移除重复项；同步精简重复或不帮助判断的说明。保留关闭后果、时间/金额、权限和未知结果保护。
4. 按发布→申请→选人→交易→评价逐段核对同一内容、角色与返回；覆盖既有正常、失败、取消及未知路径。当前为分模块合成演示，检查中明确记录哪些只是导航/展示、哪些是同页模型状态；不伪造真实订单、付款、评价资格或跨模块业务同步。
5. 旧审查按历史保存，增加最新结果索引，标注已解决、已验证和真实接入未验收，不继续把已制作的V21/V22记为未制作。

参考[GOV.UK返回链接](https://design-system.service.gov.uk/components/back-link/)恢复来源状态，以及[提交前核对](https://design-system.service.gov.uk/patterns/check-answers/)保留必要核对。本项目沿用现有小程序视觉和已确认业务，不以简化为由移除后果确认。

## 验证方案

每个实现批次先复现、补用例，覆盖320/375/414/1280px、长内容、原按钮焦点、内外位置、正常与非法返回地址、源需求类别/标题/金额/时间、角色展示及未保存保护。最后运行既有发布/申请/交易/评价相关浏览器验证、全量Node测试、14项文档验证、交接和Git差异检查。各批次独立Git提交，最终统一记录证据与限制。

## 结果

第一批：已复现维修需求错误进入默认跑腿预览。服务页现带入需求类别、公开标题、服务费和时间；服务来源仅显示对应角色，返回恢复需求详情与申请入口，并保留通知来源和未读状态。非法外部返回地址回到服务页。四种屏宽、申请未保存保护和通知回归通过，全量1229项Node、14项文档及交接检查通过；分模块预览边界不变。其余批次及最终验收见下文。

第二批：详情进入编辑、管理、历史前记录原按钮和内外位置，取消或保存后恢复；关闭导致内容缩短时按实际可滚动高度保留位置，原入口消失则定位更多。长说明、明确保存/放弃、重开取消及四种屏宽通过；弹层隔离回归、全量1229项Node、14项文档与交接检查通过。

第三批：历史只保留需求详情内入口；更多只在确有关闭操作时展示，避免只剩取消的空菜单。编辑页移除不帮助填写的“不置顶/发布时间”规则说明，关闭说明的选填提示放进输入框。必要关闭后果、隐私范围和校验保留。关闭后原更多入口消失时定位重新开放，不恢复无效按钮。

第四批核对：服务列表的订单进入V07后此前显示通用演示编号，已修复为原记录编号；同时带入成对校验的开始/到期时间，复用原金额和角色，维修/其它费用按来源展示。只接受与业务相符的已知合成编号，不把URL参数当真实订单权限；不合法日期回退原示例。六个既有交易来源、四种屏宽、正常时间及畸形输入验证通过。

## 任务链路验收边界

| 阶段 | 本轮验证 | 明确边界 |
| --- | --- | --- |
| 发布 | V04四类表单、公开/私密核对、草稿/地址、成功/失败与未知查询验证通过 | 成功只记录当前页；没有服务端帖子编号，不向首页/服务列表注入新订单。 |
| 浏览与申请 | V01/V02公开详情进入V03；服务页查看本人申请或选人，类别、标题、金额、时间、角色与返回来源保持 | 首页是已有合成信息；不冒充从V04真实发布生成的帖子。 |
| 选人 | 候选草选、无效时间、确认失败、唯一选人、未知查询与保存/撤回验证通过 | V03明确标注不创建真实承接；不把单页选择自动写入独立V07模型。 |
| 交易 | 服务来源六项交易的原编号、标题、金额、时间、角色与返回验证；V07四类约定、异议、取消、费用和保护回归通过 | 服务页/V07仍是合成模型；到期与资金状态分开，不因页面跳转伪造已付款或已交付。 |
| 评价 | V18评分、一次修改、图文审核、回应、未知恢复、旧合法内容保留及V19公开展示验证通过 | 只使用现有合格来源，不从任意V07返回地址或参数生成评价资格；V17继续归档。 |

此处完成的是现有预览的分段与来源一致性验收，不是同一条真实记录从发布到评价的跨模块业务联调。真实帖子/交易关联、服务端资格、通知送达、付款和评价同步不在本次HTML优化中启用，也不记作验收通过。

第五批：已建立[当前状态索引](ui-ux-current-status-20261025.md)，将原审查正文明确归为历史语境，V21/V22改为已制作独立HTML的现状；主ASCII、PRD、结构化说明、开发计划与CONTEXT统一引用。返回按钮的辅助说明按订单列表、通知中心、需求详情实际目的地显示。

# V11 广告管理 UI、流程与命名修改建议（已确认文稿）

日期：2026-10-22（Asia/Shanghai）

文稿状态：用户于 2026-10-22 确认本稿整体方向，并明确要求本轮只更新文稿，不修改页面。本确认不授权修改 HTML、CSS、JavaScript 或启用任何真实广告、上传、付款、退款与投放能力。

审阅对象：[V11 广告投放本地预览](http://127.0.0.1:8765/v11.html)。本文以 V11 的商家端广告管理流程为主，只检查 V12、V13 与 V11 相连的入口名称和跳转价值，不替代对 V12 订单/退款、V13 数据报表的独立评审。

## 结论

V11 的视觉基调、移动端安全区、固定底部操作、隐私授权和“未知结果不冒充成功”都应保留。当前最需要解决的不是换一套视觉，而是让“现在是什么状态、用户下一步做什么、当前期和下一期是否相互影响”在每个页面都只有一种解释。

推荐采用“**状态驱动的广告管理首页 + 按任务进入子流程**”：首页同时容纳当前购买期和下一期准备记录；创建、修改、预览、审核进度分别使用与任务相符的标题；订单和投放数据仍通过明确入口进入 V12、V13。优先修正 3 个流程正确性问题：

1. 草稿保存状态与离开提示互相矛盾，且提示条会遮挡确认弹层。
2. “准备下一期”后，界面不再显示仍在投放的当前期，容易让商家误以为当前广告被替换或停止。
3. 审核未通过时，首页只写“待修改”，不直接显示原因，也没有“查看原因并修改”的完整恢复路径。

本文是已确认的改版文稿，不是页面实施授权。第 10 节中的 D1、D2、D3、D6 已按用户本轮答复记录为确认；D4、D5 仍缺少足以安全落地的业务事实，继续作为禁止猜测的实施前置条件。

## 3. 三种信息架构方案

### 方案 A：状态驱动的广告管理首页（推荐）

首页先回答“当前在投什么、下一步是什么”，再提供修改、下期准备、订单和数据入口。当前期与下一期是两张独立状态卡；只有用户进入某项任务后才打开编辑、预览或进度页。

优点：符合当前业务中“当前期继续投放、下一期可提前准备”的并行关系；小屏首屏能看懂状态；不会把管理、素材、订单、报表混成一页。缺点：需要把当前单记录渲染改成当前期/下一期两个明确区域。

### 方案 B：严格步骤式向导

按“选择位置 → 填素材 → 预览 → 审核与排期 → 付款 → 投放”显示一个完整步骤条。

优点：首次创建最易理解。缺点：投放开始后会同时出现修改、查看订单、查看数据、准备下期等非线性任务，步骤条会迅速失真；不适合作为长期管理首页。

### 方案 C：素材、订单、数据三标签

手机端直接提供“素材 / 订单 / 数据”三个标签，每个标签承载对应内容。

优点：信息分类稳定。缺点：用户仍需自己判断下一步；窄屏会增加导航占用；“退款”与“投放状态”跨标签，容易再次造成状态割裂。

**推荐 A。** V11 的核心不是多功能后台，而是让社区商家在小屏上完成一个明确的下一步。V12、V13 已经承担订单和数据详情，不需要在 V11 再复制一套标签后台。

## 4. 推荐页面结构

```text
┌────────────────────────────┐
│ ‹          广告管理      ··· ◎ │
├────────────────────────────┤
│ 当前投放                    │
│ [投放中] 青禾生活馆          │
│ 首页轮播 · 首位（默认显示）    │
│ 开始 10月12日 10:00          │
│ 结束 11月11日 10:00          │
│ [查看投放数据] [查看订单]      │
├────────────────────────────┤
│ 管理当前广告                  │
│ 修改当前素材                 › │
│ 预览正在投放的广告            › │
├────────────────────────────┤
│ 下一期                       │
│ 尚未准备                      │
│ 不自动续费，排期确认后再付款     │
│ [准备下期广告]                 │
├────────────────────────────┤
│ 投放与费用说明                › │
└────────────────────────────┘
```

如果下一期已经是草稿、审核中、审核未通过、待付款或待开始，第三块改为对应状态卡，不覆盖“当前投放”。如果没有当前投放，则首页只显示一张草稿/审核/待付款卡和一个明确主操作。

### 4.1 页面层级

1. **广告管理**：当前期、下一期、状态、唯一推荐动作和相关入口。
2. **创建广告**：首次或已结束后新建。
3. **修改广告素材**：修改投放中的当前版本；必须明确原版本继续展示。
4. **准备下期广告**：只创建下一期记录；必须始终显示“当前期不受影响”。
5. **广告预览**：标明正在预览“待提交版本”“待投放版本”或“当前生效版本”。
6. **审核进度**：显示当前节点、预计处理目标、退回原因及下一步。
7. **订单与退款 / 投放数据**：进入 V12、V13，不在 V11 重复详情。

## 5. 命名体系

建议使用“两层业务名 + 一层任务名”，避免“广告投放、我的广告、广告素材、经营推广”互相指同一层。

| 层级或场景 | 当前文案 | 推荐文案 | 理由 |
| --- | --- | --- | --- |
| 商家抽屉一级入口 | 经营推广（已确认） | **经营推广** | 保留已确认入口，涵盖未来但不提前展示未开放功能 |
| Banner 产品名 | 首页轮播位置 / Banner | **首页轮播广告** | 商家能理解展示位置；避免内部英文术语 |
| V11 首页标题 | 我的广告 / 广告投放 | **广告管理** | 页面同时承担状态、修改、下期准备和跨页入口，不只是“投放动作” |
| V12 入口 | 订单退款 | **订单与退款** | 页面不仅处理退款，还含付款、订单和结果核实 |
| V13 入口 | 投放效果 / 查看效果 | **投放数据 / 查看投放数据** | 当前只有曝光、点击、点击率；“效果”容易被理解为转化或收益 |
| 初次编辑页 | 广告素材 | **创建广告** | 说明用户正在完成什么任务 |
| 投放中编辑页 | 广告素材 | **修改广告素材** | 与创建、下期准备明确区分 |
| 下期编辑页 | 广告素材 | **准备下期广告** | 不让用户误以为正在改当前广告 |
| 草稿状态 | 待完善 | **草稿** | 当前示例内容已完整，“待完善”与事实不一致；草稿也不必然缺字段 |
| 退回状态 | 待修改 | **审核未通过** | 先说明发生了什么，再给“查看原因并修改” |
| 审核/排期完成 | 审核排期已确认 / 待付款 | **待付款**，副文案“审核通过，排期已确认” | 状态名直接对应商家的下一步 |
| 付款未知 | 付款待核实 | **付款结果核实中** | “待核实”没有说明由谁处理，容易让商家重复操作 |
| 退款未知 | 退款待核实 | **退款结果核实中** | 与付款状态保持一致 |
| 已结束后按钮 | 新建投放预览 | **新建广告** | 点击后实际进入编辑，不是直接进入预览 |
| 返回按钮 | 返回广告 | **返回广告管理** | 目的地明确 |
| 通用弹层次按钮 | 返回检查 | 按场景改为 **继续编辑 / 先不准备 / 暂不撤回 / 暂不终止** | “检查”并不适用于所有弹层 |
| 轮播位置 | 首图 / 次图 / 末图 | **首位（默认显示）/ 第二位 / 第三位** | “次图”容易被理解为详情副图，“末图”不够口语化 |

“首位/第二位/第三位”的最终叫法需在实施前确认；业务记录中的首/次/末价格映射保持不变，不能因改文案改变位置或价格。

## 6. 按优先级修改

### P0：先修流程正确性

| 问题证据 | 风险 | 修改建议 | 验收标准 |
| --- | --- | --- | --- |
| 点击“保存草稿”后出现“草稿已保存”，立即返回仍提示“尚未保存的修改将丢失” | 用户无法相信保存结果，可能重复操作或不敢离开 | 引入明确的“已保存快照 + 是否有未保存改动”状态；只有当前表单与最近保存快照不同时才拦截离开 | 保存后未再修改，返回不弹丢失提示；保存后再改任一字段，才弹“放弃未保存修改？” |
| 保存成功提示仍在显示时打开返回确认弹层，提示条覆盖弹层正文 | 用户看不全风险说明，弹层层级失真 | 打开模态弹层前关闭非持久提示；模态存在时不再显示 Snackbar/Toast | 任意提示与确认弹层不得重叠；弹层标题、正文、按钮在 320px 宽度仍完整可见 |
| 确认“准备下一期”后进入通用“广告素材”页，当前投放从界面消失 | 商家可能误以为当前广告已停止或被下一期替换 | 当前期和下一期使用独立卡片与独立版本标签；下期编辑页持续提示“当前广告继续投放，本操作不会替换或停止当前期” | 下期处于草稿/审核/待付款/待开始时，返回首页仍能同时看到当前期和下一期 |
| 审核未通过时首页只显示“待修改”，点击后直接进入编辑；具体原因只在另一进度画面中出现 | 不知道改什么，容易盲改和重复退回 | 状态改为“审核未通过”；首页展示一条可读原因摘要，主按钮为“查看原因并修改”；编辑页在对应素材区重复原因 | 商家不进入隐藏页面也能看到原因；原因能指向需修改的具体内容；修改后可重新预览并提交 |

### P1：统一状态、动作和信息层级

| 问题证据 | 修改建议 | 验收标准 |
| --- | --- | --- |
| 审核中页面使用绿色对勾图标，视觉上像“已完成” | 改为时钟/进度图标；已通过才使用对勾。步骤列表区分已完成、当前、未来，并给当前步骤 `aria-current="step"` | 不读正文也不会把审核中误认成审核通过 |
| 同一状态在演示控件写“审核排期已确认”，商家卡片写“待付款”；“待完善”又可能是完整草稿 | 演示控件可以保留后台组合状态，但商家界面只用面向行动的状态词；采用第 5 节状态表 | 相同含义在 V11、V12、V13 可被一致识别，不再出现两套商家状态名 |
| “预览当前广告”用于审核未通过、待付款、退款中等不同版本 | 按版本改为“预览待审广告”“预览待投放广告”“预览正在投放的广告”“查看已终止广告” | 用户在点击前知道将看到哪个版本 |
| “待开始”仍把“查看投放数据”作为主要入口，但此时没有实际投放数据 | 待开始时主操作改为“查看订单与排期”；数据入口在实际开始后出现 | 待开始状态不把用户送进无数据空页作为主要路径 |
| 投放中修改页只写“更新素材，审核通过后替换” | 标题改为“修改广告素材”，顶部增加“当前生效版本继续展示”；预览页标记“待提交修改”；提交成功后首页同时显示当前版本和待审修改 | 用户可区分当前生效内容与新稿，不会把保存草稿当成已经替换 |
| 位置选择是互斥选择，但当前控件以多个 `aria-pressed` 按钮呈现，在无障碍树中表现得像复选项 | 使用带 `legend` 的单选组，或确保控件语义为互斥单选；整张位置卡可点击 | 键盘与读屏都能知道“3 选 1”、当前选中项和每项价格 |
| 校验失败仅滚动到字段，焦点仍停在“预览广告”；底部还有不可点击的笼统提示 | 在表单可视顶部提供错误摘要，链接到字段；保留字段旁具体错误；聚焦错误摘要或首个错误字段，并设置 `aria-invalid` | 键盘、读屏和触屏用户一次提交后都能定位全部错误；已填内容不丢失 |
| 正式素材规格和文字长度尚未确认，当前只写“另行确认” | 原型可继续标注未定；真实上传和真实提交前必须先确认规格，并在选择文件前展示格式、大小、比例、字数限制 | 未确认规格时不得把原型控件升级为真实上传/提交；确认后校验规则、提示和测试一致 |

### P2：改善扫描效率与细节反馈

- 将“本期排期 10/12 10:00 — 11/11 10:00”拆成“开始时间 / 结束时间”两行；跨年时显示年份，并在页面说明统一使用北京时间。
- 将“本期费用不变”放到“修改当前素材”的辅助说明中，避免成为没有明确对象的右上角小字。
- “修改广告素材”“准备下期广告”改为有清晰按压态的整行操作，按下轻微缩放至约 `0.98`，松开恢复；同时保留键盘焦点样式和减少动态效果适配。
- “投放与费用说明”保留折叠，但与当前状态直接相关的规则就地显示，例如待付款显示保留截止时间，修改页显示“先审后换”，下期页显示“不自动续费、排期确认后再付款”。
- 预览页把“广告预览”角标改为版本标签，例如“待提交版本”“当前生效版本”；轮播圆点作为装饰时对读屏隐藏，旁边用文字说明“第 1 位，共 3 位”。
- 原型外层导航改为“广告管理 / 订单与退款 / 投放数据”；明确这只是评审导航，不复制进正式小程序顶部。
- Toast 只承载短反馈；需要用户决定或理解后果的内容继续使用弹层/结果页。打开弹层时清除已有 Toast，避免层级竞争。

## 7. 推荐流程

### 7.1 首次创建

```text
广告管理空态
  → 新建广告
  → 选择轮播位置
  → 填写素材与公开信息
  → 预览待提交版本
  → 提交审核
  → 审核中
      ↘ 审核未通过 → 查看原因并修改 → 重新提交
      ↘ 审核通过且排期确认 → 待付款
  → 付款结果已核实成功
  → 待开始
  → 投放中
  → 已结束
```

“素材审核”和“排期确认”是否拆成两个对商家可见节点，必须根据真实后台事实确认；如果后台只有一个组合结果，界面不得虚构两个独立进度。

### 7.2 投放中修改

```text
当前广告继续投放
  → 修改当前素材
  → 保存修改草稿（不改变当前版本）
  → 预览待提交修改
  → 提交修改审核
  → 当前版本继续投放 + 新稿审核中
      ↘ 未通过：显示原因，当前版本继续投放
      ↘ 通过：替换为新版本，不重算本期时长
```

首页至少要同时表达“当前生效版本”和“待审修改”两件事；不能只禁用修改按钮而不说明为什么。

### 7.3 准备下一期

```text
当前期投放中
  → 准备下期广告
  → 明确提示：不影响当前期、不自动续费、不保证原位置
  → 下期草稿 / 审核 / 待付款 / 待开始
  → 当前期卡片始终保留
```

下一期不应复用“新建当前广告”的标题，也不应在创建草稿时把当前期从管理首页隐藏。

## 8. 状态与主操作矩阵

| 商家可见状态 | 必须显示的信息 | 主操作 | 次操作 |
| --- | --- | --- | --- |
| 草稿 | 已保存时间或未保存状态、位置候选、缺失项 | 继续编辑 | 删除/放弃草稿（若未来提供，需单独确认） |
| 审核中 | 提交时间、24 连续小时内部处理目标、当前版本是否继续投放 | 查看审核进度 | 撤回申请/修改 |
| 审核未通过 | 原因摘要、受影响内容、当前版本是否继续投放 | 查看原因并修改 | 查看提交记录 |
| 待付款 | 已确认位置、排期、金额、位置保留截止时间 | 查看订单并付款 | 预览待投放广告 |
| 付款结果核实中 | 不要重复付款、查询状态 | 查询付款结果 | 返回广告管理 |
| 待开始 | 已付款、确认排期、不会提前起算 | 查看订单与排期 | 预览待投放广告 |
| 投放中 | 当前期、实际开始、结束、当前生效版本 | 查看投放数据 | 查看订单、修改素材、准备下期 |
| 已结束 | 实际投放区间、历史数据和订单 | 查看投放数据 | 新建广告 |
| 已终止 · 退款处理中 | 停止时间、预计退款、处理目标 | 查看退款进度 | 查看已终止广告 |
| 已终止 · 退款结果核实中 | 保持终止、不重复退款、查询结果 | 查询退款结果 | 查看订单 |
| 已终止 · 已退款 | 已核实金额、完成时间 | 查看订单 | 新建广告 |

矩阵中的“删除草稿”“提交记录”和完成时间如果没有真实能力，不应为了凑齐界面而创建；表中相应项可以省略。

## 9. 实施后的验证方案

### 9.1 流程与状态

- 覆盖第 8 节所有状态，并验证每个状态只有一个明确主操作。
- 验证草稿保存后无修改可安全离开；再次修改后才出现丢失确认；刷新后恢复最近已保存内容。
- 验证投放中修改待审时原版本继续展示；退回、撤回、通过后版本标记正确。
- 验证准备下一期后，当前期与下一期同时可见，且任何下期动作不改变当前期状态、时间和素材。
- 验证待开始不以无数据报表为主入口；投放开始后才展示“查看投放数据”。
- 验证审核未通过原因在首页、进度页、修改页之间一致，不出现三套文案。
- 验证付款/退款结果未知时不出现重复付款/退款入口，也不显示成功图标或成功文案。

### 9.2 布局与交互

- 在 320、375、414px 宽度检查无横向溢出；小程序胶囊、标题、返回键不冲突。
- 长经营名称、长标题、长错误原因、跨年日期和系统字体放大后仍可阅读。
- 内层长内容可滚动到底，固定底栏不遮挡最后一个字段、错误摘要或弹层按钮。
- 按钮、单选、复选和折叠项保持至少 44px 可操作高度；整行操作有按压反馈，减少动态效果设置下不缩放。
- Toast、底栏、键盘和确认弹层不能互相遮挡；弹层打开后焦点留在弹层，关闭后回到触发控件。

### 9.3 可访问性与内容

- 单选位置具有组名、选中状态和价格；错误字段具有 `aria-invalid`、错误说明关联和可见文字。
- 状态不只依赖颜色或图标；审核中不用完成对勾，未知不用成功色。
- 错误摘要可聚焦、可跳转到字段，字段原值不被清空。
- 同一动作在 V11、V12、V13 使用一致名称；“投放数据”不出现成交、收益或访客身份暗示。
- 正式素材规格、字段来源和审核节点未确认前，测试应确保页面继续标注为演示且不会发起真实上传、提交、付款或投放。

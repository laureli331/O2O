# V15 运营处理交互预览

日期：2026-10-22。用户确认“待办队列首页＋五类任务详情”，重要操作先核对影响并确认，全部使用合成数据，不执行真实管理、费用、退款或故障验收。页面：[V15](http://127.0.0.1:8765/v15.html)。

## 设计与范围

采用手机卡片队列、详情分段、固定底部主操作。保留浅米白、柔和绿、统一SVG与胶囊安全区。与大表格方案相比更便于手机处理；与把所有表单塞在首页相比，减少误操作并保留对象上下文。不新增人员分工、双人复核、批量封禁或AI自动处置。

| 分组 | 设计内容 |
| --- | --- |
| V15-A | 待办优先，内容巡查、举报申诉、费用、实收退款、故障分类筛选；卡片展示对象、阶段、提交和首次回应目标；未知操作可恢复查询。 |
| V15-B | 必要公开摘要、受限材料、原结论与申诉、首次回应与结论分离；整改、下架、限制、封禁及按当前对象状态解除；理由1—1000，适用期限1/3/7/30天或永久，影响确认和账号级操作历史。 |
| V15-C | 原锁定标准、原基数、双方新价、争议佣金和核验基数分开；旧材料重复不再暂停，新材料受理仅影响对应争议部分；请求补充、核验结论、补充通知成功后72小时；无争议期限不改。 |
| V15-D | 核实收款按最早到期可缴项分配，争议暂缓单列；同支付引用去重，多收待退和核准抵扣分开；退款待核对、待退回、处理中、已退回、失败和未知分开，未知先查。 |
| V15-E | 已核实故障的证据、影响功能与交易范围；恢复验收通过后保护取原有效到期和恢复＋24小时较晚者，同事件不刷新；原服务约定、支付事实和无关账单不变。 |

提供普通账号拒绝、未登录、空队列、加载失败重试、长队列、成功/失败/未知操作和旧版本冲突的合成检查。每次写操作均检查演示角色、对象和版本；这不能替代生产服务端鉴权。

## 参考及适配

- [Zendesk处理状态](https://support.zendesk.com/hc/en-us/articles/8263915942938-About-the-ticket-lifecycle-and-ticket-statuses)：区分待处理、等待资料与已作结论，适配为首次回应和结论两个独立事实，不照搬其自动关闭或分配人员机制。
- [Zendesk事件记录](https://support.zendesk.com/hc/en-us/articles/4408829602970-Viewing-all-events-for-ticket-updates)：借鉴对象更新历史；本项目只记共用管理账号、时间、对象、前后状态与理由。
- [GOV.UK核对信息](https://design-system.service.gov.uk/patterns/check-answers/)：提交前核对动作、范围和影响，返回修改保留已填值，安全返回为默认焦点。
- [Stripe退款状态](https://docs.stripe.com/refunds)：借鉴发起、处理中、成功与失败分离；实际采用项目EA03规则，不照搬Stripe通道、费用或到账承诺。

## 验证方案

先模型用例验证权限、状态动作资格、理由长度、版本冲突、未知防重复与恢复、首次回应不结案、争议部分暂停、原快照重算差额、通知成功后72小时、实收去重/最早到期分配/多收分离、退款不假成功、故障范围/较晚截止/重放不续期。

再浏览器检查五组流程、错误汇总与字段焦点、草稿及未保存离开、核对页和安全确认、成功/失败/未知、刷新恢复、权限不足、空/加载错误/长列表、320/375/414px标题胶囊不碰撞、长内容可滚到底、固定底栏无覆盖、44px触控、轻微按压与减少动态效果。最后执行全量测试、文档与交接检查，查看截图并提交Git。

## 边界

所有对象、材料引用、收退款及故障均为显式合成示例。无真实接口、附件上传、自动扣款、退款、发通知、解禁、恢复验收或自动结束。旧凭据不开放，证据仅显示必要脱敏摘要；外部V16/V20/V21尚无完整HTML时明确为规划入口，不伪造可执行页面。E03/E06及真实通道、服务端权限与版本并发仍需实际核实。本地演示在当前标签页临时保存30分钟，不与V14或服务页后台同步。

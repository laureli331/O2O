## 本轮范围与验证方案

保留 V15-A～E、网页三栏承载及原有业务动作。先验证每个合成事项对应自己的正文和材料、原句与举报描述对应、申诉不覆盖原结论、缺少原文不允许直接作内容结论；再验证浏览器八个事项、图片放大及焦点返回、五种宽度、长内容滚动与原有处置、版本、未知结果、资金和故障流程。最后运行全量测试、文档校验并提交 Git。

不读取真实聊天或私密附件，不增加真实数据接口、账号处罚类型、违规规则、自动结论或实际资金操作。

## 参考与适配

[Reddit 官方 Moderation Queue](https://support.reddithelp.com/hc/en-us/articles/15484440494356-Moderation-Queue) 说明举报理由可以放在内容附近，并能在上下文面板查看原文和回复。借鉴的是“先看到内容和原因，再判断”的信息顺序，不照搬其批量处置、自动审核或处罚机制，也不声称体验过其内部后台。

本项目仍使用绿白视觉、原网页侧栏和固定底部动作；详情顺序为：

1. 简短事项标题、状态和实际目标提醒。
2. 原标题、完整原文与全部合成图片，图片可放大。
3. 举报描述、申诉描述或巡查线索；明确标记待核实，引用具体原句。
4. 本次需要判断什么及对应材料；申诉保留原下架理由与补充授权说明。
5. 处理操作与所属账号核对。
6. 编号、版本、提交/回应时间、处理段和日志折叠。

新增正文均为本轮明确编写的合成场景，不是对历史真实举报的还原。图片使用项目现有插画并注明非现场或凭据。原文与材料按事项编号、分组、事项标题绑定，未知事项或对象变化不借用其它事项的材料。每次读取返回独立副本，不修改业务状态。

缺少原内容时显示“原内容尚未加载”，网页预览阻止直接下架、限制或保存内容结论等操作，仍可回应或请求补充。这是预览层的可用性保护，不代表真实服务端已完成材料鉴权或验证；原业务模型及实际权限能力未改。

# 第二版路线与条件提醒记录

版本：1.0。记录日期：2026-10-08（Asia/Shanghai）。

依据：[PRD v1.5](prd.md)、[功能确认记录](ai-feature-decisions.md)、[开发计划](development-plan.md)、[结构化设计](structured-design.md)及[实际进度](development-decisions.json)。本文件确认版本归属与提醒条件，不替代第二版详细设计或启用证据。

## 1. 本轮验证方案

核对VP01—VP05及商家/客户角色、第一版范围不扩展、收费细节未确认、收款与分佣更正、提醒触发/故障重置/证据不足不触发。用内存错误副本验证错误版本、遗漏功能、捏造收费、遗漏稳定记录、把今天当起点及故障不重置均被拒绝。运行相关文档回归、检查链接与差异后创建Git提交。提醒另外核对应用实际配置，不把文档记录当作自动化创建成功。

## 2. 已确认的第二版范围

用户原话：“那这部分放到第二版吧. 在第一版成功跑通及稳定两周后, 你记得提醒我做第二版”。

| 编号 | 目标 | 本次确认的边界 | 详细设计前待确认 |
| --- | --- | --- | --- |
| VP01 | 文字与图片共同整理 | 保留原跑腿/二手AI范围；不读旧帖子、地址簿或私密凭据 | 图片数量/格式、检测、文字图像冲突、费用/时延与评测 |
| VP02 | 有出处的平台规则问答 | 使用可追溯的平台规则来源；无依据不编造答案 | 知识版本、更新、引用、冲突、拒答和权限 |
| VP03 | AI运营处理助手 | 事实与建议分开，运营确认执行动作 | 必要输入、权限/记录、误判评测，不直接裁决/退款/封禁 |
| VP04 | 商家发帖广场 | 商家发主帖；客户评论、收藏、微信分享；此限制只用于广场主帖 | 商家身份与代表授权、发帖/评论类目和权限、内容字段、审核、反刷屏、举报申诉及数据处理 |
| VP05 | 商家营销服务及付费宣传探索 | 图片优化、菜单/海报/宣传内容制作、可选付费展示；不增加居民交易分佣 | 基础展示是否免费、入驻费/推流费/服务费、具体权益/价格/交付数量/修改次数/退款、支付通道与真实需求验证 |

以上为范围确认；免费基础展示及“制作优先”的收费次序仍是此前建议，不写成用户已批准的商业合同。商家角色不是第三方交易商户资格或支付分账资格，不能以宣传账号替代真实业务准入。

用户已更正：“说错了, 不是收款, 是分佣”。按用户反馈，受限的是第三方交易入驻与分佣；未取得具体后台原文/项目适用证据，不写成所有收款受限，也不保证商家发帖或服务收费已获准。平台自己的营销服务收费与居民交易资金分别核实。

第一版M01—M12、R01—R08、48项任务、56项验收、21个页面组和18组字段继续执行原合同。VP04/VP05没有混入第一版；居民原维修、跑腿、二手发布不因商家广场主帖限制而取消。面向全部居民的通用主帖广场没有因此获批。新增广场评论也不自动产生原业务实际经历或评分资格。

## 3. 提醒触发标准（用户已确认）

用户选择：“完整上线验收通过，且有连续14天稳定记录；出现阻断核心流程或严重安全／资金问题后，从修复验收通过时重新计时”。

| 项目 | 执行要求 |
| --- | --- |
| 成功跑通 | 第一版完整上线验收实际通过，有正式运行版本、验收结果与上线依据；文档测试、演示、模拟或部分流程通过不能替代 |
| 观察起点 | 记录完整上线验收通过后的实际观察开始时间与来源；时区Asia/Shanghai，不从本次讨论/提醒创建日或代码提交日起算 |
| 两周 | 连续14天的完整稳定观察区间，覆盖该区间的真实逐日运行/检查记录；时间经过本身不证明稳定 |
| 故障重置 | 出现阻断核心流程或严重安全／资金问题后，停止沿用旧起点；问题修复并验收通过后记录新起点和依据，再连续观察14天 |
| 证据缺失 | 未有验收/起点/连续稳定记录或未解决故障时不触发；没有故障报告、没有消息也不能证明稳定 |
| 达标动作 | 只提醒一次开始第二版规划，列出VP01—VP05；同一第一版稳定周期不重复提醒，不自动开发/收费/上线 |

# V06 商家主页与订阅内容流实施计划

日期：2026-10-20
依据：[已确认规格](../specs/2026-10-20-merchant-profile-subscription-design.md)，规格提交 `4733cf1`。

## 1. 交付目标

只调整 V06 / V23 离线预览，把已确认的商家主页和订阅内容流落实为可交互、可自动验证的合成原型：

- 发现页顶部增加 `订阅 / 发现` 主入口，底部“发现”每次默认进入顶部“发现”。
- “订阅”只展示当前用户已订阅商家的合规公开帖子；游客看到“登录后查看订阅内容”。
- 商家公开资料页改为用户手绘稿确认的商家主页，包含头像、名称、`帖子 / 订阅 / 收藏`、一句话简介、详细信息折叠区、订阅按钮和作品流。
- 作品筛选为 `最新 / 优惠 / 上新 / 活动` 单选下拉，结果按审核通过后的发布时间倒序。
- 订阅、取消订阅、失败回滚和“不再继续订阅？”确认框均在离线状态模型中可重复演示。

## 2. 边界、风险与回退

- 不修改 V01—V05，不修改小程序源码，不创建生产接口或数据库字段。
- 不连接真实登录、账号、订阅、收藏、审核、通知或联系方式服务；所有数据继续使用明确标注的合成数据。
- 联系方式仅在合成商家记录带有明确授权公开状态时显示；电话和微信直接完整展示，不用未授权数据替代。
- 不增加评论、点赞、私信、热榜、推荐算法或订阅通知。
- 不暂存或提交 `redbook` 中用户已有的删除记录。
- 所有项目文件使用 `apply_patch` 修改；每个阶段先写失败测试，再实现并验证通过，不提交已知失败状态。
- 每个逻辑阶段独立提交；需要回退时对对应提交创建反向提交，不使用 `git reset --hard`，也不覆盖用户工作区。

## 3. 阶段一：订阅模型与发现页双入口

### 3.1 先写失败测试

修改：

- `tests/v06-preview.test.cjs`
- `scripts/verify-v06-preview.cjs`

模型与静态合同：

- 增加合成用户登录状态、当前有效订阅关系和商家公开资料，不用浏览器存储制造跨会话状态。
- `subscriptionFeed` 只返回已订阅商家的 `approved && displayable` 帖子，并按 `approvedAt` 倒序；删除、下架或不可展示内容不能出现。
- 登录用户无订阅时显示真实空状态与“去发现看看”；已订阅商家无合规帖子时不填充其它商家内容。
- 游客进入订阅页显示“登录后查看订阅内容”和登录按钮，发现页公开内容仍可浏览。
- 发现顶部主入口顺序严格为 `订阅 / 发现`；顶部“发现”内部继续使用 `最新 / 优惠 / 上新 / 活动`。
- 重新点击底部“发现”时强制回到顶部“发现”和内部“最新”；从帖子详情或商家主页返回时恢复原来的顶部入口及筛选状态。
- 订阅内容流不产生站内通知或微信提醒。

```powershell

```

## 4. 阶段二：商家主页、公开统计与作品筛选

### 4.1 先写失败测试

继续修改：

- `tests/v06-preview.test.cjs`
- `scripts/verify-v06-preview.cjs`

测试合同：

- 商家主页按顺序包含 SVG `<` 返回、头像与名称、`帖子 / 订阅 / 收藏`、一句话简介、“查看详细信息”、全宽订阅按钮以及作品流。
- “帖子”只统计当前合规公开帖子；“订阅”只统计有效订阅关系；“收藏”只汇总当前合规公开帖子的有效收藏。
- 帖子被删除、下架或改为不可展示时，同时退出发现、订阅、商家作品流和公开统计。
- “查看详细信息”在当前位置展开并变为“收起详细信息”，箭头旋转，作品区自然下移，不跳转页面或打开底部弹层。
- 展开区按已填写字段展示服务项目、服务方式、服务区域、营业时间和联系方式；服务方式只显示商家实际选择的 `上门 / 到店 / 远程 / 配送`。
- 空字段隐藏；电话和微信只在商家明确授权公开时完整显示，对游客也不打码。
- 作品筛选入口默认“最新”，下拉为 `最新 / 优惠 / 上新 / 活动` 单选；选择后关闭菜单、更新入口文字并按时间倒序展示。

## 5. 阶段三：订阅与取消订阅交互

### 5.1 先写失败测试

继续修改：

- `tests/v06-preview.test.cjs`
- `scripts/verify-v06-preview.cjs`

覆盖：

- 游客点击“订阅”进入合成登录引导，不提前建立订阅关系。
- 登录用户订阅成功后按钮改为“已订阅”、订阅数加一、该商家合规帖子进入订阅流。
- 订阅失败时按钮、订阅数和订阅流全部回滚，并显示重试提示。
- 点击“已订阅”打开确认框，文案严格为“不再继续订阅？”以及“继续订阅 / 取消订阅”。
- “继续订阅”、关闭按钮、遮罩关闭和 Escape 键关闭均保持订阅状态。
- “取消订阅”成功后更新按钮、计数和订阅流；取消失败时维持“已订阅”及原计数和原列表。
- 取消订阅不删除用户此前收藏的帖子。
- 确认框有焦点管理、键盘关闭和至少 44×44 像素的操作目标，不被固定底栏遮挡。

### 5.2 实现状态变更与失败回滚

修改：

- `previews/v06.html`
- `docs/v06-html-preview.md`

实现：

- 在 `V06Model` 中增加纯函数式订阅变更与失败回滚合同，页面只根据返回结果更新合成状态。
- 增加订阅按钮的进行中禁用状态，避免重复点击产生重复计数。
- 增加取消订阅确认框和焦点恢复；成功与失败使用现有轻提示，不产生通知中心记录。
- 在页面测试入口中保留可控的订阅失败和取消失败开关，仅供浏览器验证使用，不在正常界面显示测试控件。

- 底部“发现”默认进入顶部“发现”；订阅、详情和商家主页之间返回后恢复来源状态。
- 游客订阅页、登录引导、无订阅、无合规帖子和加载失败保留旧内容状态。

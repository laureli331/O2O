# V17 / V18 / V19 独立 HTML 设计与验证

日期：2026-10-23。用户明确要求三个独立网址；V17 范围提问后，用户选择“仅查看合法历史记录，不恢复新发起”。V18/V19 沿用已确认 PRD 第10节及既有 ASCII，不引入新的评分或商业规则。

## 页面分工

- `v17.html`：合法历史列表、历史详情、结果及既有资格。拒绝、撤回、超时、无法核实、历史等待及已确认/已核实分别呈现。页面只读，不恢复人员目录，也不提供新发起、确认、撤回或重提。既有合法资格且仍在首次窗口内，明确点击进入 V18；只记录本次评价，不创建订单或恢复联系。
- `v18.html`：待评价、我评价的、收到的三栏；从本人记录进入评分、一次修改或回应。三维整数星无预选；数值可单独提交，文字/图片独立审核，成功修改前说明一次机会及截止。明确清空图文成功后停止旧公开内容，数值保留。未知请求先查询，刷新可恢复，失败回到已填写评分和文字。
- `v19.html`：公开对象、业务、角色、总体/三维均分、维度星数、20条分页、评价详情。按首次评分时间倒序，不因修改或回应置顶。只公开已审核图文和唯一回应；修改待审或拒绝时标注此前合法内容。本人符合条件时链接 V18 回应；举报转 V14 并保留当前公开评价编号。

三个入口各自有 HTML 与应用脚本；仅共享视觉样式、规则模型及同标签页临时合成状态，不使用一个网址切换版本、不嵌套 iframe。V05“我评价的”接入 V18 本人记录。未把旧 V03/V07 的独立合成对象强行映射到本次新示例，真实接入必须依据同一交易/当事人事实。

## 参考与项目适配

参考 Airbnb 官方[评分展示说明](https://www.airbnb.com/resources/hosting-homes/a/why-reviews-matter-41)中总体/分项概览置于列表上方的方式，以及[从本人评价记录进入编辑](https://www.airbnb.com/help/article/367)的路径。这些是公开资料参考，未声称体验其最新版界面。本项目不复制 Airbnb 的时间窗、发布规则或总体评分算法：仍是首次7天、一次修改7天、三维原始分最后舍入、图文及回应先审后公开。

手机上采用现有绿白视觉、胶囊安全区、固定主要按钮、44px左右的触控热区；星级使用可聚焦的原生单选组，按钮和星标提供轻微按压反馈，减少动画设置下关闭动画。公开评价不额外收集头像，只显示打码昵称。空态居中，历史/本人/公开记录使用内容卡片。

## 数据及状态边界

共用 `reviews-model.js` 保留独立来源/方向、首次提交、一次修改计数、数值版本、修改前历史、当前待审内容与此前公开内容。公开投影不输出来源、原稿、证据、未审回应、电话或证件字段。三维评分和公开内容分别计算；同方向重复请求不重复计分或消耗次数。

V14 仅扩展“公开评价举报”的最小对象上下文（类型、评价编号、业务、角色），待确认及成功回执仍指向该评价，丢弃多余私密字段。不创建绕过原结论的申诉入口。

所有对象和图片均为合成示例。固定合成时钟为北京时间2026-10-23 10:00；本标签页会话临时保存30分钟。用户本机选择的图片仅当前页面预览，不上传；跨页/刷新只留类型、大小和示意占位，不保存原图或文件名。选择演示场景会切换整组合成记录，未提交输入先提示，不影响真实资料。

图文通过/拒绝/异常/超时和回应状态由外层合成场景演示；本次未实现 V20 审核后台或迟到审核回调接口，不允许用户自行批准新提交内容。真实身份、资格、审核、服务端并发、通知及 QG01/E03 接入均未验收，不启用真实公开评价。

## 验证方案

1. 模型：资格7日精确边界、取消/异议/自评/重复来源/访客；三维无默认及合法值；文字和图片限制；修改期限/一次机会/版本历史；明确清空；回应权限、拒绝重提和公开后只读；失败、未知恢复、幂等与旧版本拒绝。
2. 公开数据：原始三维 RS 样例3.5／4.5／3.5／2.5、星数总和、无记录不显示0或5；八组隔离，首次提交排序、20条分页；合法旧图文保留，不公开新原稿或私密字段。
3. 浏览器：三个独立网址、历史资格→评分、V05→本人记录、V19→回应及正确对象举报；星级选择、校验焦点、离开确认、图片添加/删除/拒绝非法类型、一次修改确认、清空图文、未知刷新和失败保留输入。
4. 设备：320/375/414px、无横向溢出、长表单滚动到底和固定操作可达；键盘/焦点、减少动画、空态、访客、审核拒绝/超时及过期修改。
5. 回归：V14 原有举报/申诉/补充、V05 原有入口；全量 Node、项目文档校验、UI交接资源及差异检查；完成后创建对应 Git 提交。

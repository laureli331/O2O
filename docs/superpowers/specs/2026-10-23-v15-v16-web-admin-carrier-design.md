# V15/V16 管理端承载方式确认设计

日期：2026-10-23  
状态：D1—D5 已获用户确认（2026-10-23），设计同步完成；页面迁移尚未实施
范围：V15 运营处理、V16 运营配置/公示/操作记录的承载方式、页面分工与迁移边界

## 1. 文档性质

用户在审阅本文及五项决策摘要后回复“没错”，确认 D1—D5 全部采用推荐项。本次据此更新 DP04、DP12、PRD、V05 入口说明及 V15/V16 设计口径，覆盖旧“小程序内完整承载”决策。文中方案比较保留为选择依据，推荐项现为已确认设计。

本次不修改现有 V15 HTML、CSS、JavaScript、数据模型、接口或生产环境；文档确认不等于网页迁移、真实登录、权限或托管已经实现。

本次修改只讨论“管理功能放在哪里、如何分工”，不改变以下已确认业务规则：

- V15 的队列、举报、申诉、内容处置、账号能力限制、费用核验、实收退款核对和故障保护规则。
- V16 的真实地区、业务分类、服务配置、佣金版本、公示、生效时间和操作记录范围。
- 成功、失败和结果未知必须分开；未知结果先查询，不重复执行。
- 旧交易继续使用确认时锁定的配置快照，新配置不倒改旧交易。
- 当前共用管理账号及账号级日志仍是现状；本稿不擅自改成独立运营账号。

## 2. 结论摘要

微信公众平台没有直接提供能够替代 V15/V16 的成品业务后台。微信和腾讯云提供的是平台管理能力、内容安全接口、客服、数据分析、数据库、云函数、托管、通用云后台和低代码工具；它们不知道本项目的业务队列、账号处置、佣金争议、故障保护和配置版本规则。

推荐采用以下承载方式：

> **V15/V16 使用网页端作为完整管理工作台；小程序只保留轻量值班入口；微信公众平台和 CloudBase 控制台继续只承担平台及云资源管理。**

该方案不是新增一套后端。网页端和小程序端应共用同一套 CloudBase 数据、云函数、权限校验、事务状态和应用级操作日志。

## 4. 三种方案比较

| 方案 | 优点 | 主要问题 | 结论 |
|---|---|---|---|
| A：全部继续放在小程序 | 延续现有 DP04；进入快；无需新增网页入口 | 屏幕窄，长队列、证据对照、配置表格和版本差异难以阅读；高风险操作容易被压缩成多层页面 | 不推荐作为完整管理端 |
| B：V15/V16 全部改为网页端 | 桌面空间充足；适合筛选、搜索、多栏对照、键盘操作和长记录 | 手机临时值班不方便；需要单独确认登录入口和实际托管条件 | 可行，但失去移动端快速查看 |
| C：网页主后台＋小程序轻量入口 | 完整操作在桌面完成，同时保留移动提醒和低风险响应；共用同一后端 | 需要明确两端功能边界，并验证状态同步 | **推荐** |

## 5. 推荐的信息架构

### 5.1 微信及云平台后台

保留官方后台负责其原生职责：

- 小程序成员、版本、审核、发布和平台配置。
- 官方数据分析、客服、内容安全接口配置。
- CloudBase 环境、数据库、云函数、存储、日志和告警。
- 若以后真实开通支付能力，官方支付后台或接口只作为支付、退款等渠道事实的来源；不能直接替代本项目费用账本、争议核验和状态判断。

CloudBase 数据库控制台不作为日常运营界面。运营人员不得通过直接修改数据库绕过业务校验、核对步骤和应用级操作记录。

### 5.2 网页主后台

网页端承担完整 V15/V16：

```text
+--------------------------------------------------------------------------------+
| 湘邻湘友管理台   [全局搜索]                         管理账号  [退出]             |
+----------------+--------------------------+------------------------------------+
| 运营待办       | 待你处理 / 等待对方 /   | 当前事项                           |
| 内容处置       | 最近完成                 | 对象、材料、原结论与处理历史       |
| 费用核验       |                          |                                    |
| 实收与退款     | [类型] [状态] [时间]     | 当前允许的操作                     |
| 故障保护       | 事项列表                 | [填写说明] [核对操作]              |
|                |                          |                                    |
| 经营配置       |                          | 操作后结果、回执与下一步           |
| 配置版本       |                          |                                    |
| 操作记录       |                          |                                    |
+----------------+--------------------------+------------------------------------+
```

布局原则：

- 左栏保持模块位置稳定，避免在长流程中失去方向。
- 中栏用于队列、筛选、排序和事项切换；已出结论事项不混回“待你处理”。
- 右栏用于对象上下文、证据、原结论、表单、核对和结果，减少在多个窄屏页面之间来回跳转。
- 主要操作每个区域只突出一个；危险操作使用明确动词，不用含糊的“确定”“处理”。
- 表单、表格、弹窗和抽屉支持键盘操作、清晰焦点、即时反馈和可理解错误信息。
- 小交互保持克制：按钮按下轻微缩放或下沉，处理中立即禁用重复提交，成功、失败和待确认使用不同反馈。

### 5.3 小程序轻量值班入口

建议保留：

- 待办数量和异常提醒。
- 三段队列摘要及只读事项详情。
- 查看材料摘要、原事项、首次回应和当前处理进度。
- 在真实权限与通知链路验证后，可开放“发送首次回应”和“请求补充材料”两类时效性操作；仍需核对页和明确结果。

建议不在小程序执行：

- 最终维持、整改、下架等内容结论。
- 账号能力限制、封禁和解除。
- 实收重新分配、多收退款发起和费用更正。
- 故障恢复验收和保护截止变更。
- 地区、分类、服务、佣金、公示及生效时间配置。

若用户希望管理功能全部退出小程序，可以进一步采用方案 B；本稿推荐保留轻量入口，但不把它当作完整后台。

## 6. V15 网页端调整

| 当前模块 | 网页端建议 | 解决的问题 |
|---|---|---|
| V15-A 运营待办 | 三栏结构；中栏固定显示三段队列、筛选和可解释排序；右栏打开详情 | 避免列表和详情反复进退，保留筛选上下文 |
| V15-B 内容处置 | 同屏展示当前内容、必要材料、原结论、账号目标和操作历史；表单与核对页保持上下文 | 防止看错对象、漏看原结论或把内容动作与账号动作混为一项 |
| V15-C 费用核验 | 争议部分、无争议部分、旧材料、新材料和截止时间分栏呈现 | 防止错误暂停整张账单或刷新不应刷新的期限 |
| V15-D 实收与退款 | 应缴、实收、已分配、待分配、多收、退款渠道状态分开 | 防止“已发起”被显示成“已退款”，支持逐笔核对 |
| V15-E 故障保护 | 故障证据、受影响交易、保护截止、恢复验收和重复事件并列核对 | 防止无证据恢复、重复事件续期或覆盖原到期时间 |

网页化只改变信息密度和操作路径，不改变 V15 已确认状态机。所有写操作继续经过“填写 → 核对 → 执行中/查询 → 明确结果”，不能因为桌面空间更大而跳过核对。

## 7. V16 网页端调整

V16 只在网页主后台提供完整编辑能力：

### 7.1 真实地区、分类与服务配置

- 使用可搜索表格展示名称、类型、状态、来源、版本和最后修改时间。
- 新增与编辑分开；没有真实依据的地区、人员或服务不得预填。
- 批量导入不作为默认第一版能力，避免未经核对一次写入大量配置。

### 7.2 佣金配置及生效核对

- 同屏展示“当前版本”和“拟发布版本”。
- 变更项逐字段高亮，明确原值、新值、原因、生效时间和必要公示。
- 保存前再次说明只影响生效后新确认交易，旧交易继续使用原快照。
- “保存草稿”“发布配置版本”“实际生效”使用不同状态和动作名称，不能合并成一个含糊按钮。

### 7.3 操作记录与版本详情

- 支持按模块、对象、动作、结果和时间筛选。
- 每条记录展示管理账号、请求编号、时间、对象、动作、理由、执行结果和变更前后快照。
- CloudBase/微搭自身审计日志只能补充登录、权限和通用数据操作证据；V16 仍需保留可供运营理解的应用级业务记录。
- 若继续共用管理账号，页面必须明确提示“记录归属管理账号，不能识别具体自然人操作者”，不能用网页端掩盖该限制。

## 8. 共用后端与状态边界

```text
微信官方能力 ── 内容安全/客服/平台数据/渠道结果
                         │
                         ▼
小程序轻量入口 ─┐   CloudBase 云函数与业务规则   ┌─ 网页主后台
                ├── 权限、版本、幂等、状态查询 ─┤
                └── 数据库、文件、应用级日志 ──┘
```

- 小程序和网页端不得各自维护一套事项状态。
- 所有写操作由服务端重新校验管理权限、对象版本、允许动作和当前状态。
- 内容安全结果只作为风险线索，不自动生成最终违规结论。
- 渠道退款或支付结果只作为渠道事实；业务侧仍需记录发起、处理中、成功、失败和未知。
- 网页端遇到旧版本冲突时，不覆盖新状态；重新加载差异后再决定下一步。
- 页面关闭或网络中断后，进行中的操作通过请求编号恢复查询，不依靠浏览器内存判断成功。

## 9. 登录、权限与审计决策

网页化不等于自动获得安全的运营身份体系。实施前必须从实际可用能力中选择并验证登录方案，不能猜测接口或套餐：

- 保持现有共用管理账号：改动较小，但仍不能区分本人和伙伴的实际操作。
- 改成独立运营账号：审计更清楚，但会覆盖当前已确认的共用账号规则，需要另行讨论权限、交接和账号找回。

无论选哪种，前端隐藏按钮都不能替代服务端权限校验。高风险动作需要明确对象、影响范围、理由、变更摘要和最终确认；登录失效、无权限或版本冲突时不得产生部分写入。

## 10. 迁移顺序与回退

建议采用可回退的渐进迁移：

1. 核实当前 CloudBase/微搭环境、套餐、Web 托管、身份认证、内部用户和审计能力，只形成事实记录，不购买或开通未确认服务。
2. 先建立网页端只读工作台，读取 V15 队列、V16 当前配置和操作记录，对照现有小程序预览检查字段与状态一致。
3. 开放 V16 单项配置草稿和版本核对；验证并发冲突、旧交易快照和操作记录后，才允许发布配置版本。
4. 按内容处置、费用核验、实收退款、故障保护的顺序逐类迁移 V15 写操作；每类单独验收。
5. 网页端完整验收后，再缩减小程序中的高风险操作入口。

回退原则：

- 迁移期间不删除现有 V15 预览或业务定义。
- 每类写操作可独立关闭网页入口；关闭后不删除已生成记录。
- 已提交但结果未知的操作继续按原请求编号查询，不能因回退而重复执行。
- 回退承载入口不回滚已经成功的业务事实、支付事实或配置版本。

- 桌面端：建议以 1366×768 和 1440×900 作为首轮布局检查样例，1024px 宽度仍能完成关键操作；最终设备范围以真实运营设备确认结果为准。

- 高风险操作：填写、核对、处理中、成功、失败、未知、恢复查询、重复提交和旧版本冲突。

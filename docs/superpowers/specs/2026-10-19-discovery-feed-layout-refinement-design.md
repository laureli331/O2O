# V06 内容流、发帖、详情与商家资料布局细化设计

日期：2026-10-19  
状态：用户已确认设计，等待书面规格审阅  
适用范围：V06 / V23 离线预览中的发现页、商家发帖页、帖子详情页和商家公开资料页

## 1. 目标

V06 的发现、商家发帖、帖子详情和商家公开资料页参考小红书 App 的内容优先信息层级，但继续使用项目已有的绿色、米白色视觉体系，不复制小红书的品牌色、图标、文案、社交指标或推荐机制。页面应突出图片与正文，减少后台表单感和重复审核标签。

本轮只修改 V06 离线预览、设计记录和验证，不修改 V01—V05，不修改小程序源码，不连接真实发布、审核、定位、通知或商业服务。

## 2. 已确认决定

1. 删除顶部引导卡“附近 · 商家新鲜事 / 慢慢逛，看看身边”。
2. 删除“最新发布 / 演示加载失败”行；加载失败仍由预览状态入口和失败状态验证，不在正常发现页占据固定位置。
3. 标题栏下方增加横向主题栏：`最新 / 优惠 / 上新 / 活动`。
4. “最新”包含全部审核通过且当前可展示的商家主帖，并继续按审核通过后的发布时间倒序。
5. 商家发布主帖时，最多选择一个主题，也可以不选：
   - 选择“优惠”时，同时进入“最新”和“优惠”；
   - 选择“上新”时，同时进入“最新”和“上新”；
   - 选择“活动”时，同时进入“最新”和“活动”；
   - 普通内容不选主题时，只进入“最新”。
6. 不得由系统根据正文自动猜测主题，也不得为增加曝光同时给一篇主帖分配多个主题。
7. 不使用“推荐”，因为第一版不新增推荐算法；不使用“附近”，因为当前没有确认距离或区域范围。
8. 公开卡片、公开详情和商家公开资料页不显示“已审核”或“资料已审核”。审核未通过或当前不可展示的商家内容本来就不会进入公开页面，重复标签没有额外信息价值。
9. 审核状态继续保留在商家自己的发布、待审核、驳回、替换成功和风险下架流程中。

## 3. 页面结构

正常发现页从上到下为：

1. 原有标题栏“发现”；
2. 单行横向主题栏；
3. 双列商家图文瀑布流；
4. 原有底部导航“首页 / 发现 / 发布 / 服务 / 我的”。

主题栏与内容流之间保持紧凑间距，不插入介绍卡、固定说明、排序标题或演示按钮。主题数量在当前四项范围内完整显示；窄屏不得出现横向页面溢出。

## 4. 主题栏交互

- 默认选中“最新”。
- 选中项使用项目绿色文字与细下划线；未选中项使用中性色。
- 每个主题保持至少 44×44 像素触控区域。
- 点击时提供轻微缩放，切换后使用短时透明度或位移动画；开启减少动画时关闭过渡。
- 切换主题只改变当前发现内容集合，不改变底部导航、用户身份或详情状态。
- 某主题没有内容时显示主题专属空状态，并提供“查看最新”按钮恢复到“最新”。不得用虚构帖子填充。

## 5. 发现卡片

发现卡片仅保留封面、最多两行标题、商家头像和商家名称。删除卡片上的“已审核”标签。

## 6. 商家发帖页

发帖页使用图片优先的纵向编辑结构：图片选择与排序置顶，下面依次排列标题、正文、非必填内容主题和隐私说明。图片仍为 1—9 张，首图仍是封面，标题与正文字数限制不变。

底部固定“保存草稿 / 预览”操作区，避免长正文将主要操作推离视线。按钮保持至少 44 像素触控高度和轻微按压缩放；输入错误仍在对应字段附近说明，不清空用户已填内容。

内容主题使用单选控件：不选择、优惠、上新、活动。该选择只是本地合成原型数据，不创建生产接口或数据库字段。

## 7. 帖子详情页

详情页从上到下为：顶部沉浸式大图和页码、返回按钮、标题、发布时间、正文、商家简洁入口与隐私说明。图片切换继续使用现有本地图库数据。

底部固定“收藏 / 微信分享”操作区；收藏失败继续回滚到原状态，分享内容继续只包含获准公开字段。不增加评论、点赞、关注、视频、相关推荐或社交统计。详情中的“资料已审核”文字删除。

## 8. 商家公开资料页

资料页头部只展示头像、商家名称、服务区域和商家已明确授权公开的联系方式；不显示审核标签，不显示粉丝数、获赞数、关注按钮或其它虚构指标。

资料头部下方展示该商家自己的公开主帖双列列表，只包含审核通过且当前可展示的帖子。点击卡片进入同一套帖子详情；没有可展示主帖时使用真实空状态，不用其它商家的内容填充。

## 9. 发布侧主题规则

提交审核后的主题随主帖内容一起接受审核。此轮不增加优惠有效期、活动截止时间或自动失效规则；是否增加这些业务字段必须另行设计并由用户确认。现有 `displayable` 状态仍决定内容是否出现在公开页。

## 10. 保持不变

- 发现仍只展示审核通过且当前可展示的商家图文主帖。
- 居民维修、跑腿、闲置和其它内容仍在首页。
- 第一版不增加评论、点赞、关注、视频、热榜、内容加热或个性化推荐。
- 详情、收藏失败回滚、微信分享字段限制、游客浏览、加载失败保留旧内容、通知二级入口和底栏顺序保持不变。
- 空状态、失败状态和减少动画支持继续保留。

## 11. 验证方案

1. 静态测试确认正常发现页不再包含顶部引导卡、固定“最新发布”行或公开审核标签。
2. 模型测试确认默认“最新”包含全部合规帖子，三个主题只返回其明确标记的帖子，未选择主题的普通内容只出现在“最新”。
3. 浏览器测试逐项点击“最新 / 优惠 / 上新 / 活动”，确认列表与空状态切换正确，并验证“查看最新”恢复行为。
4. 浏览器测试确认卡片可进入详情，详情仍可进入商家公开资料，且公开界面没有审核标签。
5. 浏览器测试确认商家发帖页保持图片排序、主题单选、字数限制、草稿和预览能力，固定操作区不遮挡最后一个字段。
6. 浏览器测试确认详情的大图、页码与固定收藏/分享操作区可用，收藏失败仍能回滚。
7. 浏览器测试确认商家公开资料页只列出同一商家的合规公开主帖，卡片可返回详情。
8. 在 320、375、414 像素宽度检查无横向页面溢出、主题触控区域足够、固定操作区和底栏不遮挡内容。
9. 运行完整 Node 测试、结构化文档验证、生成物一致性检查与 `git diff --check`。

## 12. 回退方式

规格与实施分别使用独立 Git commit。若本次布局不适合，可按提交粒度回退，不影响此前已确认的导航、通知层级、商家审核与隐私规则。

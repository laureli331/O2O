# V14 二次优化实施记录

日期：2026-10-22。依据[独立审阅](v14-ui-flow-naming-review-20261022.md)，由用户随后明确要求实施；原审阅的“只提供建议”仅表示其撰写阶段。预览：[打开 V14](http://127.0.0.1:8765/v14.html)。

## 已确认决策和边界

- D1、D2：用户确认任务型结构。处理记录在前，帮助与设置在后；申诉从本人符合条件的原记录进入，个人信息权益位于规则与隐私说明下。画板外的五组导航仅供评审。
- D4：用户确认到期提醒、催回复提醒两个独立开关。本轮分别保存本标签页的演示偏好，尚未接入真实通知策略或微信授权。旧版单开关演示值可分别带入两个开关，不改变已有线上策略。
- D3：仅以本地合成数据演示待确认占位、发起时间和恢复查询，不表示已有后台幂等、查询或持久化接口。当前标签页临时记录有效期仍为30分钟。
- D5：E03仍未确认。明确“在线申请暂未开放，本预览不收集材料、不创建请求单”，不增加虚构客服或人工办理渠道。
- D6：原结论、理由、时间来自本人可见的合成记录显式字段；不从说明拼凑理由，字段缺失时不开放演示申诉。真实字段、权限和脱敏范围仍须核实。

## 实施方案

1. 通知用具体变化命名；固定全部/未读/全部已读工具栏，标记不会删除记录。
2. 处理记录展示待你处理、全部记录、帮助与设置。待确认提交显示事项类型、发起时间，可返回继续查询；不生成成功记录，不允许再次提交。
3. 申诉表单展示原对象、结论、理由与时间。申诉和补充材料成功后回到同一条原记录，保留原结论与时间线；本次申诉首次回应另记，提交不表示原结论已撤销。
4. 举报、申诉、补充材料各有可回看的任务回执，带合成编号、提交时间和下一步，不依赖短暂提示。
5. 服务或费用争议保留既有内部原因值，选中后就地说明与订单异议、费用核对的区别。
6. 离开提醒页使用设置专属说明；继续填写/继续设置是绿色主按钮和默认焦点，放弃修改为危险色次按钮。
7. 标题缩短、正常辅助文字加深，延续米白绿色和轻微按压反馈；减少动态效果下关闭缩放。

## 参考与适配

- [GOV.UK 提交确认](https://design-system.service.gov.uk/patterns/confirmation-pages/)：借鉴可回看的确认、编号与下一步，未引入不存在的联系渠道或导出能力。

- 原审阅中的Google申诉、Apple通知与弹层参考继续适用；不复制外部产品品牌或业务限制。

验证结果：全量Node测试通过；14项PowerShell文档验证及交接资源检查通过。`verify-v14-preview.cjs`和新增`verify-v14-review.cjs`均通过，浏览器无脚本错误；320/375/414px检查通过。辅助文字在米白、回执、提示和浅绿四类背景上的对比度分别约5.82、5.34、5.40、5.30:1。测试覆盖三类任务的三种结果、原记录不丢失、待确认列表/刷新恢复、持久回执、独立开关及离开焦点。

原有临时记录不会被本次升级擅自补写处理理由；缺少原结论字段的历史演示记录不会开放申诉，可通过评审区“正常”状态重新查看本轮完整合成示例。本轮不启用真实举报、申诉、上传、消息发送或个人信息处理。

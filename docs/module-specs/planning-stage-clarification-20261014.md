## 用户不回来确认时，已确认设计如何处理

依据：[第一轮已确认规则](commission-simplification-rules.md)及[第二轮规则](commission-simplification-boundaries-rules.md)。以下只解释已有决定，不新增完成、收入或评价规则。

| 事项 | 已确认处理 | 前提或限制 |
| --- | --- | --- |
| 暂定计佣 | 不需要用户再次点击完成；双方约定的预计结束时间后，连续72小时窗口结束且条件齐备可形成暂定记录 | 双方事先明确同意关键规则及时间，使用有效正式金额；未知金额、有效未解决异议及待处理变更等不得伪装无异常 |
| 列表整理 | 暂定记录形成后自动归档，标“交付未确认”；闲置暂停售展示 | 仍保留异议入口和真实履约义务，不能当真实已售或已付款 |
| 真实交付事实 | 明确确认真实交付后才记录该事实，可自愿补确认 | 仅无人回应不证明真实完成；补确认不重复计佣或改变首次形成月份 |
| 个人收入 | 保留目前已确认完成的跑腿服务费累计口径，排除垫付款，非到账金额 | 只发生暂定计佣的记录不自动加入；用户不确认可能导致该展示不能反映所有线下实际收入，调整口径须另行确认 |
| 评价资格 | 保留真实交付明确确认后取得资格的设计 | 暂定计佣和归档不自动证明评价经历 |

因此，无人确认不会使符合条件的暂定计佣等待“完成”按钮，也不要求交易永久堆在进行中。没有有效金额或存在异常的交易仍需相应处理，不能保证单凭此方案防止全部线下规避。按现有约定不回来操作，不会自动变成“不计佣”；但此结论不代表已经收款或法律适用已核实。

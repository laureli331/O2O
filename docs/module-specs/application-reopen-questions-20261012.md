# 维修和其它申请排序与关闭重开：第十二轮8题

日期：2026-10-12。状态：8题全部待答。A推荐，均为提案，同时适用于维修和其它。保留先申请再选1人、有效申请最多1份、可立即重申、申请私密及关闭留历史的已确认规则。

| 编号 | 问题 | A（推荐） | B |
| --- | --- | --- | --- |
| 1（AR01） | 修改有效申请后，候选排序时间怎么取？ | 保留该次申请首次有效提交时间，修改不改变位置 | 使用最近修改成功时间，重新排到后面 |
| 2（AR02） | 撤回或失效后重新申请，排序时间怎么取？ | 按本次重新申请成功时间排序 | 保留本人对该需求首次申请的时间 |
| 3（AR03） | 未选人就关闭的需求，如何重新开放？ | 发布者可主动重开同一需求，须重新申请，不恢复旧申请 | 旧需求保持关闭，需另发一条新需求 |
| 4（AR04） | 重开的需求在首页“最新”怎么排序？ | 保留原发布时间，不因重开置顶 | 按重开成功时间重新排序 |
| 5（AR05） | 未选人需求关闭再重开，有次数上限吗？ | 不设产品次数上限，保留每次关闭/重开记录 | 同一需求最多重开3次，之后只能新发 |
| 6（AR06） | 未选人时关闭需求，需要填写理由吗？ | 理由选填，最多300字 | 理由必填，1—300字 |
| 7（AR07） | 选人前哪些内容修改会使旧申请失效？ | 标题、描述、图片、公开区域、服务时间任一变化 | 标题、描述、公开区域、服务时间；仅图片变化不使申请失效 |
| 8（AR08） | 关闭需求与选人同时操作，怎么办？ | 以服务端先成功的操作为准，另一操作不执行并提示刷新 | 检测到同时操作时，两项都不执行，提示刷新后重试 |

第1—2题只讨论候选排序，不把申请预估费用变成正式约定。第3—6题讨论尚未选人关闭的需求；取消已选服务后重开仍按既有规则处理，已完成服务不能借本轮重开。关闭记录、理由及重新开放均不代表物理删除，消息渠道与保存期限另议。

第4题只讨论需求在首页“最新”的公开排序，不改变第1—2题的候选排序，不修改优选的付费展示规则。第7题不新增必填图片或服务时间，也不允许选人后单方改内容；私密地址、联系方式及非关键编辑另议。

第8题仅解决两项尚未成功操作的冲突，已经成功的选人或关闭不因另一个旧请求到达而回退。选人成功后只能按服务取消规则处理，关闭成功后不能选中结束申请。具体实现、未知结果核对及提示文案另议，不用客户端点击时间判定。

# 闲置交易确认与交付完成规则

联系展示的新决定：CS08已确认闲置完整联系方式须双方确认交易并知悉计佣规则后才交付，见[简化机制](commission-simplification-rules.md)。联系申请获准仍可确定发起目标，但单独获准不再作为新机制完整电话展示条件；实际权限未改动，旧记录保留。

后续确认：第二十轮已补齐双方取消、单份改价及完成前处理、完成自动已售/打码、新流程完成直接评分资格，见[取消改价与完成规则](idle-change-rules.md)。以下第十九轮评分衔接待定等内容是当时历史，不再作为最新状态；其它未补齐边界仍待后续确认。

确认日期：2026-10-14。依据：[第十九轮原题](idle-transaction-questions-20261014.md)，实际回复“5B, 全A”，对应1A、2A、3A、4A、5B、6A、7A、8A。承接[第十八轮已确认动作](commission-confirmation-rules.md)：卖家发起、买家确认生效，面议先明确金额，成功确认时锁定5%及20元佣金上限。旧PRD是历史基线，本增量不表示真实流程已实现。

## 已确认

| 来源 | 规则 | 边界 |
| --- | --- | --- |
| IT01 / A | 卖家仅向该闲置帖联系申请已获准的买家发起交易确认 | 注册、申请中或仅浏览均不足；目标合法授权的判定与失效衔接仍待定，不新增用户搜索接口或扩大隐私权限 |
| IT02 / A | 同一闲置帖最多1份待确认交易，确认后只保留1笔进行中交易 | 不开放多个有效交易；重复操作、撤回后新提、已售/取消后的重新开放及并发细则仍待定 |
| IT03 / A | 待确认金额/内容修改先撤回，再发新版本，买家重新确认 | 原版本留历史，不能覆盖或确认已撤回旧版本；已生效交易变更另议 |
| IT04 / A | 买家不回应交易确认，保持待确认，卖家可提醒或撤回，不自动同意 | 不满24小时自动关闭；提醒频率及撤回与确认并发未定，不额外添加自动到期 |
| IT05 / B | 买家不同意交易确认，理由必填1—300字，请求结束并留历史 | 不是选填；空理由不能提交有效不同意，不把不同意待确认交易当取消已生效交易；文字计数/空白、历史可见性仍待补齐 |
| IT06 / A | 交易确认后标记交易中、暂停新联系申请，既有合法权限保留 | 不提前标已售，不新增授权对象，既有权限沿原期限不延长；进行中公开位置、恢复联系申请及结束后打码另议 |
| IT07 / A | 交付后卖家提交完成，买家确认后完成 | 提交完成、实际付款或单方标已售均不等于此完成事实；完成字段/证据及并发/不同意另议 |
| IT08 / A | 买家不回应完成申请，保持待确认、不自动完成，可提醒或提出异议 | 不套跑腿24小时自动完成；不授予运营代确认，也不自动开启评分；异议处理细则另议 |

交易确认、交付完成和付款为不同事实。仅待确认交易尚未生效，不能锁定为成功交易/直接产生佣金；买家确认生效后的交易中仍未完成，不能以此提前计佣。闲置仅成功完成/成交事实才进入已定月结方向，最终字段和状态映射仍待补齐。买家确认交付完成的评分衔接待下一轮确认，不自动替代旧RV01资格流程或增加钱包。

佣金5%/20元继续按双方确认交易时的标准锁定；交易结束后的联系方式、已售公开状态、调价/取消/退款与评级待议，不从“既有合法权限保留”推导永久可看完整联系方式或详细地址。

## 验收依据

1. 未获准该帖联系申请的用户不能作为确认目标；其它帖联系获准不能跨帖授权。
2. 同帖已有待确认请求不能同时新增第二份；进行中交易不能与第二笔进行中交易并存。具体失败提示和并发判定仍待定。
3. 撤回后旧版本不可确认，新版本须买家重新确认，旧金额和请求历史留存；不凭直接编辑原版本生效。
4. 无回应请求即使满24小时也不自动同意/关闭；卖家明确撤回或买家不同意是不同结束来源，不能假装交易取消。
5. 不同意理由0字或301字不满足1—300字要求；有效理由提交后请求结束留历史，不把空理由当有效拒绝。文字计数与空白归一化尚未定，例子使用明确字数文本。
6. 成功确认后交易中、暂停新联系申请；既有合法权限不被本轮自动撤销，也不向其他用户开放。
7. 卖家完成申请尚未获买家确认时仍未完成，不产生自动完成/付款成功/新评分资格；买家明确确认交付后完成，评分衔接继续待定。
8. 待确认完成无回应超过24小时仍待确认；旧举报/申诉入口保留，不因本增量假装已启用支付或计佣。

当前仅验证文档与资源一致性，没有实现或验证真实交易、确认、并发、授权、通知、计佣或支付。

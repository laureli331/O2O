# 取消人工完成确认，改为到期收尾

日期：2026-10-15。用户原话：

> 全A
> 取消"确认完成/收到", 新增"服务到期时间", 到时自动完成, 新增"延长到期"
> 这样不需要用户多一步操作(因为他们线下完成交易之后, 也不想在小程序上确认)
> 在发布需求的时候, 让用户填写"服务时间", "有效期"让他们自己填个时间
> 你认为呢?

## 已明确的方向

取消客户的“确认完成/收到”按钮，不要求线下完成后回来确认。发布需求时由用户填写时间，交易按约定到期自动结束，并提供“延长到期”。这是首发方案内的业务调整，没有运行中的旧机制。

事前选定接单员/接受报价/确认交易仍是确定双方及收费规则的动作，和事后的完成确认不同。维修/其它选人时费用可以未知，不能把选人成功当双方已经确认具体金额。费用、取消和异议解除的明确同意要求没有被一句“取消完成确认”取消。

## 建议及取舍（尚待选择）

推荐用“服务时间”表示什么时候开始，用“服务到期时间”表示最晚什么时候办完并结束流程；界面不再另放一个含义相同的“有效期”。推荐到填写的最终到期时间直接自动收尾，不再叠加原预计结束后72小时；如果有效异议解除时已到期，也不再额外等72小时。这能少一个确认动作，也能少一层时间计算，但是否采用分别由NE01—NE03决定。

另一种是把有效期用作“最晚找人/接单时间”，这样还要另填服务到期，至少有三种时间。也可以保留原72小时作为额外缓冲；代价是用户填写的预计办完时间和真正结单时间仍不同。不能擅自把这两种时间当同一个字段。

“延长到期”建议沿用已经批准的双方同意原则，一方提出、另一方同意后才生效；未同意仍按原时间。初次720小时、每次从原有效结束最多延168小时的上限没有被这次原话明确撤销，不再重复问。有效未完成/未成交/取消争议仍有入口并暂停自动收尾，不让用户必须先拒绝一个已取消的完成确认按钮。

自动结束记录和客户线下实际付款不是一回事。取消人工完成后，旧主收入仅计“明确实际完成跑腿”的资格入口不再完整；推荐改用正常到期、费用已确认且无有效交付异议的跑腿服务费，说明按到期订单统计、非到账。也可先不显示主累计。这一改变须NE04明确选择，不能默认改数字。

只删客户确认按钮是否还保留接单员可选“已办完”上报，NE05另问。可选上报不能当客户已认可，也不能因此提前结单、计佣或恢复隐私权限。

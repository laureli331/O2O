## 已确认的增量

## 拟讨论顺序

这是一份讨论提案，不是用户已批准的开发排期：先明确其它范围，再继续维修细节；之后核对跑腿、闲置；再整理账号身份、联系授权、评价；接着首页搜索、免费目录、付费优选、个人工具与收入；最后通知举报、核验标识/报表、运营看板、AI发布助手及全模块衔接。完整覆盖原12模块与8扩展，同时补其它；尚未为其它虚构正式M编号。

## 每个模块的收口内容

目标与允许范围；角色与入口；页面和文案；字段及校验；权限与可见性；动作与状态变化；费用/时限/通知（有则明确）；异常、重复操作与并发；数据来源与外部依赖；可验证验收场景。规则中引用原编号；新增编号在具体规则确认后建立。

每轮集中确认一个关键问题。已有明确决定沿用；变更或冲突由用户明确裁定。确认后记录原回复与日期，逐项同步有关交接文档，补验证并提交Git；整模块复述给用户核对，关键规则尚未明确时不进入实现。

## 验证方案

每次记录检查：回复与选项对应；其它没有遗漏；已确认与待定分开；不得把选择A解释成抢单或强制报价；不得把其它解释成任意任务。验证文档链接、资源清单与现有PRD引用仍有效；保留原图哈希、原业务规则和已有验收。文档测试不替代后续产品测试。

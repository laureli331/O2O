## 已确认的增量

1. 其它是业务模块，纳入本次规划；归集维修、跑腿、闲置之外的需求数据，作为后续更新迭代依据。用户确认公开发布并允许申请接单，先申请再由发布者选人；2026-10-11确认每条需求最终选1位且申请人数不设产品上限，申请时不强制填写服务费报价，金额后续协商。自愿报价、费用确定时点、分类判断及禁止范围细则仍需明确。
2. 维修模式选A：先申请，再由发布者选人；申请时不强制报价。2026-10-11确认每条需求最终选1位且申请人数不设产品上限。价格确定方式另议，不能据此默认免费、不支持报价或先报价才能申请。

3. 2026-10-11确认两类申请操作：同一人对同一需求最多1份有效申请，选定前可修改或撤回；重复点击不新增申请记录。

4. 2026-10-11确认两类联系权限：选定前查看对方联系方式仍打码；选定成功后仅发布者与选中的接单员互看完整联系方式，其他申请者仍打码。仅在卡片草选、发起申请或选择请求失败/结果未知时，不能视为选定成功。服务端授权沿用原PRD可见性要求，不能把完整信息下发后仅在页面打码。

5. 2026-10-11确认两类费用约定：协商后的费用在小程序内记录并由双方确认，供后续完成确认、变更和异议处理参考。记录金额不代表已付款；费用明细、确认时点、变更/拒绝/撤回/无回应及异议规则仍待讨论。不新增平台代收、余额或自动结算；个人收入目前仍仅按原确认的跑腿口径，不自动包含维修和其它。

维修和其它已确认先申请再由发布者选人，每条需求最终选1位，申请人数不设产品上限，申请时均不强制报价。撤回后重申/冷却/修改细则、接单员同时接单、选定生效、其他申请如何结束、取消后能否改选仍待讨论；选定前可撤回申请不代表选定后可单方取消服务。联系开放时点和对象已定，详细地址及联系变更/撤销/结束后的处理仍待讨论。费用记录和双方确认已定，但明细/时点/变更等尚不完整；维修申请内容、预约诊断、完成取消、争议、评价仍待议。“其它”的归类原则和整理数据目的已确认，允许公开发布并申请接单；完整流程仍待议。

本次联系规则用于维修求助扩展接单流程及其它需求，与历史CT03逐人授权联系模式存在变更。闲置、免费服务目录及其推广仍沿用原CT03；没有因此改为选人流程。旧维修求助关系如何迁移及切换安排待确认，不能自动抹掉旧授权或沿用旧授权解码新需求。

不强制报价不代表免费、不填时默认0元、不允许自愿报价或已确认选人时可以不确定金额。自愿报价字段及费用在哪个阶段由双方确认仍需讨论。不因两者选人模式相同而自动复制费用、资格、联系和履约规则。整理数据目的不等于已批准将原文交给AI、公开私人数据、无限期保存或新增真实数据采集方案。两项均不具备完整流程开发依据。

## 拟讨论顺序

这是一份讨论提案，不是用户已批准的开发排期：先明确其它范围，再继续维修细节；之后核对跑腿、闲置；再整理账号身份、联系授权、评价；接着首页搜索、免费目录、付费优选、个人工具与收入；最后通知举报、核验标识/报表、运营看板、AI发布助手及全模块衔接。完整覆盖原12模块与8扩展，同时补其它；尚未为其它虚构正式M编号。

## 每个模块的收口内容

目标与允许范围；角色与入口；页面和文案；字段及校验；权限与可见性；动作与状态变化；费用/时限/通知（有则明确）；异常、重复操作与并发；数据来源与外部依赖；可验证验收场景。规则中引用原编号；新增编号在具体规则确认后建立。

每轮集中确认一个关键问题。已有明确决定沿用；变更或冲突由用户明确裁定。确认后记录原回复与日期，逐项同步有关交接文档，补验证并提交Git；整模块复述给用户核对，关键规则尚未明确时不进入实现。

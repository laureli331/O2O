# 维修和其它：履约与结束规则

更新：2026-10-11。依据：[第三轮8题](fulfillment-questions-20261011.md)实际回复“全A”，同时适用于维修和其它。原PRD跑腿24小时自动完成规则不受本轮影响。

## 本轮8项决定

| 来源 | 已确认规则 | 边界 |
| --- | --- | --- |
| LQ01 | 选人后修改服务内容或区域须双方确认，确认前原内容有效 | 不批准单方覆盖，具体待确认版本的拒绝/撤回/冲突待定 |
| LQ02 | 预约时间选填，双方确认后记录，改期也需双方确认 | 不新增必填预约、默认日期或自动确认；旧视觉仅标签不是时间来源 |
| LQ03 | 接单员提交完成，发布者确认后完成 | 发布者不能跳过接单员提交而直接结束；完成不等于付款或费用结清 |
| LQ04 | 发布者不回应完成申请，保持待确认，不自动完成，可提醒或提出异议 | 不采用跑腿24小时规则；提醒渠道/频率和异议处理待定 |
| LQ05 | 任一方可申请取消，另一方确认后取消 | 本轮用于选人后、完成前；不能当作选定前撤回申请，也不代表费用结清 |
| LQ06 | 对方不回应取消申请，保持待确认，不自动取消，可提醒或提出异议 | 不设置48小时自动取消，不能以沉默作同意 |
| LQ07 | 已确认取消后，发布者可主动重新开放同一需求，重新申请和选人 | 不自动重开或递补，旧申请不恢复，不覆盖历史服务和费用 |
| LQ08 | 完成或取消后，联系方式重新打码，关闭接单员对完整地址的访问 | 发布者仍可管理自己的地址；未确认完成/取消不触发该结束规则；保存期限另议 |

费用继续按[费用规则](fee-rules.md)记录和双方确认；取消前无需先对已发生费用达成一致，取消后可另行协商记录。信息权限关闭不能清除必要历史或将费用显示为已结清。重新开放后新服务的当事人须由新申请和新选定产生，不能让旧接单员凭旧授权解码新服务；同一人再次被选中也以新的选定关系授权。

## 验收依据

1. 选人后的内容/区域变更未确认时，原约定仍有效；只有双方明确认可新版本才能生效。
2. 无预约时间也可继续服务；单方提出时间或改期不产生双方已确认预约，未填不能显示虚构时间。
3. 接单员提交完成后保持待发布者确认；只有发布者确认后才为已完成。重复提交和网络结果未知不能重复结束服务。
4. 完成申请超过24小时仍无回应，不自动完成；不得把跑腿计时逻辑复用到维修和其它。
5. 任一方提交取消申请后仍待对方确认；超过48小时无回应不自动取消，可提醒/提出异议。
6. 确认取消后，费用记录保持必要历史，仍能协商已发生费用；取消不得自动标记支付或结清。
7. 发布者主动重开已取消需求后，旧申请不自动恢复、不自动选旧接单员，重新申请和选定；新旧服务与费用可区分，不被覆盖。
8. 确认完成/取消后，双方完整联系方式不再下发给对方，旧接单员不能获取完整地址；发布者管理本人地址不受影响。新服务选人不能重新开放旧服务的授权。

当前仅验证文档记录与权限边界的一致性，没有实现或验证真实履约功能。使用这些场景编写后续产品测试时，必须以实际服务端状态和权限为准。

## 尚未确认

变更/预约的字段、发起方、待确认数量、拒绝/撤回及冲突；时间格式/时区/过期校验；完成和取消说明/凭据；不同意完成/取消及异议处理；完成、取消与未决变更/费用的衔接；通知渠道和提醒频率；重开次数/编辑/公开排序/申请期限/新旧服务展示；评分资格和旧维修实际经历迁移；返修/质保；字段校验、保存期限、运营权限及完整状态/接口合同。服务结束后再改变约定或再次提供服务如何记录，尚未批准。

个人收入仍仅包含已确认完成的跑腿服务费，不自动纳入维修或其它。既有其它禁止范围、评分启用条件和私人数据处理边界保持原决定。

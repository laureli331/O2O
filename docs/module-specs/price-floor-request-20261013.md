# 交易确认后的调价下限：新增要求

来源日期：2026-10-13。用户原话：

> 新增规则: 确认进行交易后, 若骑手及维修员修改服务费, 闲置卖家修改金额, 不能低于初始金额

已明确的意图：确认进行交易后，骑手及维修员修改服务费、闲置卖家修改金额时，不得低于初始金额。记录该约束，不把“初始金额”擅自解释成发布预算、申请报价、商品标价、首个费用阶段或最近一次价格。

## 现有流程核对

- 跑腿RUN03在成功选人时明确最终服务费，RUN06承接后费用变更须双方确认；预算、申请报价和最终费是不同值。
- 新维修选人时不强制报价，正式费用选人后按阶段双方确认；服务费与实际支出分项，阶段独立累计。不能把未知金额默认0，也不能覆盖已确认的完成后费用只读要求。
- 闲置的历史基线POST04/F03/CT03为信息与联系模式，可标价或面议；联系获准不等于成交。事后实际经历确认用于评价资格，不能当成事前交易价确认。
- 原话没有提“其它”，不能因它与维修有共同费用结构就自动纳入。

新增意图不取消现有双方确认、原费用生效至新方案确认、费用历史、金额上限或居民线下直接结算规则；不授予单方涨价即生效权限，不表示实际收款。不能据此直接实现闲置交易价确认流程或把事后评分资格改为事前交易确认。

## 必须确认后才能落地的边界

跑腿与维修的初始金额来源和冻结时点；闲置确认交易的新步骤及面议处理；维修阶段/整次服务的服务费下限，材料等实际支出的适用性；是否约束双方发起调价、是否包含其它；涨价后能否回降至初始金额。[原第十三轮8题](price-floor-questions-20261013.md)未逐题作答；后续“没问题, 继续”已确认通用锁价/计费/独立调整原则，见[已确认规则](monthly-commission-rules.md)。具体字段与业务细则仍待补齐，不能据此直接开发完整校验流程。

后续还需明确取消/重开后的下限继承、闲置一帖多联系对象与交易对象/状态、历史订单适用范围、分项更换与退款/纠错、页面提示及并发。这些未确认事项不使用默认值，也不从禁止降低金额推出禁止退款。

核对原话和具名对象留存、与第十二轮答案分开、三个业务基线差异及待定字段未被填入；验证文档链接、既有确认及原图不变。本次没有实现或验证真实调价拦截、付款或闲置交易流程。

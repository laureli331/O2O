# 月末按交易金额抽佣：规划方向与评估

日期：2026-10-13。状态：用户提出的收入模式规划方向；比例、计费订单、收取方式及下述建议尚未确认。不是已实现或获准运行的收款方案。

## 用户原话

> 我计划的抽佣方式为，在每月月末，根据骑手及维修员的服务费，以及闲置卖家的成交价格，按比例抽佣。所以我担心有骑手，维修员以及卖家为了避开抽佣，会在确认进行交易后，与客户协商修改价格。
> 所以我希望在修改价格时, 不能低于初始值. 你认为呢?

已明确的计划：每月月末，按骑手及维修员的服务费、闲置卖家的成交价格比例抽佣。限制确认交易后降低金额的目的，是避免双方协商改小记录金额来减少佣金。原话未给佣金率、是否三类同率、计入哪个月份/哪些状态、退款减免、收取方式及其它业务适用性，不填默认值。

## 与当前基线的变化

原PRD第2.4节与首期不做范围明确不抽跑腿佣金、居民直接结算。本次提出了抽佣的收入方向，后续需形成明确变更规则；保留旧PRD作为历史，不以本次计划直接开启收款、改成平台代收、变更旧交易价格或已有授权。跑腿收入显示口径与平台佣金、服务者净收入的关系尚未决定，不能直接把原收入统计改为扣佣后收入。

[已记录调价要求](price-floor-request-20261013.md)仍有效；[第十三轮8题](price-floor-questions-20261013.md)尚未回答，本条解释不等于“全A”。闲置原联系授权不等于成交，维修允许分阶段费用确认，抽佣需补齐对应的确认金额及有效交易依据。

## 建议方案，待用户确认

建议保留普通改价不得低于双方确认初始值的限制，并将原确认价、历次双方确认变化和佣金计算依据分别保留。月底账单使用明确的计费记录，不读取可随时改动的当前展示价。

建议后续明确：完成/成交后哪些交易计入佣金；确认的新增服务费如何计入；退款、误录、服务缩减等是否走独立调整记录、谁确认或审核、如何留证。普通改价不覆盖原交易事实；不将该建议自动写为“退款不退佣”“按最高手续费金额收佣”或运营已有服务调解权限。

示意：初始双方确认100元，普通改价改为1元会被下限拦住；后续确认增费则佣金如何增加需明定；实际未完成、部分退款或录入错误不能仅靠禁止降价处理。数值仅用于说明，不是运营数据或佣金率。

局限：初始就少报价格、虚假取消后线下成交、线下新增费用不记录，均无法仅靠下限消除。按当前居民直接结算流程推断，平台能记录约定金额和应缴账单，不能单凭这些记录核实全部线下实际收付或保证佣金缴纳。选择支付方案前需要明确月末出账后的付款、逾期、异议与核对流程。

## 收款能力核对

[微信支付服务商分账官方文档](https://pay.wechatpay.cn/doc/v3/partner/4012072582)说明其基于特约商户收单成功后的交易资金分配，且须特约商户授权设置允许分账比例。该能力不能从“月底按比例出账”推导为本项目已可自动扣款；本项目开通/商户适用条件及实际支付方案尚未核实。此处仅核对产品能力，不确认实际资格或替用户选择支付方式。

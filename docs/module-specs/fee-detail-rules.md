# 维修和其它：费用录入与方案处理

确认日期：2026-10-12。依据：[第五轮8题](fee-detail-questions-20261011.md)，用户实际回复“全A”。同时适用于维修和其它，与[此前费用规则](fee-rules.md)一起使用。本文件描述业务约束；结构化决策中的名称是规划记录，不是已定义的数据库字段或接口。

## 已确认的8项规则

| 来源 | 已确认规则 | 边界 |
| --- | --- | --- |
| FQ09 | 是否垫付及上限与费用方案一起记录并由双方确认 | 自愿且在垫付前确认；上限可0及超限处理已由第六轮补齐，字段映射仍待讨论 |
| FQ10 | 服务费允许明确填0元，表示免费 | 未填仍为待协商；未知实际支出不能填0充数；不修改跑腿服务费必须大于0规则 |
| FQ11 | 成功选人后，由发布者或选中的接单员发起正式费用方案 | 候选申请者不能发起；申请时选填的预估服务费仍不算正式约定；第六轮已确认完成后只读，取消后费用仍可协商，未决费用收尾另议 |
| FQ12 | 每项填写名称、类别、该项金额；备注选填 | 名称必填1—30字，类别为服务费或实际支出，金额必填；备注最多300字；不要求录入单价和数量 |
| FQ13 | 一份费用约定至少1项、最多20项 | 项目示例不变成固定必收项目；第六轮已确认每项及每份方案合计上限99,999.99元 |
| FQ14 | 当前阶段各项目金额确定后才能提交正式确认 | 未知后续费用先不加入，后续分阶段确认；不支持以估算项替代本阶段确定金额，不强填0 |
| FQ15 | 修改待确认方案须先撤回，再提交新方案 | 保留历史；撤回不抹掉原已生效约定，新方案双方确认前原约定有效 |
| FQ16 | 对方不同意方案时理由选填，本次待确认方案结束 | 原有效约定保留；可再协商提交新方案；不同意不取消服务或否认历史已确认费用 |

## 输入与展示边界

金额输入沿用原PRD共同格式：不允许负数或货币表达式、最多2位小数、价格输入防误填上限99,999.99元。输入检查不证明已付款。实际支出零值是否允许、金额字段映射与跨阶段累计计算仍待确认，不能由服务费可为0推定所有费用字段都可为0。第六轮已确认每项和每份方案合计均不超过99,999.99元，详见[费用边界规则](fee-boundary-rules.md)。

类别只区分服务费和实际支出；检查费、上门费仍属服务费，材料、配件、商品只是支出示例。金额采用本项合计金额，不自动引入单价×数量功能。名称和备注沿用用户可见字数、去除首尾空白的共同原则；具体计数实现与逐字段映射待整理。

既有最多1份待确认方案、提交即认可该版本、另一方确认后生效的规则继续有效。修改、撤回、不同意与对方确认同时发生的优先级及提示仍待明确，不凭页面先点击判断成功。

## 验收依据

1. 明确0元服务费可作为免费服务约定；未填申请预估报价仍显示待协商，未知支出不能因此补0。
2. 选人前或未选中的申请者不能发起正式费用方案；选人成功后仅该服务双方有发起资格。
3. 名称空白、超过30字、类别缺失、金额缺失或备注超过300字，应被阻止提交；合法备注可不填。
4. 0项或21项不允许提交，1—20项按确定金额分别记录，不要求单价或数量。
5. 当前阶段未知金额不能提交为正式约定，未知未来支出可留待后续阶段，不阻止已明确阶段的协商。
6. 待确认方案不能原地更新；先撤回再提交，新旧历史仍在，原有效约定不被待确认新方案替换。
7. 不同意费用方案可不填理由，只结束该方案；不自动取消服务或把原约定金额清零。
8. 垫付条件随费用方案一起确认，不能分离为未经双方确认的自动垫付授权。

当前仅运行文档一致性检查，没有实现或验证实际表单、权限、金额计算或并发行为。

## 仍需补齐

第六轮已确认阶段预设/自定义、完成后费用只读、垫付上限可0及超限须重新确认、每项最多3张凭据和结束后关闭凭据访问、每份合计上限、重开复制为新草稿，详见[费用边界规则](fee-boundary-rules.md)。尚待补齐：实际支出零值、阶段与累计组织、结束时未决费用、取消后新凭据、草稿复制人及字段范围、并发冲突、提醒、历史展示、保存期限、完整状态及接口合同。个人收入仍仅按已确认完成的跑腿服务费累计，排除垫付款并注明非到账金额，不自动纳入维修和其它。

## 保留的收入方向

跑腿15%不封顶；维修15%、同次服务佣金最多30元；闲置5%、每笔最多20元；其它10%、同次服务最多20元。比例/封顶锁定、客户款线下直接结算、服务者/卖家主动缴佣方向不变。不引入固定撮合费、不采用客户款平台代收或自动扣佣。新机制的范围和切换安排未定。

用户选择B不是批准自动完成、无回应视为成交、自动归档计佣或仅凭单方服务者声明收费。当前维修/其它和闲置仍沿已有双方完成确认；跑腿RUN11既有24小时自动完成条件继续保留，不把新的申报窗口混成其计时。

## 可比较的三种机制（均待确认）

| 机制 | 正常收尾操作 | 主要取舍 |
| --- | --- | --- |
| S1：事前共同约定预计结束时点和计佣规则，无异议生成暂定计佣记录（推荐讨论） | 金额/时间/规则先明确；到约定时点后进入异常申报窗口，满足前提且无异常时自动形成可异议计佣记录 | 减少客户事后必须回来的操作，但可能误计未成交，须知悉、有效通知、低门槛异议和纠错；未完成真实核验，不得包装成真实成交 |
| S2：服务者主动提交申报，客户可提出异议 | 服务者点一次报告完成，正常客户可不再操作 | 少一些自动时间规则，仍依赖承担佣金方申报，金额初始低报/不申报盲区更明显；单方记录不等双方真实交付确认 |
| S3：保留双方完成确认，仅合并页面/操作与必要提醒 | 正常收尾尽量一次确认、异常按需 | 对原业务改动较小，但未回来的用户仍可能不确认，收入依赖未消除 |

S1的建议来自降低操作摩擦、将约定提前的设计推论，沿[行为评估](offline-transaction-replan-20261014.md)的心理学依据；没有真实用户试验，不保证减少多少逃佣或运营成本。拟先试闲置，具体范围须用户确认。

## S1待确认流程与前提

有效交易/选人 → 双方明确有效金额、预计交付结束时点及默认计佣申报规则 → 约定结束时点到达 → 异常申报窗口 → 无待处理异常且前提完整时形成暂定计佣记录 → 按获准规则纳入月账单；有未成交/未完成/金额异议则暂停相应部分并核验。

维修/其它不在选人时强制报未知金额，比例和封顶仍按选人成功锁定；未知正式服务费不填0，不自动计佣。原已确认金额、新增阶段/改价、取消/延期/异议有待处理时不能假装前提满足。何时将暂定记录纳入账单、适用月份、持续异常、后续加价和迟到申诉仍须补齐，不自动沿用“成功完成月份”作新暂定记录月份。

正常用户不用为了避免系统等待而反复回来点完成；真正未成交/未完成需要可达的异常入口。双方未共同知悉、金额未知、时间未定、通知失败/结果未知、有效取消或异议存在时，不按该草案默认产生收费。本轮未给出通知渠道、次数、自动生成时刻/迟到边界、退费时限或运营资源承诺。

## 三类事实分开

- **暂定计佣记录**：依事先约定的申报规则计算的可复核平台费用记录，名称/状态字段待定。
- **真实交付确认**：明确说明实际服务/交付发生的当事人确认事实，原手动完成入口可自愿使用。
- **实际付款**：平台佣金缴款或客户线下付款，各自需要对应事实；计佣或交付确认都不能证明付款。

暂定计佣不能直接变成真实完成数、成交额、评分资格、个人页收入或已付款。双方明确确认真实交付仍可沿原规则评分；是否保留此入口或试点暂缓新评分在后续问题中确认。归档只是记录管理，不是交付验收。新规则不会从暂定记录新增HD02收入。

## 规避收费与公平

不回收尾不能成为确定的免佣途径，是S1想改善的问题；但已拿到电话后完全不确认新交易、初始金额故意低报、实际加价不申报、双方虚假取消和熟人复购仍不可完全观察。必须同时讨论闲置联系展示是否后移至交易/计佣规则确认之后，不能宣称时间规则已堵住事前绕行。

提出未成交/未完成不能只因系统无投诉而被否认；窗口结束后合理申诉/纠错的权利、证据必要性及权限仍待确认。运营只核验计佣依据，不因此取得维修/其它服务调解权。异常不能仅靠双方一句话就被当退款到账，也不能对无证据的所有异常都自动判恶意。

## 法律文本与设计适用边界

[官方《民法典》](https://gdca.miit.gov.cn/zwgk/zcwj/flfg/art/2020/art_573d6ef5018b46b6a4e1f31ca085a710.html)第一百四十条规定沉默成为意思表示有规定、约定或交易习惯等条件；第四百九十六、四百九十七条涉及重大利害条款提示说明、公平及格式条款效力。[平台收费指南](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/jjjzs/art/2025/art_e4eca064b20843c6a97ead0c94fda00e.html)要求收费清楚、合理并有对应服务。因此本草案提出事先明确同意和救济前提；这些文本不等于为本项目自动推定计佣授权，仅点击同意也不能保证条款有效。实际主体、通知、收费和申诉规则需核实，本轮不作可收费的法律结论。

## 验证方案

| 情景 | 必须核对 |
| --- | --- |
| 双方已明确金额/时间/规则，真实线下完成后无人返回 | 若批准S1，可生成计佣候选记录；不自动增加真实完成/收入/评分，不自动扣款 |
| 仅浏览、联系获准或未确认交易 | 无有效交易前提，不能生成默认计佣；提前拿电话仍是盲区 |
| 选人成功但正式费用未知，或预计时间缺失 | 不填0、不起算默认计佣，比例/封顶快照与金额前提分开 |
| 尚有改价、延期、取消、未完成异议或通知未知 | 不直接当无异议自动计佣；具体暂停/续算方案另议 |
| 初始低价，实际加价没登记 | 不能凭系统记录宣称掌握真实实价，须明确承认盲区 |
| 真实未成交，或申诉晚到/已出账 | 有异常核验和纠错出口，保留原账单及记录，差额/月份和救济时限待定 |
| 原跑腿24小时计时与出账后72小时缴款 | 各自按原来源保留，新申报窗口是另一规则，不相互替换 |

本轮仅完成文档、历史和提案边界验证，没有真实计时、用户实验、支付、计佣或通知测试。具体金额/时限/状态转换获准后再设计验收与低成本试用，样本与指标不编造。

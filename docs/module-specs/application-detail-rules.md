# 维修和其它：申请展示与历史

确认日期：2026-10-12。依据：[第十一轮8题](application-detail-questions-20261012.md)，用户实际回复“全A”。与[申请与选人规则](application-rules.md)共同使用，仅记录业务约束，未实现真实申请功能。

## 已确认规则

| 来源 | 决定 | 边界 |
| --- | --- | --- |
| AD01 | 发布者可看该需求全部申请，申请者只看自己的，其他人不可看 | 包括申请说明及预估报价；不扩大身份、联系方式或私密地址权限，不能向无权者下发完整申请后仅前端隐藏 |
| AD02 | 发布者候选列表展示说明、预估服务费、申请时间 | 未填说明不占行，未报价显示“待协商”；预估报价不是正式费用约定；头像昵称及合法评分另按既有规则与角色衔接处理 |
| AD03 | 按有效申请时间先后排序，先申请的在前 | 不按报价或评分暗中重排；修改保留该次首次提交时间、重申用本次成功时间已由[第十二轮](application-reopen-rules.md)确认，同一时刻并列排序另议 |
| AD04 | 未选人需求不设自动到期，发布者可主动关闭 | 不套用7天到期；关闭不等于物理删除，也不等于选人后的取消服务 |
| AD05 | 有有效申请但尚未选人时，发布者仍可关闭需求 | 结束有效申请并通知，保留历史；不是逐个拒绝申请，不授予选人后单方取消权 |
| AD06 | 修改申请保留各次提交版本，发布者与本人可查看 | 对应申请历史不得向其他申请者开放；不批准无限期保存，不向新服务当事人自动开放旧服务私密信息 |
| AD07 | 修改有效申请通知发布者，列表标记“已修改” | 通知渠道、频率及失败重试待确认，不默认订阅消息；不能因此改写申请时间或费用约定 |
| AD08 | 内容变更导致旧申请失效后，仍开放时可立即重申 | 没有24小时冷却；旧记录保留但不能选中，仍最多1份有效申请；主动撤回后立即重申的旧规则保留 |

成功选人后其余申请结束并通知、不自动递补；正式费用仍须双方另行确认。关闭与选人同时发生以服务端先成功操作为准已由[第十二轮](application-reopen-rules.md)确认，具体实现待定，不用页面点击顺序替代实际成功事实。未选人关闭后可主动重开同一需求、须重新申请已由第十二轮确认，不能自动恢复已结束申请。

## 验收依据

1. 发布者能看本需求申请说明和预估报价；申请者不能获取另一申请者的内容，未登录及其他用户也不能获取。
2. 未填说明不留空白说明行；预估费用为空显示“待协商”，不变成0元或免费。
3. 无修改/重申情形下，早申请者排前，不因报价、评分改变默认排序；并列时间的次序需后续确认。
4. 未选人需求经过7天仍可申请，不自动关闭；发布者主动关闭成功后不可新增申请或选中已结束申请。
5. 有有效申请时关闭也能成功，原有效申请均结束、通知且留历史；不能只关闭页面入口却保留可选申请。
6. 修改后新旧提交版本均可按权限查看；其他申请者无权看历史版本，保存期限不得默认无限。
7. 有效申请修改成功后通知发布者并标记“已修改”；通知发送失败不能假装已送达，补偿方式待定。
8. 因需求变更失效的旧申请不能直接选中；需求仍开放时本人可立即重申，重复提交不产生多个有效申请。

当前仅运行文档一致性检查，没有验证实际访问授权、列表排序、消息送达、关闭或并发处理。

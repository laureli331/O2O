# 维修和其它：申请排序与关闭重开

确认日期：2026-10-13。依据：[第十二轮8题](application-reopen-questions-20261012.md)，实际回复“4. B\n\n其它全A”，对应1A、2A、3A、4B、5A、6A、7A、8A。与[申请展示与历史](application-detail-rules.md)共同使用。

## 已确认规则

| 来源 | 决定 | 边界 |
| --- | --- | --- |
| AR01 / A | 修改有效申请保留该次首次有效提交时间，位置不因修改变化 | 修改版本及通知仍保留，不把编辑时间当申请排序时间 |
| AR02 / A | 撤回或失效后重申，按本次重新申请成功时间排序 | 不沿用本人首次申请时间，旧记录仍保留，不新增冷却期 |
| AR03 / A | 未选人关闭后，发布者可主动重开同一需求 | 必须重新申请，不恢复已结束或失效的旧申请；不是新编号再发布 |
| AR04 / B | 上述重开在首页“最新”按重开成功时间重新排序 | 不改变原始发布时间事实；不把普通编辑视为重开，也不改变候选排序和付费优选规则 |
| AR05 / A | 未选人关闭后重开不设产品次数上限 | 保留每次关闭/重开记录；不因此绕过资格或下架限制 |
| AR06 / A | 未选人关闭理由选填，最多300字 | 关闭结束有效申请且通知，理由可空；具体通知内容和理由可见范围待定 |
| AR07 / A | 选人前标题、描述、图片、公开区域、服务时间任一变化使旧申请失效 | 不新增必填图片或时间；通知重申，失效记录不能选中；私密地址/联系方式另议 |
| AR08 / A | 关闭与选人以服务端先成功操作为准，另一项不执行并提示刷新 | 不能按客户端点击时间决定，已成功结果不因旧请求到达回退；具体并发实现待定 |

本轮重开规则仅用于尚未选人关闭的需求。已选服务双方确认取消后重开按既有履约规则处理，其首页排序及其它细节不自动套用本轮；已完成服务不能通过本轮重开。选人成功后不允许“关闭需求”替代双方确认取消；关闭成功后不能选中已结束申请。

## 验收依据

1. 甲先申请、乙后申请，甲编辑说明成功后仍排前；保存修改版本、通知及已修改标记。
2. 甲撤回或失效后晚于乙重申，则按重申时间排在乙后；不恢复旧申请排序时间或有效状态。
3. 未选人关闭后重开仍为同一需求，旧申请历史在、当前有效申请为空；旧申请不能直接选中。
4. 重开成功后，“最新”使用该次重开成功时间；普通编辑不刷新该排序时间，原始发布时间保留。
5. 超过3次重开不因产品次数限制阻断，但每次均留记录，不清除旧历史或绕过资格/下架规则。
6. 关闭理由为空可以提交，超过300字不可以；关闭成功结束申请并通知，不产生逐个拒绝流程。
7. 仅替换图片也会使旧申请失效，旧申请者须重新申请；不因图片选填而跳过变更规则。
8. 关闭先成功则选人失败并提示刷新；选人先成功则关闭失败，后续取消仍需双方确认。重复或迟到请求不能逆转成功结果。

当前仅运行文档一致性检查，未实现或验证真实排序、重开、权限、消息送达或并发操作。

# 维修和其它：已确认费用规则

更新：2026-10-11。依据：此前逐题A与[费用第一轮8题](fee-questions-20261011.md)的实际回复“全A”。本文件整理已确认业务，不定义尚未确认的接口、字段名或完整订单状态。

## 适用范围与前置原则

同时适用于维修和其它。服务费和材料、配件、商品等实际支出分项记录并显示合计；每个收费阶段开始前双方确认。项目示例不是必收项目或封闭枚举，未知金额不能默认为0元。收费前确认不等于必须预付。平台不代收居民服务款，费用记录和确认不证明线下付款。

## 本轮8项决定

| 来源 | 已确认规则 | 边界 |
| --- | --- | --- |
| FQ01 | 检查费、上门费归入服务费，分别列名称和金额 | 不要求每单收费，不确定收费金额 |
| FQ02 | 双方都可发起费用约定；发起方提交即认可该版本，另一方确认后生效 | 不能由任何一方单独修改有效约定 |
| FQ03 | 可新增或修改费用项，新版本须双方确认；确认前原版本有效 | 待确认方案不能覆盖或抹掉仍有效的原约定 |
| FQ04 | 每条需求同时最多1份待确认费用方案 | 双方同时提交也只能形成1份；具体冲突提示待定；第五轮已确认修改须先撤回再提交 |
| FQ05 | 对方不回应时保持待确认，可提醒，发起方可撤回；不自动同意 | 未批准24小时自动关闭；提醒方式和频率待定 |
| FQ06 | 双方可先确认取消服务，已发生费用另行协商记录 | 取消不代表费用结清；具体取消和异议处理流程待定 |
| FQ07 | 支出票据或照片选填，供双方核对 | 未上传不因此阻断支出记录；不代表有票据即已付款或已被对方认可 |
| FQ08 | 接单员可自愿垫付，双方事先确认是否垫付及金额上限 | 不强制垫付；超限、变更上限和拒绝垫付的处理待定 |

## 文档核对及后续产品验收依据

1. 一份含检查费、维修服务费、配件支出的约定，应能分清前两项属于服务费，配件属于支出；分别有名称、金额和正确合计。
2. 无论哪方发起，单方提交均只是待另一方确认；另一方确认同一版本后才是双方认可。
3. 原版本已确认，新版本待确认时，原约定仍有效；不能用新金额直接替换原约定。
4. 双方同时发起方案，应保证每条需求最多1份待确认；不能因重复操作形成2份。
5. 对方不回应时不能自动认可或在24小时后自动关闭。发起方撤回待确认方案不影响此前有效约定。
6. 服务取消后的记录不能显示“费用已结清”或“付款成功”，已发生费用仍可另行协商记录。
7. 支出可以不附凭据；有凭据也不代表对方已确认费用或平台核验了付款。
8. 垫付必须自愿并事先由双方确认条件和上限，不能自动要求接单员垫付。

以上是业务验收依据；当前仅运行文档一致性检查，没有实现或验证实际产品功能。

## 尚未确认

第五轮已确认服务费可为0、项目字段/1—20项、确定金额后提交、不同意及先撤回再提交规则，详见[费用录入与方案处理](fee-detail-rules.md)。尚待确认：字段映射、实际支出零值、合计边界、具体收费阶段、并发冲突处理；提醒方式和频率；费用记录允许创建的服务状态；取消后费用协商和异议关闭（第四轮已确认只记录服务异议，运营不介入服务调解）；凭据数量/尺寸/访问权限/保存期限；垫付超限、上限变更；完整状态、通知和接口合同。

个人收入仍仅按已确认完成的跑腿服务费累计、排除垫付款并标明“非到账金额”；本轮未批准维修或其它计入收入，也未修改跑腿规则。历史PRD保留，当前增量从[模块规划入口](README.md)和[业务补充](../ui-development-handoff/business-addendum.md)读取。

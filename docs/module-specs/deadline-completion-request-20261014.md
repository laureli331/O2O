# 四类交易结束期限与到期自动完成：方向确认

日期：2026-10-14。用户原话：“都设定一个服务结束期限吧, 到了期限自动完成”。当前仍是首发业务规划，没有运行中的小程序交易机制切换。

## 已确认的方向

跑腿、维修、闲置、其它四类交易都设置结束期限，期限到达时自动完成流程，用户不必再次点击完成才有自动结束途径。闲置对应交易结束期限，其余对应服务结束期限；这不意味着所有未成交帖子、免费服务目录或未生效申请也自动当作已完成交易。

本次要求替换此前“明确交付确认是流程完成的唯一途径”的设计方向，不再仅以“暂定计佣后归档、交付未确认”作为无人回应时唯一收尾。具体期限如何确定、72小时异常窗口与结束期限如何衔接、有异常时是否暂停以及费用、收入和评价规则仍须用户明确选择。保留用户明确确认实际交付的事实记录，不将系统到期行为伪称为用户点击确认或线下付款。

## 已有决定如何衔接

| 事项 | 当前处理 |
| --- | --- |
| 自动完成方向 | 四类统一设置结束期限，到期自动完成；未实现产品或真实计时任务 |
| 72小时异常窗口 | 已批准过72小时方向，本次不擅自删除、缩短或重复计算；在自动完成前还是完成后，见AF02 |
| 期限字段 | 谁提出、在哪个确认动作生效、时间精度与范围未完整；先确认AF01，不猜具体日期或默认时长 |
| 服务费用与计佣 | 已确认费率、封顶、双方有效费用和未知金额不默认0原则保留；自动完成时是否同时形成计佣记录、异常及未知费用如何处理待AF03/04/06 |
| 延期与待确认请求 | 不擅自继续套用此前全部阻断条件；延期见AF05，取消/费用变更等具体收尾随后补齐 |
| 个人金额展示 | 既有HD02口径不是因本次要求就自动变更，需AF07明确指标、文案和自动完成的纳入范围 |
| 评价资格 | 到期不会自动生成评价内容或星级；是否开放自愿评价资格需AF08确认 |
| 原问答和选定视觉 | 保留历史，不把此前选择改写成对本轮的批准；当前不改变设计图、真实授权或支付 |

此前[第三轮提问草案](commission-simplification-operation-questions-20261014.md)的SO09、SO02—SO08均未获答案；为避免把自动完成与原计佣窗口混在同一题，本次暂停该表，优先讨论[结束期限8题](deadline-completion-questions-20261014.md)。SO01仍为撤销项，不恢复、不记为A/B。用户“继续”只授权继续规划，追加的到期要求只确认主方向，不代表八个具体选项已批准。

原PRD的跑腿24小时自动完成提案不是需要迁移的运行功能，本次也没有指定自动完成时长为24小时。先确定期限、异常与依赖，再形成统一的首发状态规则，不能同时开发相互冲突的完成流程。

## 验证方案与待定事项

本轮验证：保存要求原话及四类范围；主方向指向期限到达自动完成；八题全部待答；原SO表暂停且无伪造答案；金额未知不默认0、客户付款与平台佣金不混淆、自动完成不伪造用户确认；原问答及选定图保留；两个决定文件与交接链接一致、资源清单可重现。检查仅针对规划资料，没有真实订单、计时、送达、收款或用户行为测试。

本轮不根据未答选项编写产品。结束期限计算、延期待确认超时、取消/改价收尾、异常解除后恢复、月末并发、收入更正和评价异议细则在关键方向确定后逐项补齐。服务者主动缴佣、未收客户款、不自动扣款及实际资格仍按已有边界保留。

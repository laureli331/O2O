# 交易确认后的调价下限：第十三轮8题

日期：2026-10-13。状态：原表未逐题作答。用户后续已确认锁定双方初始确认金额、普通调价下限及独立调整等通用原则，见[已确认规则](monthly-commission-rules.md)；不自动对应各题A/B，未明确的具体选项仍待讨论。原A/B保留，用于补齐[新增调价要求](price-floor-request-20261013.md)。不把第十二轮“其它全A”解释为本轮答案。

| 编号 | 问题 | A（推荐） | B |
| --- | --- | --- | --- |
| 1（PF01） | 跑腿的“初始金额”取哪个值？ | 选定骑手时确认的最终服务费 | 发布需求时的服务费预算 |
| 2（PF02） | 维修的“初始金额”取哪个值？ | 选人后首次双方确认的服务费 | 首次发布的明确服务费；未填则取首次双方确认的服务费 |
| 3（PF03） | 闲置如何认定“确认进行交易”？ | 增加卖家提出、买家确认交易价的步骤，双方确认后适用下限 | 双方线下确认后，由卖家在小程序记录交易对象和价格 |
| 4（PF04） | 闲置原价为“面议”，下限如何确定？ | 以该笔交易首次双方确认的明确金额为下限 | 卖家先把面议改成明确标价，交易确认时以该标价为下限 |
| 5（PF05） | 维修分阶段收费，下限如何比较？ | 每阶段首次确认的服务费分别锁定，实际支出不纳入 | 整次服务首次确认的服务费合计锁定，实际支出不纳入 |
| 6（PF06） | 不低于初始金额的限制，约束谁发起调价？ | 双方都受限，即使双方同意也不能提交低于下限的价格 | 只约束骑手、维修员、卖家；发单人或买家发起降价可双方确认 |
| 7（PF07） | “其它”是否也采用这项服务费下限？ | 与维修采用同一规则 | 暂不纳入，只约束原话中的跑腿、维修、闲置 |
| 8（PF08） | 初始100元，后涨到120元，能否改为110元？ | 可以，仍不低于初始100元 | 不可以，后续每次都不能低于上一有效金额 |

第1—2题冻结的是交易确认时对应的基准：跑腿成功选人并确认最终费；维修成功选人后首次双方确认服务费。第2题若无明确金额，不默认0；B首次发布值为明确且符合既有金额格式的数值，展示面议/待协商不算数值。第2题来源与第5题比较范围须同时成立，不提前指定字段。

第3题涉及闲置新业务步骤，联系授权仍不等于交易确认，不将原事后实际经历确认改造成事前确认；买卖对象选择、状态、多人联系、变更/取消等完整规则需继续讨论。第4题若选择A、与第3题B同时出现，首次价格如何获双方确认仍需补齐，不能把卖家单方记录当成双方确认。

第5题不禁止材料、商品等实际支出按事实协商变化；费用各阶段独立记录、上限与完成后只读规则仍有效。第6题不授予任何一方单方涨价生效权，现有跑腿/维修的双方确认规则保持；闲置调价确认细则随新流程另议。

第7题需独立确认，原话未提其它。第8题的A也仍须完成对应的确认步骤，不能直接覆盖有效价格。取消/重开、退款纠错、历史适用范围及并发另议；具体选项未获明确选择时不填默认值；后续先讨论[月末抽佣第十四轮8题](monthly-commission-questions-20261013.md)，再补剩余业务边界。

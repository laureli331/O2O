# 维修和其它：预约细则

确认日期：2026-10-12。依据：[第九轮表格8题](appointment-questions-20261012.md)，实际回复“全A”。与[预约基础](form-appointment-rules.md)、[履约规则](fulfillment-rules.md)、[费用收尾](closing-rules.md)共同使用。本文件记录业务约束，不表示实际定时任务、接口或页面已实现。

## 已确认规则

| 来源 | 决定 | 边界 |
| --- | --- | --- |
| TQ01 | 预约只填写一个开始时间，精确到分钟 | 不新增结束时间或时段、默认日期；沿用Asia/Shanghai时间 |
| TQ02 | 只能提出未来预约，开始须晚于服务端当前时间 | 不允许历史补录，客户端改时钟不能绕过；确认与到点并发按服务端有效事实处理 |
| TQ03 | 未来预约到点仍待确认时，自动关闭该预约申请，保留历史 | 不替换或清除原有效预约，不自动完成/取消服务，不自动认可时间；清除请求无回应保持待确认且不自动关闭，见[第十轮规则](change-rules.md) |
| TQ04 | 发起方可撤回待确认预约；修改须先撤回再提交 | 保留历史，新方案仍需另一方确认，不能覆盖原有效预约或撤销已确认结果 |
| TQ05 | 不同意预约/改期的理由选填，最多300字 | 本次待确认预约结束留历史，原预约仍有效，不取消服务；不同意完成/取消的理由仍必填1—500字 |
| TQ06 | 清除已确认预约须一方提出、另一方确认后执行 | 只清除预约，不取消服务，保留历史；数量占用/撤回/不同意/无回应已由[第十轮规则](change-rules.md)确认 |
| TQ07 | 完成或取消后，关闭未确认的预约及服务内容/区域变更，保留历史 | 不视为同意，不以这些未决变更阻止结束；完成前仍必须处理待确认费用 |
| TQ08 | 已确认预约时间过后，仍未提交完成时，只标明时间已过 | 不自动完成/取消、不自动生成站内提醒、不新增逾时收费或违约处罚；原有效预约历史保留 |

## 时间和结束边界

本轮选择单一时间点，“到点”以该预约申请提出的开始时间为准。提交时必须晚于服务端当前时间；仍待确认到该时间即应关闭，不能把过时申请确认成已生效的未来预约。任务执行延迟不意味着可以继续认可已过时的申请；具体并发、迟到执行、提示和技术实现尚需整理。

待确认改期关闭、撤回或不同意时，原已确认预约保持有效。原预约时间已过不自动删除或改期，只作过时标记；需要改期仍由双方确认新未来时间。无预约可以继续服务，预约状态不作为付款、完成或评分资格证明。

已确认预约不能由单方直接清空；提出清除也不立即生效。清除请求的无回应处理不能默认套用未来预约到点关闭规则，共用同次服务最多1份待确认，撤回/重提/不同意及无回应见[第十轮规则](change-rules.md)。

服务结束后未确认预约和内容/区域变更关闭留历史，不修改原有效约定。该规则不关闭取消后符合条件继续待确认的已发生费用方案，不恢复联系方式或凭据权限。结束发生在确认变更之前时，不能在结束后再确认该未决变更。

## 验收依据

1. 只录入一个开始时间，精确到分钟；不要求结束时间，不自动填默认日期。
2. 提交过去或等于服务端当前时刻的预约应被阻止；客户端伪造时间不能改变校验结果。
3. 待确认预约到点后关闭留历史，不认可该时间，不改变旧有效预约或服务状态；迟到执行不放行过时确认。
4. 修改待确认预约必须先撤回再提交，不能原地覆盖；重提仍须另一方明确确认。
5. 不填不同意预约的理由可结束该申请；超过300字不能提交，原有效预约和服务状态不变。
6. 单方提出清除后原预约仍在，另一方明确确认后才清除，历史保留、服务不取消。
7. 完成/取消后，预约及内容/区域待确认变更关闭留历史，不表示同意。待确认费用仍按收尾规则处理，不能借此自动认可费用或绕过完成前费用处理。
8. 已确认预约时间过后只标明已过；不能自动生成一次站内提醒、结束服务、收费或新增评分资格。

当前仅运行文档一致性检查，没有实现或验证真实预约校验、到点任务、通知或并发状态变化。

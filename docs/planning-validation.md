# 规划文档验证用例

记录日期：2026-10-06（Asia/Shanghai）

本轮只变更规划文档。本文件记录与用户已确认决定对应的验证用例，不是小程序运行测试，也不证明监管准入或真实付费需求成立。

验证对象：[规划记录](miniapp-planning.md)。

| 编号 | 检查场景 | 预期结果 |
| --- | --- | --- |
| D01 | 核对当前工作区与文档路径 | 两份文档均在 E:\O2O\docs 内；临时快照仍保留，后续更新指向项目内主记录。 |
| D02 | 区分广告决定与历史选择 | 每类3个名额、7天和30天两种期限、按期收费、固定同时展示为已确认；先审核后付款已经确认，先付款后审核仅保留为已替代历史；价格没有被编造。 |
| D03 | 检查年龄门槛及覆盖范围 | 跑腿发单/接单、维修求助、二手发布均须满16周岁；未满16岁只浏览公开信息；16—17岁不被自动视为成年人。 |
| D04 | 检查旧未成年方案 | 无年龄门槛、未满16岁年龄标签及不满14岁监护人配套流程仅作为已撤销历史，不继续作为首期有效规则。 |
| D05 | 检查联系方式展示 | 所有访客都看到打码版本；登录不会解码；完整联系方式仅向获发布者确认的联系对象展示，其他人保持打码。 |
| D06 | 区分联系许可与成交 | 跑腿选定接单者并正式承接后解码；维修/二手申请联系获同意后定向解码，确认联系对象不被写成已成交。 |
| D07 | 检查跑腿承接与费用 | 同一用户可发单和接单，多人申请报价、发布者选一人，确认最终服务费；自愿垫付及其上限在承接前确认。 |
| D08 | 检查完成与取消 | 完成申请后24小时无确认且无异议自动完成，有异议人工处理；承接后取消须双方确认，已发生费用先协商；取消不等于结清。 |
| D09 | 检查资金与准入边界 | 平台不代收或结算跑腿费用；自身广告费与跑腿费用区分；没有将线下付款、年龄门槛或湖南说明写成项目已获准上线。 |
| D10 | 核对咨询草稿 | 统一业务说明同步年龄、联系方式、每类3个广告名额、7/30天期限、固定展示、先审核后付款、实际展示起算、满额暂停、排序、24小时审核以及到期和续购；微信咨询保留项目支付分类和付款后异常处理问题；草稿未被写成已发送或获答复。 |
| D11 | 检查文档完整性 | UTF-8可读；内部相对链接存在；不残留“本文件仅在临时目录、未改项目文件”等错误描述；未决事项明确列出。 |
| D12 | 核对Git交付 | 本轮只纳入两份文档；git diff --check通过；创建对应提交，并确认提交后工作区状态。 |
| D13 | 核对虚拟支付证据及边界 | 区分已认证个体工商户开通规则、个人工具路线限制、推广权益分类推断及本项目未获官方确认；iOS不支持开发者主动退款，普通退款提交不等于成功；现行费率与适用类目/标准费率分开，不把月末后45—60天写成每笔支付后固定到账；没有执行代码接入、开户或真实支付。 |
| D14 | 核对最新三项选择 | 虚拟支付方案以微信确认适用为前提，用户认可不等于官方批准；所有终端统一先审核后付款，期限从实际开始展示时起算；同类3个名额满额暂停购买，空出再开放，无后续时段预订；不把待支付名额保留、付款后展示时间、修改复审或其他未决细节写成已经确认。 |
| D15 | 核对推广排序、审核及到期续购 | 按本轮实际开始展示时间排序、先开始排前；推广资料提交后24小时内给出审核结果，不能混为跑腿24小时自动完成或24小时值守；到期自动撤下仅影响付费位置，保留免费资料；客户手动续购且重新审核，无自动扣款，不擅自确定同时间排序、待支付名额保留、修改复审或付款后展示时限。 |

执行方式：逐项人工对照用户回复；通过PowerShell检查实际保存的关键决定、排除已废弃的有效规则、核对相对链接及修改范围，再执行Git差异检查。运行结果在本次交付消息中说明。

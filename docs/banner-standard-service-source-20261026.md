# 本地生活服务小程序｜首页 Banner 广告与定制模块 PRD

**文档版本：** V1.0
**阶段：** HTML Demo 规划阶段
**产品范围：** 商家广告购买、Banner 定制、广告排期、平台管理后台

## 一、产品目标

建立一套低运营成本、交付质量稳定、可逐步自动化的首页 Banner 广告系统。

核心目标：

1. 允许多个商家购买首页顶部轮播广告。
2. 按广告展示位置和投放周期进行售卖。
3. 为没有广告素材的商家提供标准化 Banner 制作服务。
4. 通过模板、程序规则和按需调用 AI 控制制作成本。
5. 为后续接入真实订单、支付、排期和广告数据建立清晰的业务结构。

### 产品原则

- 功能优先于审美个性化。
- 标准化优先于无限定制。
- 规则优先，AI 按需介入。
- 广告位、订单、素材和投放计划相互关联，但独立管理。
- 先通过人工辅助验证流程，再逐步自动化。

## 二、广告资源与售卖规则

### 2.1 广告展示区域

首页顶部已有一个轮播 Banner 容器，位于搜索框下方、服务分类上方。

- 全站共享广告池。
- 一个展示容器，三个固定展示位置。
- 商家自主选择位置，不采用随机起始广告。
- 用户进入首页时从首位开始，按固定顺序轮播。
- 保留分页指示和用户手动切换能力。

### 2.2 三个广告位置

| 位置 | 展示顺序 | 定价原则 |
|---|---|---|
| 首位 | 第一个展示 | 最高价格档 |
| 次位 | 第二个展示 | 中间价格档 |
| 末位 | 第三个展示 | 最低价格档 |

具体价格尚未确定。

每个位置独立售卖、独立排期。同一位置在相同时间段内不得重复售出，不同位置可以同时投放。

首位、次位、末位是固定的资源位置，不因某个位置未售出而自动提升其他商家的位置权益。

未售出的位置可以展示平台自有的非商业内容，或采用经产品确认的空位处理方式。不得将其他商家的广告自动提升至更高价格档的位置。

### 2.3 容量与轮播规则

- 初始容量建议为每个位置同时容纳一个有效投放订单，共三个位置。
- 轮播切换间隔暂以 4 秒作为可配置的测试参数，尚未最终确定。
- 不按商家出价调整展示顺序。
- 不承诺未经验证的固定曝光量。
- 后续根据有效曝光、点击率、商家续费和用户体验数据调整容量。

### 2.4 定价结构

建议采用：

**广告订单金额 = 位置基础价格 × 投放周期调整系数**

其中，位置基础价格反映不同位置的资源价值；投放周期调整系数用于处理不同投放期限的价格差异。

位置价格系数、具体人民币价格、周期优惠和退款规则均需另行确定，不得在 Demo 中将试算数值当作正式报价。

投放周期可先评估 7 天、14 天和 30 天三个选项，最终以商家需求和运营规则为准。

## 三、商家端功能

### 3.1 广告推广页面

页面职责：帮助商家理解广告权益、选择位置、查询档期并提交购买申请。

主要内容：

- 广告服务说明。
- 首位、次位、末位的位置卡片。
- 每个位置的展示顺序和权益说明。
- 可配置价格。
- 投放周期与可售日期。
- 基础 Banner 制作服务说明。
- 购买申请入口。

设计要求：

- 明确说明购买的是轮播序列中的固定位置，而非三个同时展示的广告位。
- 不承诺广告一定带来订单或转化。
- 不展示尚未确定的正式价格。

### 3.2 档期选择页面

商家选择广告位置后，选择投放周期和日期。

系统需要：

- 检查指定位置在目标时间段内是否可售。
- 阻止同一位置的重叠有效订单。
- 支持不同位置同期售卖。
- 显示投放开始日期、结束日期、订单金额和当前申请状态。
- 在订单确认阶段提供限时档期预留机制。
- 预留过期后释放资源。

### 3.3 Banner 制作需求页面

采用结构化表单，避免商家提交过于开放的设计需求。

字段包括：

| 字段 | 必填 | 说明 |
|---|---|---|
| 推广目标 | 是 | 优惠促销、主打服务、门店展示 |
| 店铺名称 | 是 | 优先读取商家已有资料 |
| 服务卖点 | 是 | 必须来自商家提供的真实信息 |
| 宣传标题 | 否 | 可由 AI 辅助生成 |
| 优惠价格与期限 | 否 | 有活动时填写 |
| 店铺或服务照片 | 否 | 优先使用真实素材 |
| 广告跳转目标 | 是 | 指向明确的商家或服务页面 |

### 3.4 我的推广页面

商家查看：

- 当前广告订单。
- 订单状态与付款状态。
- Banner 制作进度。
- 候选方案及最终确认的素材。
- 投放位置和投放时间。
- 历史推广记录。
- 可查看的投放效果数据。

当前 Demo 阶段只实现页面和交互状态，不模拟真实支付成功。

## 四、Banner 定制与生产机制

### 4.1 模板策略

采用标准化模板加有限差异化，不提供自由画布和无限风格定制。

首版设置三类模板：

2. **优惠促销型：** 适用于限时优惠、团购、新店开业和活动推广。
2. **主打服务型：** 适用于家政、维修、美容等服务介绍。
3. **门店展示型：** 适用于商家介绍、品牌展示和特色门店推广。

三类模板共享统一的字体、间距、颜色和布局规范，根据推广目标采用不同的信息结构。

商家选择推广目标，不直接参与复杂的设计决策。

### 4.2 AI 与程序的职责

制作流程：

3. 获取商家信息与素材。
2. 根据推广目标匹配模板。
3. 判断是否需要 AI。
4. 使用程序按模板自动排版。
5. 自动检查并由平台处理异常。
6. 商家确认最终方案。
7. 进入广告投放流程。

规则如下：

- 信息完整、素材可用时，直接排版，不调用 AI。
- 文案不足时，按需调用 AI 生成或优化文案。
- 缺少合适的视觉素材时，优先使用素材库；必要时调用 AI 生成背景。
- 标题、价格、日期、店铺名称等重要文字由程序渲染，避免依赖图像模型直接绘制中文。
- AI 不得自行编造价格、优惠、服务资质或商家能力。
- 自动检查未通过的素材不得直接投放。

### 4.3 基础制作服务范围

建议的初始规则：

- 每笔广告订单提供 3 个候选方案。
- 商家选定其中一版后，可提出 1 轮集中内容微调。
- 内容微调包括标题、副文案、优惠信息、按钮文字等。
- 整体构图、视觉风格和创意方向在选定后原则上锁定。
- 平台制作错误由平台免费修正，不计入修改次数。
- 商家要求推翻整体设计方向时，重新评估工作量，不自动纳入基础服务。

这里的 1 轮修改指一次性提交多项内容修改，不是只能修改一个字段。

### 4.4 制作时限

建议初始服务标准：

- 商家完成付款并提交全部必要资料后，平台争取在 2 个工作日内提供首批候选方案。
- 商家收到方案后，建议在 2 个工作日内确认或提交修改意见。
- 商家延迟提供资料或确认时，应提醒并暂停相关处理；不能无限期占用广告档期。
- 平台自身延迟交付时，应提供合理补救，并按照事先公布的订单规则处理。

具体服务时限和退款条款须在正式上线前确认。

## 五、订单与投放状态

订单、素材和投放计划应分别管理。

### 5.1 订单状态

- 待平台确认
- 待付款
- 已付款
- 制作中
- 待商家确认
- 待审核
- 待投放
- 投放中
- 已结束
- 已取消
- 退款处理中
- 已退款

实际状态转换需由业务规则控制，不能允许商家直接跳转到任意状态。

### 5.2 素材状态

- 待制作
- 制作中
- 待商家选择
- 待修改
- 待审核
- 审核通过
- 审核不通过
- 已确认
- 已归档

### 5.3 投放计划状态

- 未排期
- 已排期
- 待开始
- 投放中
- 已暂停
- 已结束

只有满足付款、素材审核、商家确认和档期有效等条件的订单，才能正式上线。

## 六、平台管理后台

### 6.1 广告概览

显示待处理订单、待制作素材、待审核内容、即将开始和即将结束的投放。

### 6.2 广告订单与排期

支持：

- 按商家、位置、日期和订单状态筛选。
- 查看和确认广告申请。
- 管理档期预留与释放。
- 检查同一位置的日期冲突。
- 查看订单付款状态。
- 处理取消、改期和退款申请。

### 6.3 Banner 制作工作台

支持：

- 查看商家需求和上传素材。
- 记录使用的模板与制作方式。
- 上传和管理 3 个候选方案。
- 保存每个版本及修改意见。
- 记录商家选择和确认时间。
- 进行最终审核并交接投放。

### 6.4 广告规则配置

后续支持配置：

- 位置名称与展示顺序。
- 各位置价格。
- 投放周期及调整系数。
- 同时投放容量。
- 轮播切换间隔。
- Banner 尺寸与模板规范。
- 制作服务范围。
- 审核和订单规则。

### 6.5 投放效果分析

未来记录：

- 有效曝光量。
- 点击量和点击率。
- 不同位置的曝光及点击表现。
- 制作耗时和修改次数。
- 广告订单收入。
- 商家续费率。
- 退款及投诉情况。

当前尚无真实投放数据，不应在 Demo 中展示虚构的实际业绩。

## 七、数据结构建议

后端实现时至少拆分以下业务对象：

- **Merchant：** 商家资料。
- **AdPosition：** 广告位置及资源规则。
- **AdOrder：** 购买订单、金额、周期、付款状态。
- **BannerBrief：** 商家提交的推广需求。
- **BannerAsset：** 候选素材、版本、审核结果和确认记录。
- **AdSchedule：** 投放日期、位置和投放状态。
- **AdEvent：** 曝光、点击等事件记录。
- **RefundRecord：** 取消与退款处理记录。

每个广告订单可以关联多个候选素材，但只能将最终确认并审核通过的素材绑定到有效投放计划。

## 八、质量与风险控制

### 素材质量

检查文字准确性、信息完整性、图片清晰度、裁切、文字溢出、视觉层级和首页适配情况。

### 广告内容

核实优惠价格、活动期限、服务承诺和相关资质，避免虚假宣传。

### 用户体验

控制轮播广告数量，明确标识商业推广内容，避免付费广告伪装成自然推荐。

### 商业风险

不承诺未经验证的曝光量或成交结果；不得因某商家支付更高费用而自动改变固定位置顺序。

### 运营成本

不因个别商家的特殊要求就新增模板。只有重复出现、具有共性且值得维护的需求，才纳入标准模板库。

## 九、分阶段实施

### 阶段一：HTML Demo

实现：

- 广告推广页面。
- 三个位置的选择交互。
- 档期选择示意。
- Banner 需求表单。
- 我的推广页面。
- 管理后台的订单、素材和排期界面。
- 订单与素材状态展示。

不实现真实支付、数据库、自动排期和 AI 生成接口。

### 阶段二：最小可用系统

接入真实商家数据、订单、支付、素材存储、审核、排期和广告展示。先以平台人工辅助制作方式运营。

### 阶段三：逐步自动化

根据真实订单量和制作数据，逐步加入自动模板匹配、按需 AI 生成、自动质量检查和投放效果分析。

## 十、尚待确定的事项

以下事项不能在没有依据的情况下写死：

4. 三个广告位置的正式价格。
2. 投放周期及长期套餐折扣。
3. 同时投放容量是否始终限制为三个。
4. 轮播切换间隔。
5. 档期预留时限。
6. 取消、改期和退款细则。
7. 广告位价格调整依据。
8. 正式上线时的支付和履约方式。

**最终验收目标：** 商家能够理解广告权益、选择位置和档期、提交推广需求、确认 Banner 并查看投放状态；平台能够管理订单、素材版本、审核和投放排期。整个系统不依赖无限次人工设计修改，也不要求商家具备设计能力。

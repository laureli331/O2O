# 申请填写：离开前保留选择权

2026-10-25。沿用资料、地址和交易表单已有的未保存保护，不新增业务规则。

## 实际问题与修复

- 已复现V03申请说明有修改时切换业务，文字直接消失。现在切换业务、演示状态及页面内返回/离开链接前，有实际未保存改动才提示“放弃未保存的修改？”。
- “继续编辑”、Esc或点击遮罩保留输入与原业务/状态，恢复触发位置；“放弃修改”后才执行原操作。弹层优先聚焦继续编辑，背景暂不可操作，键盘焦点保持在两个按钮内，保留原按钮按压反馈及44px触达尺寸。
- 撤回或正式选人会刷新双角色表单，若合成申请者表单还有修改，执行前同样允许继续编辑；这里只保护原操作，不新增第二次选人或更改已确认的业务规则。
- 比较实际可提交字段：维修/其它预估、说明、时间与规则知悉，以及跑腿垫付选择和明确上限；隐藏且不适用的字段及跑腿只读价格不算改动。0元、无效待修正文字也能识别，改回原值不打扰，成功保存后更新基线。
- 原生刷新/离开提醒仅在实际有改动时请求。浏览器与系统可能不触发该事件，不能承诺手机系统强制关闭时仍可恢复。
- 查看接单资料已有返回快照、资格补充已有申请暂存，因此这两条保留内容的流程不额外阻挡；返回资料后恢复未保存标记，不自动提交。未知结果继续优先查询，已选定的只读表单不当作待保存修改。

## 参考与适配

[MDN离开事件说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)明确原生提醒用于防止未保存内容丢失，并说明移动端存在触发限制。本项目结合现有资料表单保护：页内使用同风格底部确认，浏览器离开使用原生提醒；能恢复的子流程不额外增加步骤。

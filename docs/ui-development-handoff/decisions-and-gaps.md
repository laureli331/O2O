# 开发前差异与缺口

视觉选择和业务确认分别记录。用户明确保留了五页B版图；该操作没有明确撤销原 PRD 的资金、权限、推广标记或业务范围。原图保持原样；实现遇到下列差异先查 [decisions.json](../../assets/ui/development-handoff-20261009/decisions.json)。

| 编号 | 差异 | 当前处理 |
| --- | --- | --- |
| HD01 | 维修详情“接单”、价格占位及“接单后查看完整信息” vs M02/V02/CT03信息联系 | 用户确认先申请再选人、申请不强制报价，2026-10-11确认每条需求选1位；申请人数、费用、选人细则及履约合同仍待讨论 |
| HD02 | 个人收入“在湘邻湘友赚了…元” vs 平台不代收居民服务款 | 用户确认累计已确认完成跑腿服务费、排除垫付款并标非到账；自动完成及更正等细节待确认 |
| HD03 | 优选无广告标记 vs AD01—AD03要求付费推广明确标识 | 用户确认优选就是付费推广；付费性质已定，识别文案/位置仍需明确，不自动取消原标记要求 |
| HD04 | 首页其它类目 vs 首期三业务和禁止任务范围 | 其它归集三类之外需求，公开发布并申请接单，先申请再由发布者选人，为后续迭代整理数据；2026-10-11确认每条需求选1位，申请人数/报价/费用/完整流程待定，原禁止任务没有自动获准 |
| HD05 | 维修“服务时间”只有标签 vs F02无此必填字段 | 用户明确暂不填值；保留显示意图，不添加真实默认时间或必填规则 |
| HD06 | 图中姓名/地址栏 vs ID06/CT02/RA12隐私规则 | 姓名示例只是昵称占位；生产不用原实名作公开字段，完整地址只按必要授权 |
| HD07 | 五页图 vs PRD V01—V21 | 删闲置单页图不是删M03；其它页面仍需补设计/状态，coverage.json逐组记录 |
| HD08 | 模糊、SVG、小字语义色、rpx适配 | 当前是实施候选；选定基础库和设备上验证，不宣称微信运行通过 |

三条问题已在本聊天收到实际回复，原话及细分状态见 decisions.json。已确认的决定与未确认的细节分开记录。历史PRD不覆盖重写；本次补充是该交接的当前决定依据，后续业务扩展需同步完整字段、状态、权限和验收，不能仅换按钮文字。

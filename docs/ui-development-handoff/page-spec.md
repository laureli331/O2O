# 五页精确结构与开发边界

页面展示文案集中在 [content.json](../../assets/ui/development-handoff-20261009/content.json)。名称“闲置”对应 PRD 历史“二手”，名称“接单员”对应历史“承接者”；这是显示层映射，不能据此擅改已有业务编号或存储枚举。下列 UI 编号只是交接索引，不是新 API/路由。

2026-10-11追加申请规则（维修和其它）：同一人对同一需求最多1份有效申请；选定前可修改或撤回；重复点击不新增记录。具体字段和撤回后重申/冷却/修改通知规则仍待定；不把已选定的服务取消当成撤回申请。

2026-10-11追加联系规则（维修和其它需求）：选定前双方查看对方联系方式仍打码；选定成功后仅发布者和选中的接单员互看完整联系方式，其他申请者仍打码。草选或请求结果未知不是成功；服务端执行授权，不下发完整字段仅靠界面打码。详细地址、联系变更/撤销/结束与旧维修求助流程迁移仍待确认；闲置、免费目录及推广仍按原CT03。

2026-10-11追加费用规则（维修和其它需求）：协商后的费用在小程序内分项记录，在每个收费阶段开始前由双方确认；服务费和材料/配件/商品等实际支出分开，页面同时显示合计。检查若收费先确认，诊断后再确认维修/配件费用，不代表已付款或必须预付。费用第一轮8题已获用户“全A”确认：检查费/上门费归服务费并单列；双方可发起，另一方确认后生效；新增/修改约定需双方确认且确认前原版本有效；最多1份待确认方案，无回应不自动同意，可提醒或由发起方撤回；可先双方确认取消，已发生费用另议，不代表结清；支出票据/照片选填，垫付须自愿且双方事先确认是否垫付及上限。详见[费用规则](../module-specs/fee-rules.md)。具体字段、阶段细则、拒绝/待确认版本修改和异议流程仍待讨论；尚未确定表单字段及页面，也没有按选定稿¥--补出真实默认费用。个人收入暂不因此扩入维修和其它。

## UI01：首页，对应 V01

顺序：品牌湘邻湘友/系统胶囊 → 搜索 → 优选大卡 → 最新需求 → 全部/维修/跑腿/闲置/其它筛选 → 选择村/社区和最新 → 双列需求 → 五项底部导航。

三大独立维修/跑腿/闲置图标模块已经删除；单独闲置列表画面删除不等于删除 M03 功能，闲置通过筛选、发布、详情和本人历史可达。首页需求卡不显示“示例区域”或位置行，但仍保留区域筛选，服务端仍按真实区域过滤。每批20条、首次发布时间倒序、编辑不置顶，来源 PRD共同格式。

优选标题第一行左对齐，大图居左，服务名称/项目和查看资料居右。不按图片中的一个卡推定广告容量1个。付费推广标记及其它筛选的真实分类含义见差异清单，未确认不能悄悄省略或扩业务。

2026-10-10用户明确其它属于业务模块，归集维修/跑腿/闲置之外的需求，为后续更新迭代整理数据，并确认允许公开发布和申请接单，先申请再由发布者选人；2026-10-11确认每条需求选1位且申请人数不设产品上限、申请时不强制服务费报价，金额后续协商。费用按阶段在收费前确认；自愿报价字段、收费阶段细则、分类判断和禁止范围细则仍待确认。具体发布/详情/申请页面、字段和全状态仍需规划，不能把业务方向确认当成完整流程可用，也不能将未填报价显示成免费或0元。

## UI02：需求详情示例，对应 V02

当前图：导航需求详情 → 分类/标题/占位价格/服务时间 → 需求说明大图 → 图片下正文 → 需求方信息 → 对方的评价 → 底部分享任务/接单。

用户明确“服务时间”只显示标签，暂不填值；不能生成电话沟通、日期、默认可服务时间。维修实际字段没有自动新增必填服务时间或价格；图中 ¥-- 和费用待协商是视觉占位，不代表维修价格字段已批准。

正文精确为“启动后无反应，希望维修人员联系查看。”，放在大图下方。图中姓名栏的示例用户不是实际实名；PRD只公开昵称，生产不能公开原姓名/身份证、手机号或完整地址。图片公开性与资料解码要按服务端授权，不是按卡片显示决定。

用户明确选择“扩展维修接单流程，另行讨论并补齐业务规则”，并于2026-10-10追加确认A：先申请，再由发布者选人，申请时不强制报价；2026-10-11确认每条需求选1位且申请人数不设产品上限。申请与联系规则见本文开头追加记录；价格确定方式、申请内容/重申、选定生效/竞争申请/改选细则、同时接单、履约、详细地址/联系结束和取消规则仍未确定。开发不能直接复制跑腿流程或开放真实维修接单。详见[业务补充](business-addendum.md)。对方评价入口使用 V19 合法角色资料，不将“待展示”替换为虚构5分或2条。

## UI03：跑腿选人，对应 V03，发布者视角

顺序：选择接单员 → 公开需求摘要/服务费 → 阶段指示 → 候选接单员 → 费用说明 → 确定选择。

候选A示例报价12、不垫付；候选B示例报价15、愿垫付、上限50。它们只是视觉样例，不能成为实际默认报价。愿垫付/上限两枚标签同为浅绿底绿字且分开；上限不是服务费，格式小且不采用红色金额样式。

点卡只改变草选；确定选择前核对当前有效报价、最终费和垫付条件。只有服务端成功选定1人后才正式承接及双方解码。重复提交、报价已改、任务过期、被别人选中、网络未知结果都不能仅保留绿色勾就当成功。需查询当前结果，不自动替用户再选。

“待选择/履约中/待确认”只是摘要导航，不覆盖超期、取消、异议等真实状态，详细映射见组件合同和 PRD RUN规则。

## UI04：评价接单员，对应 V18

顺序：对象昵称和该单标题 → 态度/效率/沟通，每项5个未选星 → 说说这次服务的感受吧...，0/300 → 添加图片，最多3张 → 居中小审核提示 → 提交评价。

对象卡取消“接单员”徽标和“实际完成…示例”说明；页面标题仍可为评价接单员。删除三项说明文案不删除3维必填规则：整数1—5、无默认五星、无半星；错误显示在对应未选项附近。文字选填，图0—3，JPEG/PNG单张最多5MB，依据F14/F15。

该单标题由真实有效经历关联对象读取，不把维修订单冒充跑腿代取快递。公开评价中的昵称按 RA12 打码；图中示例用户A用于当事人编辑画面说明，不能作为所有公开列表的昵称规范。实际经历资格、7日修改窗口、一次修改、图文审核与数值有效性独立。

## UI05：个人页，对应 V05—V14、V18

顶部不写“我的”，保留设置；头像居中，昵称、登录和资格各自表达。示例资格待核验黄色，发布或接单时核验资格。灰色。微信登录不代表已核验。

我的交易区：标题 → 全黄且居右收入行 → 我发布的/我服务的/联系申请/我评价的。工具箱：收藏/草稿/私人地址簿三独立行；最后服务管理与帮助。用户确认收入按已确认完成的跑腿服务费累计，排除垫付款，注明非到账金额；不是余额、不加提现。自动完成是否计入及数据合同仍待确认，未取得可信统计不能上线xx或假0元。
